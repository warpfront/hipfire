# Kernel-agnostic beta/alpha fold: preliminary gate evidence

- Branch: `gfx11-betaalpha-fold` on `ef52914a4` (`mq4-lloyd` with gfx1100 V2C). Source head when this report was written: `00d66b4e9`.
- The load path concatenates complete MQ4V2 Z, beta and alpha rows, preserving all 136-byte groups. It pads SET's row count to 128 on gfx1100 or 256 on gfx1151. The same existing production SET selector handles QKV and folded Z; a small HIP split writes the original Z/beta/alpha F32 output layout. No GEMM kernel is forked. Default on only for the exact four-MQ4V2 Qwen3.5 LA route, `HIPFIRE_IU4_BAFOLD=0` disables it. Decode and fallback retain the original beta/alpha weights.
- Source proof: local `cargo check -p hipfire-arch-qwen35 -q`; `hipcc --offload-arch=gfx1100 --offload-arch=gfx1151 -c kernels/src/split_mq4v2_z_betaalpha.hip`; model one-chunk gfx1100 smoke emitted `split_mq4v2_z_betaalpha` JIT code object and scored KLD `0.053701`.
- gfx1100 candidate WT2 c24 q8/q8 (24,552 scored tokens): `0.077271` slice-mean KLD, 1.881043 NLL. Exact `ef52914a4` baseline c24 q8/q8: `0.076879` KLD, 1.882926 NLL. Candidate minus baseline KLD = `+0.000392`. Both runs completed, arch asserted `gfx1100`, and the evaluator was explicitly invoked with `--kv-mode q8 --kv-v q8`. Evaluator does not log a VMM assertion (that applies to serve/bench). The A runner failed *after* scoring because it erroneously required this serve-only log; the check was corrected in `00d66b4e9`. `cmp` of the complete KLD sequences differs at byte 21; this fold is not byte-exact against the baseline and must not be reported as such. Inputs and full logs are `gfx1100/wt2*/`, excluded from Git.
- The tested candidate evaluator predates the stack-local kernarg change `1f8ab4454` (one heap allocation removed from each split launch); the final rebuilt evaluator has MD5 `43bf06899b943a26e4b2c92cb098a106` on hipx and still needs its numerical/performance recheck. The final service binaries are built locally, then copied to hipx; no source was copied to hipx.
- **Not a ship pass:** no gfx1100 ABBA ×2, rocprof trace, battery or TTFT-511 was run. No Halo fold gates were run: they must await the Halo-v2b integration on `mq4-lloyd`, then rebase this branch onto that merged SHA so Halo measures v2b, not X5. Do not claim the fold meets throughput or no-regression gates yet. Stop at the first actual failed gate. In particular investigate the KLD-sequence difference before calling this an exact change.
- Gate tools: `scratch-bafold/gates.py` for fresh-process WT2/ABBA, `trace_request.py` for a warm then uncached pp8192 service request, and `summarize_trace.py` for profiler kernel counts. For rocprof, stop the daemon gracefully with `hipfire stop` before ending the service so its CSV flushes. Keep the GPU lease and both cards quiet during ABBA.
