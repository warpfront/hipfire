# --- quant-type register parity (scripts/check-quant-registry.py) ------------
# Asserted against docs/quant-formats/qt-register.txt, the committed allocation
# of qt numbers. All four are invariants rather than ceilings: a table check has
# no legitimate slack, which is the point of preferring it to a count.
#
# The first draft of this gate WAS three counts, including `qt_unregistered <= 10`.
# That ceiling could not distinguish a deliberate non-passthrough format (qt 22 is
# an index tensor; 28/29 load via paro.rs; 31-37 via arch loaders) from a genuine
# omission like cf061b7ed, where qt=40's encoder, GEMV and is_mq arms all landed
# and the model would not load. Nor could any count see substitution -- delete one
# justified entry, add an unjustified one, cardinality unchanged, gate green. That
# is the shape of f00fa8058. Declaring each number's disposition in a table makes
# both cases mechanical.

# A declared variant missing from the register, or a register row naming no
# variant. Same UNLISTED/STALE pair check-layering.py applies to crates.
