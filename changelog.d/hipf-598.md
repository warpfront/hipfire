### Fixes: G12 engine loop, lane marks, cancel snapshots and the Gemma 4 cache gate

- **Engine-loop A/B harness: route key `chat_system` (HIPF-598).** `scripts/engine_loop_ab.py` opens every multi-turn, interleaved and batch conversation of such a route and both abort scenarios with a system message of about 430 tokens whose first line names the conversation; `--conc` does not use it yet. A Gemma 4 follow-up reuses only the previous prompt rounded down to the 256-row prefill chunk, so the short default prompts reused 0 tokens and the cache rows tested nothing on Gemma 4. A turn-end chunk split that gave reuse to short prompts was tried and reverted: it made every short Gemma 4 prompt prefill 35-65 % slower (Loki HIPF-622).
- **A client cancel of an AR request on the engine loop keeps the snapshots its prompt captured (HIPF-598).** The singleton route and a resident request on the N-request scheduler now publish the turn's prompt snapshots before the rollback, as a speculative cancel does.
- **The lane marks of the engine live in the runtime session driver (HIPF-598).** `SessionDriver::mark_lane`, `lane_mark`, `lane_rewinds`, `continue_lane` and `drop_lane_mark` replace the Qwen4 bundle's own mark list: a family declares only how its state moves between the resident slot and a lane. Qwen4 behaviour is unchanged.
