### New model: Inkling-2-Mini (arch 24)

- **Inkling-2-Mini: refusal at admission, standard metrics, accurate load summary.** The GPU forward stops at position 8192, because it does not implement full-attention log scaling beyond that point. Requests whose prompt plus `max_tokens` exceed that limit, or exceed the allocated `max_seq`, are now refused before any state changes. The refusal is a `context_length` error that names the prompt, `max_tokens`, the limit and the capacity, instead of failing partway through prefill or decode. The limit comes from the model's own log-scaling config, through the same check the forward uses. A larger `max_seq` does not raise it, and the message says so. The `done` event now carries the standard `prefill_tokens`, `cached_tokens` (always 0), `prefill_tok_s`, `ttft_ms`, `decode_ms` and `decode_tok_s` keys, so serve usage reports the real prompt token count. The load summary now gives the actual route: `kv: f16`, `prefill: single-row`, plus the executable context when the limit is below `max_seq`. It no longer claims per-prompt chunking.
