### Changes

- **Inkling-2-Mini's bundled DSpark draft now has a GPU body behind the shared DSpark driver (correctness bridge, not wired into serving).** `hipfire-runtime` gains a second DSpark proposal binding next to the Qwen3/DeepSeek one: a `DsparkCommittedBody` keeps its own context projections for every committed target row, which the driver streams from prefill and forced advance (`SpecTarget::spec_advance_taps_gpu`, a device tap sink) and from each window's consumed rows (the anchor and the accepted drafts, never the bonus). The body drafts a fixed fill-in block and scores it itself; the driver checks that the draft holds exactly the rows before each anchor and repairs a terminal prefix by truncating the last window. `hipfire-arch-inkling2` adds the BF16 body built from existing HIP operators (`dspark_body`: three DFlare layers over taps entering visits 5/23/41 plus the final norm, the recurrent rank-256 Markov head with `f_rnn` from row `P-1`, `hidden_out` folded into the target unembed) and a scalar interleaved `SpecTarget` over a one-row tap seam (`spec_target`), which forwards a draft only after the target picked it, so it never rolls back. The existing Qwen3/DeepSeek bindings and `build_dspark_speculator` are unchanged. The GPU oracle (`tests/dspark_body_oracle.rs`) checks the body against the CPU reference: 4 golden windows (identical proposals, hidden cosine ≥ 0.99998), 765/800 gate windows with identical proposals and the other 35 differing only at logit near-ties (gap ≤ 0.125), the `f_rnn` state, reset, forced advance, `k = 0` and terminal repair.
