### Fixes: G12 engine loop, Gemma 4 batch reuse

- **A Gemma 4 prompt finds a snapshot at the grid end of an earlier, shorter prompt (HIPF-628; `generation.engine_loop = engine` with `serve.vmm_batch`).** `SessionCache::plan` probed only the boundaries of the current prompt. A Gemma 4 grid end (the prompt length rounded down to the prefill width) depends on the prompt length, so the 256 snapshot of a 459-token first turn was not probed for a 3454-token follow-up. The legacy loop found that prefix in its resident snapshot, but an engine lane park drops the resident. `plan` now probes every position p that is a boundary of the prompt cut at p, and hashes all probes in one pass (`prefix_fingerprints`). Qwen4 has no length-dependent boundary and probes the same positions as before. Halo, gemma-4-26b-a4b-it mq4, `engine_loop_ab.py --batch-only` (`chat_system`, `batch_reuse prompt`): P~1 reuses 256 (was 0), equal to the legacy loop.
