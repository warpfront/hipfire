### Fixes: sealed kernel routes

- **Fixed: a walked route plan no longer seals a load whose context selects kernels no walk ran.** A plan's `max_seq` was only a ceiling, but gfx1100 Q8 decode attention takes tile32 and the plain `attention_flash_q8_0_tile` at `max_seq <= 8192` and the GQA tile above, so a plan walked only at the default context sealed a `max_seq` 4096 load without the plain tile and failed every request (`attention_flash_q8_0_tile ... is outside this load's planned kernel route`). `route_plan_build.py --union-max-seq` now records every walked context (`#! walked_max_seq`), and the loader seals a Qwen3.5 load only when its Q8 decode attention band (`rdna_compute::attention::q8_decode_attn_band`) is one a walked context ran; a load in another band, or with a non-default `attention.flash`, keeps the plan open and logs `route left open, outside its walks`, so a kernel outside the walks binds lazily instead of failing the request. `route_plan_walk.py` drops the requests a short-context walk cannot fit.
