### Changes: G12 engine loop, capabilities and fallback on the wire

- **The load ack tells which routes run on the engine loop (HIPF-631, `generation.engine_loop = engine`).** The `loaded` event has a new `engine` object. `ar` and `verify` (`null` without a drafter) give the route, whether it runs on the engine and, if not, why (for example `a speculator is attached`). `session_reuse` and `lanes` (capacity, rows per step, windows, sampled windows, records) describe the load. The values come from the same admission checks that a request meets, for a greedy request without constraints.
- **A request that leaves its route says why on its terminal (HIPF-631).** On the engine loop, `commit_ready` and `done`, also the `done` of a cancel, list each step in `fallback`: `no_admission`, `engine_to_legacy`, `spec_to_ar` or `lane_to_resident`, each with its `reason`. Before, only stderr had the reason. A request that took its route has no `fallback`. The legacy loop (`engine_loop = legacy`) does not change.
- **Speculative lane admission no longer depends on the wire dialect.** A minimum token count or a think budget keeps a speculative request on the resident state for every wire, not only ChatML. The decisions do not change for Qwen4 and Gemma 4.
