### Changes

- **Inkling-2-Mini (arch 24): typed `qt44-padded-awq-v1` (`mq4-xts`) layout loads and decodes (scalar path).** The HFQ metadata key `hipfire_inkling2_mq4_layout` selects it (absent = the shipped RTN layout, unchanged; any other value fails the load). The loader certifies the exact census, shapes and strides, every attention / routed-expert / unembed qt44 half symmetric (`d >= +0`, `z == f16(-8*d)`), the 6,288 F16 AWQ sidecars (finite, > 0, wq/wr/gate identical, down tail exactly 1.0), F16 routers and the affine embed before anything reaches the GPU, then uploads attention with `WeightTensor::awq_scale`, experts directly (down `[2304, 1280]`, no repack) and per-layer device pointer tables built once at load. Decode runs `Gpu::rotate_x_mq_awq_topk` (new generic per-routed-expert AWQ + FWHT-256 producer, `kernels/src/rotate_x_mq_awq_topk.hip`) and the existing qt44 expanded GEMV; the CPU reference divides each calibrated tensor by its sidecar and slices the logical down. A certified load sets `Gpu::mq4v2_symmetric` (restored on unload / failed load) and logs one `inkling2 xts: ...` route-capability line (`kernel.iu4_prefill`, `developer.moe_sym_iu4`, A8 knobs; forced routes that cannot run are reported refused). `HfqFile::open`'s `mq4v2.symmetric` header sampler skips the affine `model.llm.embed.weight` only for arch-24 files carrying this layout key.
