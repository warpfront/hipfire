### Fixes: G12 engine loop, batch `done.tokens`

- **An engine request in a lane now reports the same `done.tokens` as on the resident state (HIPF-572; `generation.engine_loop = engine` with `serve.vmm_batch`).** The lane `done` counted the lane stream, which holds the EOS id on Qwen4 ChatML routes. A request that stopped on EOS reported one token more in the batch than alone (Qwen4 MTP `tb16` 31 vs 30), so `usage.completion_tokens` changed when a request was batched. The lane `done` now takes the count of the request run, which does not count the EOS. Legacy still counts the EOS on the singleton and in the batch (engine-loop A/B intended diff 2).
- **Engine-loop A/B harness: the token count is judged on the terminal id (HIPF-572, Loki HIPF-665/HIPF-666).** `scripts/engine_loop_ab.py` gives intended diff 2 (engine `tokens` = legacy − 1) only when both arms commit the same ids and the last id is in the new route key `eos_ids` (`[248046]` on Qwen4 routes). Before, any `stop` finish got it: a stop-string count one too low passed, and a correct `tool_calls` count on EOS failed. The `--batch` and `--conc` gates now also check that every finished engine request has `tokens` = its committed ids minus a terminal EOS. The HIPF-522 r7 AR receipt, with the count before the fix, fails both gates (batch 2, conc 144); with the EOS removed from the count, both count gates pass.
