## Route identity and admission

- Requested 27B pin: `HIPFIRE_IU4_PREFILL=0 --kv-mode fp8 --kv-v q8`, WT2 0.041859 / code24 0.029867 (`AGENTS.md:637-642`). **This exact CLI is refused in this source snapshot**: authored native FP8 is indivisible and rejects an authored V override (`crates/hipfire-runtime/src/kv_mode.rs:272-300`); native 27B additionally requires exact gfx1201 H24/Hkv4/D256 and neutral V (`crates/hipfire-arch-qwen35/src/carrier.rs:780-810`). Thus the exact requested command launches **zero** decode kernels. The tables inventory the underlying admitted neutral-V native-FP8 route, preserving the documentation/code discrepancy instead of inventing a mixed K-FP8/V-Q8 cache. The native writer dispatch writes **both K and V with the FP8 writer** (`crates/hipfire-dispatch/src/families/attention.rs:557-576`). The neutral `v_mode_bits==8` sentinel is not proof of Q8 V storage (`crates/hipfire-dispatch/src/families/kv_tier.rs:344-359`).
- On current gfx942 all native-FP8 27B writers/readers are excluded by `IsGfx1201` table predicates (`crates/hipfire-dispatch/src/tables/attention_table.rs:45-51,207-217`); Qwen4 `auto` resolves to F32-backed `bf16`, and explicit FP8 and Q8 fail before launch (`crates/hipfire-runtime/src/kv_mode.rs:548-575`). Proposed mirrors must change admission **and** registration **and** conversion semantics; widening a preprocessor gate alone is not a port.
- `HIPFIRE_IU4_PREFILL=0` does not imply FP8 activation GEMV: the F2 native-FP8 projection arm normally needs ≥512 token rows (`crates/rdna-compute/src/gemm.rs:835-839,10263-10283`). Qwen35's single-token projections remain MQ4/F32; Qwen4's qt44/qt53 indexed experts remain MQ4 with BF16 boundaries. Qwen4 weight-dtype projection dispatch explicitly distinguishes BF16/MQ4/MQ6/Q8 rather than FP8 (`crates/hipfire-dispatch/src/pipeline/layer_ops.rs:615-669`). FP8 in the ordinary decode census is **KV codes**, not FP8 activation slabs.
- Qwen35 lowered layer order is QKVZA → DN prep → recurrence → gated norm → WO residual → gate/up → SwiGLU/down residual; full attention instead uses QKV → FA prep/write/attend → WO residual → gate/up → down (`crates/hipfire-arch-qwen35/src/qwen35/forward.rs:6219-6252`). Qwen4 order is optional PLE → attn HC read → GDN or QSA → attn HC write → MLP HC read → clear/MoE → MLP HC write (`crates/hipfire-arch-qwen4/src/gpu_forward.rs:5653,5747,5787,5837,5897,5913,5956-5960,5981`). Layer rows below repeat at each corresponding layer; optional branches are alternatives, not an unconditional sum of all kernels.
- Qwen4 AR lanes on gfx1201 **do not share row-local stages**: only gfx1151 has the G0-covered production sharing policy; all other arches use `all_per_lane` (`crates/hipfire-arch-qwen4/src/gpu_forward_lanes.rs:211-265`). Stateful stages remain lane-local. Few-row verify kernels are inventoried separately below; a C8 AR wave on gfx1201 is not automatically an M=8 GEMV.
- **Model-name ambiguity in this tree:** the exact dense 27B fusion predicate is dim5120/L64/H24/Hkv4/D256/GDN16:48 (`crates/hipfire-arch-qwen35/src/qwen35/config.rs:1028-1039`). The test fixture labeled “3.8” instead has H48/Hkv8/D128 (`:1353-1367`), so it does not meet native-FP8 admission or the H24 fusion predicates. Tables give generic decode plus explicitly predicated H24 27B alternatives; no assertion that the fixture itself can run the historical pin.

## Shared gfx942 twin design contracts

These design IDs used in every kernel row specify both PM mapping and numerical fold; **an existing portable HIP source still needs a new PM gfx942 code object**.

- **V32 (canonical decode VALU):** wave64 with two independent logical width32 groups, index `lane=l&31`, `group=l>>5`; one output channel/group (or the incumbent's fixed channel bundle). Explicit `ds_bpermute_b32` addresses stay within the half; retain incumbent eight-term FMA DAG and ascending group/K order. No MFMA, no FP8, no LDS unless row explicitly specifies staging. Retain half-wave 32-thread HIP launches when portable; a full64 twin can pair two rows only with masked tails and the same DAG. PM decode DAG is not arbitrary associative math: MQ4 uses `t=fma(sc,q,zp)`, then a pinned pair-product order; single-row element1-first, dual-row row0 element0-first / row1 element1-first (`crates/peacemaker-isa/src/kernels/pm_decode/mod.rs:9-26`). A HIP twin must use explicit `fmaf` and contraction-off if exactness is required, not trust equal expressions.
- **VB (block VALU):** retain exact row-local elementwise/reduction/SFU sequence; fixed block256 (4 wave64), width32 shuffles where source uses logical groups, and the same LDS tree/intermediate storage. FNUZ fold **none** unless a KV codec row says otherwise. Preserve BF16 RNE storage boundaries. PM SFU parity is `[UNVERIFIED: confirm on MI300X]`.
- **KV-P (FP8 producer):** preserve OCP row layout `[KVheads*D codes][KVheads F16 scales]`. Compute original per-head `s16`, including zero/underflow/upward-ulp rules; encode `cvt_pk_fp8_f32((x/s16)*0.5)` on gfx942. Normalize OCP `0x80` signed-zero to `0x00` rather than let it become FNUZ NaN. QSA exact rules are `amax/448`, zero→1, smallest F16 subnormal floor and one-ulp bump (`kernels/src/tensor_ops.hip:3122-3150`). This is a codec twin, **not FP8 activation quantization**.
- **KV-D (FP8 consumer):** packed `v_cvt_pk_f32_fp8` produces FNUZ values; multiply by **`2*s16` before dot/softmax/PV** to recover OCP values. Do not multiply final attention output by2: nonlinear softmax requires corrected K before scores. Q stays F32, decoded V is scaled once. Q8 sibling uses signed-i8×F32-scale, no FNUZ fold. OCP→FNUZ factor2 follows the bias8/max240/0x80-NaN format (`CDNA3 ISA §7.2 p.50-52`); the external design theorem is `subq4/review/GFX942-FP8-FN-PLAN.md:90-101,308-309` (outside source tree). Codes differ only at signed zero; sign-of-zero bit identity is not claimed.
- **MF16 alternative (explicitly different numerical arm):** for repeated/few-row dense projection, pad activation rows to16; choose A=weights[output,K], B=activation[K,token], `v_mfma_f32_16x16x32_fp8_fp8`: lane l owns A[l%16,8*(l/16)+0..7], B[8*(l/16)+0..7,l%16], C/D item r = D[4*(l/16)+r,l%16], four accum VGPRs (`CDNA3 ISA §7.1.4 p.46-48`). If both operands are folded FP8, apply **4*a*s** to each scale block's product before combining blocks; producer uses `(x/a)*0.5`. For weight-only BF16 projection use `v_mfma_f32_16x16x16_bf16` with four BF16 inputs/lane; decode FP8 weights with `2s` then BF16 RNE, **not** FP8 activations. Neither MFMA arm is a byte-identical substitute for canonical V32; preserve same-named lever and require separate KLD/identity receipt. No int4 MFMA exists: MQ4/MQ6 retain VALU or explicitly unpack to i8/BF16, never reinterpret nibble bytes as FP8.
- PM wave64 metadata requires 64-bit EXEC/VCC, architecture VGPR/AGPR allocation (up to256 each), and LDS≤64KiB (`CDNA3 ISA §3.1 p.8-9; §3.6.4 p.12-13; §11.1 p.84`). Bank layout is32×4B; stage row-major dwords with padded strides if a transpose conflicts. Replace gfx10+ permlane/WMMA encodings with DPP/ds_swizzle/ds_bpermute/readlane (`CDNA3 ISA §13.3.9 p.544-545; §11.2 p.85-87`). `vmcnt` counts loads **and stores**, including mixed issue order; `lgkmcnt` is4 bits; no gfx12 vscnt encoding. Explicitly wait before LDS readers/barriers; barrier alone is not memory completion (`CDNA3 ISA §4.3-4.4 p.19-20`).
