# R4 — FP8 K/V state: Qwen4 QSA and dense Qwen3.5 native KV

CPU-only inventory/design. All repository citations below are relative to `/home/kaden/qcal/release-0.4.2/pm-cdna3`; proposed gfx942 paths/designs are not implementations. No builds, GPU runs or code changes.

## Critical route distinctions

- QSA `Fp8` means FP8 **both K and V**, one F16 scale per head per token, BF16 raw/pooled index keys (`crates/rdna-compute/src/tensor_ops.rs:2530-2593`). Admission: D256, even Hkv (`:2551-2559`); hardware gate currently gfx1200/gfx1201 (`:2727-2747`), runtime auto exact gfx1201 (`crates/hipfire-runtime/src/kv_mode.rs:548-551`).
- The dense 27B pinned spelling `--kv-mode fp8 --kv-v q8` is **not FP8 K + Q8_0 V**. `v_mode_bits == 8` is the neutral legacy V spelling for native FP8 V (`crates/hipfire-dispatch/src/families/kv_tier.rs:344-348`). Both sides use the FP8 writer (`crates/hipfire-arch-qwen35/src/qwen35/prefill.rs:10274-10289`; `src/forward_slots.rs:2307-2327`). FA2 KMODE=8 explicitly has FP8 K and V, stride 1032 (`kernels/src/attention_q8_0_fa2_gqa.gfx1201.hip:57-60`). `qresident_v2_q8` names **quantized Q input**, not Q8 V: arguments are `q_codes`, `q_scales` (`:3159-3162`). A real mixed FP8-K/Q8_0-V route would require a new format/dispatch contract, not merely mirroring this route.
- The eval harness requires the legacy q8 spelling (`crates/hipfire-runtime/examples/eval_hipfire.rs:453-462`), whereas the typed loader pair resolver refuses an explicit native mode plus any V-axis override (`crates/hipfire-runtime/src/kv_mode.rs:287-302`). Preserve the distinction; do not claim that every frontend accepts the pinned command.

## Exact storage numerics and byte-identity boundary

### E1: QSA append and fused prologue

`qsa_kv_store<FP8>` (`kernels/src/tensor_ops.hip:3122-3151`): one 256-thread block owns one head. Each channel's `fabs(value)` reduces within logical width32 (offset16,8,4,2,1); logical lane0 publishes `amax_lds[tid>>5]`, then every thread scans all eight slots, with barriers before read and before reuse. `s16 = amax==0 ? F16(1) : F16(amax/448)`; positive rounded-zero scale becomes bits `0x0001`; if `448*f32(s16)<amax`, increment F16 bits by **one** ULP, capped at `0x7bff`. This source has an `if`, **not a bump loop**. Code is low byte of `cvt_pk_fp8_f32(value / sf,0,0,false)`, hardware OCP RNE. Division by stored F16 scale, not `value*(1/sf)`. No explicit zero-sign or NaN remap. Layout: all `Hkv*D` code bytes, then `Hkv` little-endian F16 scales; each K/V row `Hkv*(D+2)` bytes (`:2951-2959,3147-3150`). Prologue computes norm/RoPE K before this encoder and stores V through a second call using the same LDS slots (`:3301-3320`); append encodes existing F32 K/V (`:3393-3417`).

### E2: dense single/batched/paged/VMM/lane encoders

Single `kv_cache_write_fp8_e4m3`: `kernels/src/kv_cache_write_q8_0.hip:104-145`; batched/paged: `kernels/src/kv_cache_write_q8_0_batched.hip:184-237`; VMM: `kernels/src/kv_cache_write_fp8_e4m3_vmm.hip:19-75`; lanes: `kernels/src/kv_cache_write_fp8_lanes.hip:43-96`. Each logical 32-thread group loads eight contiguous values/thread (D256), reduces local8 then XOR16..1. All use E1's **same scale/floor/single-bump rule and per-element division**, four packed pair conversions storing eight bytes/thread. No reciprocal substitution, no -0 normalization. Lane and VMM variants differ in row addressing, not encoding. Paged wrapper chooses `kv_cache_write_fp8_e4m3_batched_paged` (`attention.rs:2460-2464`); VMM uses descriptors (`kv_cache_write_fp8_e4m3_vmm.hip:65-75`).

### E3: actual Q8_0 encoding (adjacent alternative, not native-FP8 V)

QSA `qsa_kv_store<Q8>` uses per32 `amax/127`, `inv=127/amax` or0, `__float2int_rn(value*inv)`, clamp[-127,127], stores F16 scale plus32 signed bytes (`tensor_ops.hip:3107-3120`). Dense `kv_cache_write_q8_0`/batched/ring/independent variants use the same rule (`kv_cache_write_q8_0.hip:7-38,53-82`; `kv_cache_write_q8_0_batched.hip:8-59,76-108,120-157`). Code quantizes against F32 amax, **not rounded stored F16 scale**. Mirror is VALU integer RNE with unchanged scale; no FNUZ fold. Byte identity conditional on same input F32 and amax/rounding, not a claim about NaN.

### Proposed gfx942 E1/E2 encoder and decoder contract

- Keep `s16` bits and the **division result** `z=value/sf` unchanged, then FNUZ `cvt_pk_fp8_f32(z*0.5)`. Conditions per E1/E2: finite input, finite positive stored scale, normalized range ≤448, same F32 division/FP environment. Then `|z/2|≤224<240`; exponent-bias shift aligns finite nonzero OCP and FNUZ grids, including subnormals. RNE gives identical nonzero code bytes. Multiplication by0.5 is exact in this input range. Do not change scale denominator448 to240 or use amax/240: that breaks byte identity. This is a design theorem, not exercised hardware evidence (CDNA3 ISA §7.2 pp.50–52; plan §13.1).
- **Exceptions:** OCP negative-zero code `0x80` cannot be emitted as a finite FNUZ zero; canonical FNUZ zero is `0x00`. This includes input -0 and negative inputs that round to zero. Stored byte identity cannot hold there with hardware FNUZ encoding. Imported OCP `0x80` must be recognized before FNUZ conversion; canonicalize to0, or preserve signed-zero value via an explicit VALU special case if exact signed-zero decoding is required. OCP NaN bytes `0x7f/0xff` are finite FNUZ extrema, while FNUZ NaN is `0x80`; NaN byte identity and plain reinterpretation cannot both hold. Infinity/out-of-domain behavior is not covered.
- Scale ceiling matters: source comments exclude F16 infinity (`kv_cache_write_q8_0.hip:128-131`). For `amax>448*65504`, the generic ≤448 invariant is not guaranteed by the capped single bump; never extend the theorem to arbitrary F32 values/NaNs. No source-level finite-input admission is added by this design.
- Decode finite nonzero OCP byte b as FNUZ `cvt_pk_f32_fp8(b)*(2*sf)`; form `2*sf` in **F32**, not F16 (doubling65504 is legal F32). Scalar V decode preserves finite reconstructed value; factored K dot must preserve its existing accumulation sequence. QSA today performs serial code dot then `dot*sf` (`tensor_ops.hip:3065-3086`). A folded dot followed by `2*sf` has the same ordinary finite arithmetic under exact binary rescaling, but subnormal/intermediate underflow and FP mode mean universal bitwise attention identity is **not** promised; safest identity arm rescales decoded codes ×2 before the existing F32 dot. Same caveat for dense factored K dots (`attention_q8_0_kv.hip:253-285`).
- ISA conversion is RNE; **clamp/omod are ignored**. Saturation/NaN overflow uses FP16_OVFL; SH_MEM_CONFIG bit8 must be1. Packed destination write forwarding requires separation/NOP (`CDNA3 ISA §7.2 pp.50–52`). This is more precise than saying “clamp=saturate.” `[UNVERIFIED: confirm runtime mode and finite/zero conversion on MI300X]`.

## Wave64 PM/HIP building blocks (design)

**Amax256:** retain block256, four physical wave64s. Lowest-risk exact logical mapping preserves eight width32 groups: `ds_bpermute_b32` byte address `4*((lane&~31)|((lane&31)^offset))`, offsets16..1, `v_max_f32`; lanes0/32 publish slots `tid>>5`. Eight contiguous 4B LDS slots (32B), lgkm wait, barrier, scan8, barrier before K→V reuse. This reproduces source indexing exactly; `>>5` is a **logical group**, not physical wave ID. Alternative optimized finite-input mapping: ds_swizzle XOR1,2,4,8,16,32 over64, lane0 of each physical wave publishes `amax[tid>>6]` (4 slots/16B), scan4. DPP suffix-reduction row_shr1,2,4,8 plus row_bcast15 then row_bcast31 can publish a full-wave maximum from lane63; do not treat bcast31 as a full64 broadcast. Full-wave broadcast via ds_bpermute/readlane+scalar broadcast. For finite fabs/max these reductions are order-independent; NaN/sign-mode handling needs explicit comparison to source. DPP controls: CDNA3 ISA §13.3.9 pp.544–545; LDS32 banks×4B/64KiB: §2.2.1 p.6. No permlane16/x16 on this target.

**Dense eight-values/thread encoder:** either preserve block32 (half-populated wave64, all references remain within active lanes) or use block64, four values/lane and XOR32..1. Prefer block32 for stored-byte reference twin; block64 is a separate scheduling choice. Explicit width32 avoids relying on default shuffle width. Packed CVT operands must be VGPRs; retain independent registers/write spacing.

**VALU attention:** preserve token ownership, serial dimension/order chains, online softmax/gate and logical width32 max slots; no MFMA necessary for these twins. LDScode/score arrays remain indexed by thread, not physical wave. All EXEC/VCC manipulation becomes B64. `vmcnt` tracks loads **and stores** in issue order; `lgkmcnt` for LDS; wait before consuming/publishing, barrier does not replace memory waits (CDNA3 ISA §3.3 p.9; §4.4 pp.19–20).

**Gathered F16 MFMA:** preserve the derived F16 K and block-transposed V byte layout and F16 Q/P rounding, replace WMMA with `v_mfma_f32_16x16x16_f16` wave64. For lane l: A row `l%16`, K items `4*(l/16)+0..3` packed into2 VGPRs; B corresponding K rows/column `l%16`; C/D item r=`D[4*(l/16)+r][l%16]`,4 accumulators. Keep128-selected-token tile; four wave64s each process two16-token subtiles to cover original eight16-token tiles. LDS Q `[dc][head][16]`, P `[subtile][head][16]`, token indices, max/sum slots reallocated by **subtile**, not physical wave. ≤64KiB including dynamic token list. FNUZ→F32 `(2s)` then F16 RNE conversion is outside MFMA, so no additional ×4 here. MFMA layout: CDNA3 ISA §7.1.4 pp.46–48. Output is not guaranteed WMMA-bit-identical.

**Dense FP8 stage-b MFMA:** `16x16x32_fp8_fp8`, wave64 A/B8 bytes/lane in VGPR pair; D4 floats with mapping above, Q/K codes unchanged except zero handling. QK epilogue ×4*sq*sk (both codes folded), retaining scale placement per token; FP8-P/PV separately account for folded P and folded V, ×4*sp*sv. If P producer actually emits unfurled FNUZ rather than OCP-compatible half-valued codes, factor changes: choose the half-valued-byte contract consistently. F16 Q0 uses the preceding F16 MFMA design. Matrix accumulation order differs from WMMA and is not documented internally: `[UNVERIFIED: confirm error/KLD on MI300X]`.

## Admission, arenas, and call-chain consequences

- QSA storage units/dtypes must remain unchanged: Raw K/V, BF16 index keys (`tensor_ops.rs:2563-2593`). `qsa_context_arena_bytes` is charged using the selected layout (`crates/hipfire-arch-qwen4/src/config.rs:1632-1635`), bundle per-layer charge (`src/bundle.rs:236-240`), admission resolver (`crates/hipfire-loader/src/admission.rs:1501-1502`), committed bytes (`bundle.rs:2347`). Selected capacity budget+compress−1 (`config.rs:1625-1626`). Proposed gfx942 uses this same FP8 byte charge, not F32 fallback charge.
- At QSA Hkv2,D256: K/V combined1032B/token, versus4096B F32 (derived from `tensor_ops.rs:2572-2584`). Index arenas also change F32→BF16; do not reuse plan §13.1's unchanged-F32 index-key approximation as the implementation's exact memory charge. Gather scratch K rows and whole-four-token V blocks are separate (`tensor_ops.rs:4907-4912,5127-5137`); FP8 persistent F16 arena is currently disabled (`:2654-2659`). Must charge reserved and mapped prefixes consistently (`crates/rdna-compute/src/dispatch.rs:3926-3938`).
- Dense Hkv4,D256 native FP8:1032B/side/token (`attention.rs:168-170`),16 KV layers→33024B/token (`CHANGELOG.md:1589`). A hypothetical actual Q8_0 V would be1088B/side and different total; that is **not** these native buffers. - Capacity checks at native wrappers use owned byte capacity, VMM exceptions/mapped-prefix ownership (`attention.rs:181,2454-2455,2761-2762`). Slot/PagePool preflight currently cites `R9700_VRAM_BYTES` (`crates/rdna-compute/src/slot_pool.rs:115-116`, `page_pool.rs:378-379`); actual serve engine uses free VRAM (`crates/hipfire-arch-qwen35/src/serve_engine.rs:1020-1021`). Proposed gfx942 admission must resolve actual MI300X budget at existing admission layer, not inherit an R9700 capacity assumption.
- Qwen4 ops select/pool/attention callsites (`crates/hipfire-arch-qwen4/src/ops.rs:490,517,556,582`) and dispatcher lowering (`crates/hipfire-dispatch/src/pipeline/layer_ops.rs:2997,3011,3080`) must continue using the resolved state format. ## Portable as-is / needs twin / blocked

- **Portable ownership/math as-is on wave64:** index BF16 append/pool, serial norm/RoPE, serial attention, explicit width32+eight-slot QSA max reductions, block-wide LDS scalar softmax reductions, integer selection helpers. Hardware FP8 conversion branch and host architecture admission still require the gfx942 twin/capability changes. `tid>>5` is not itself a wave64 bug when eight logical32 slots are written/scanned.
- **Needs twin:** every hardware OCP FP8 encoder/decoder; gathered WMMA/permlanex16 emitter and HIP body; dense FA2 WMMA/Q-resident/packet routes; arch-specific GQA/reducer pairs and their VMM/paged symbol variants; PM wave32/B32 EXEC masks; bundle manifests/SHA pins. The parallel HIP gfx942 weight-MoE port is not a KV twin: no row-F16-scale KV reader/writer reuse is justified by a weight dequant kernel's existence.
- **Blocked as a byte-identity statement:** universal OCP/FNUZ bytes for negative zero (including negative values rounding to zero), NaNs, scale-overflow/out-of-domain inputs; universal WMMA/MFMA output bits. These are explicit numeric contract differences, not unresolved source discovery.
- `[UNVERIFIED: confirm on MI300X]` FNUZ -0 output byte, underflow/denorm mode, FP16_OVFL/SH_MEM_CONFIG setup, exact packed-conversion instruction lowering and division DAG; scalar reconstruction equivalence on finite edge cases; MFMA internal accumulation order/error; runtime wave64 behavior of compiled width32 shuffles; occupancy/bank-conflict performance of proposed fourwave64 tilings.
- `[UNVERIFIED]` frontend end-to-end compatibility of the historical eval pinned `--kv-mode fp8 --kv-v q8` spelling with the newer typed native-pair resolver: the two source contracts differ; neither warrants inventing an FP8-K/Q8-V route.

Suggested main-agent validation (not run here): per-encoder stored-code+F16-scale comparison at D256/Hkv2 and4 including zero/ties/subnormals; QSA append versus fused prologue equivalence; imported OCP -0/NaN handling; scalar/parallel/hg4/gathered routes and paged/VMM/lane address equivalence; gfx942 PM versus HIP output; qwen4_qsa_arena_check and admission accounting; generator KLD distinct from F32-state teacher.
