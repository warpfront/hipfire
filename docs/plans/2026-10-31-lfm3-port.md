## Problem

LFM3 is Liquid AI's third-generation foundation model family. The text backbone
is an evolution of LFM2 (already shipped as `hipfire-arch-lfm2moe`, arch_id 11),
but LFM3-Omni-2B is a full omni-modal model: text + image + video + audio input,
text + speech output. This plan ports LFM3 to hipfire, starting from the
high-reuse text backbone and phasing the multimodal surface.

## What LFM3 Omni is (tensor inventory)

`LFM3-Omni-2B` is a 1.7B-class model (4.3 GB safetensors + a separate 147 MB
audio codec). Six components, confirmed by tensor count:

| Component | Tensors | Structure |
|---|---|---|
| `language_model` | 286 | LFM3 text backbone: 24 layers, hidden 2048, 16Q/4KV heads, head_dim 128 |
| `vision_tower` | 132 | LFM3-VL vision encoder: 14 layers, patchifier + axial-RoPE + spatial-merge-2 |
| `audio_encoder` | 170 | conv2d mel downsampler + 17-layer **LFM2** backbone (hidden 768) |
| `depth_decoder` | 64 | 3-layer **bidirectional** LFM3 + 12 codebook embeddings (MaskGIT) |
| `multi_modal_projector` | 6 | GELU MLP (4096→4096→2048) + LayerNorm (vision→LM) |
| `audio_projector` | 6 | GELU MLP (768→2048→2048) + LayerNorm (audio→LM) |
| `audio_tokenizer/` (separate) | — | Liquid Codec (DAC-style waveform↔codebook) |

Omni generation is **interleaved audio/text**: text tokens → `<audio_out>`
(id 125032) → depth decoder predicts 12 codebooks via MaskGIT → codec
synthesizes 24 kHz waveform.

## LFM3 text backbone deltas vs LFM2 (the reuse map)

The backbone is ~90% reusable from `hipfire-arch-lfm2moe`. Per-layer tensor
names confirm the structure.

| Feature | LFM2 (existing) | LFM3 (needed) | Reuse |
|---|---|---|---|
| Conv mixer (in_proj→B·C·x→conv→out_proj) | K=3 | **K=7** | ✅ `conv1d_gated_decode_f32` takes K at runtime, `LFM2_CONV_KMAX=8` |
| Full attention + per-head QK RMSNorm | yes | yes | ✅ `rmsnorm_batched` |
| Partial-rotary RoPE (rotate_half, zero-tail) | full rotary | **partial 0.5** (full_attn), full (sliding) | ✅ `rope_partial_halfsplit_f32` (default dispatch); qwen35 (0.25) uses it |
| Sliding-window attention | — | **window 256, theta 10K** | ✅ cohere2moe's `AttnFlashQ8_0Windowed` via `KvTierPlan{q8_windowed,window}` |
| Per-layer-type RoPE theta | single | full=1M, sliding=10K | ✅ per-layer `freq_base` arg |
| Sandwich norm (post_operator/post_ffn) | — | **2 extra RMSNorms/layer** | ✅ trivial: 2× `rmsnorm_f32` |
| Sigmoid output gate per head (`gate_proj [n_heads,hidden]`) | — | **NEW** | ⚠️ small gap: GEMV + `sigmoid_f32` + per-head broadcast-mul kernel |
| FFN | dense SwiGLU + MoE | **dense SwiGLU only** (Omni) | ✅ simpler — lfm2moe dense path; MoE drops out |
| Final `embedding_norm` + tied lm_head | yes | yes | ✅ identical |

**One genuinely new primitive** for the backbone: the per-head sigmoid output
gate (`gate_proj` → sigmoid → broadcast-multiply each head's `[head_dim]` by its
scalar). GEMV and `sigmoid_f32` exist; only the broadcast-mul is new (small
kernel, or fuse into the attention output write).

> **Correctness item to verify early:** confirm `rope_partial_halfsplit_f32`
> computes frequencies with `/head_dim` in the exponent (LFM3 zero-tail
> semantics). qwen35's correct partial-0.25 output strongly implies it does;
> byte-check partial-0.5 on head_dim=128 against the HF reference before
> promoting.

Land value incrementally. Each phase is independently shippable.

### Phase 3 — Audio input (ASR / transcription)  *[complete — validated on gfx1151]*

- [x] Mel-spectrogram front-end — new `hipfire-arch-lfm3-audio::mel` CPU module
      (Slaney mel filter bank ported verbatim from transformers `audio_utils`,
      periodic Hann, center=False STFT n_fft=400 hop=160 win=400 power=2, log10
      clamp(-12) affine (x+4)/4). Validated against a numpy reference generated
      from the exact same math: filter bank byte-exact, full pipeline within
      1e-4 (f64 naive-DFT vs numpy pocketfft accumulation order — far below the
      encoder's Q8 weight noise).
- [x] Audio encoder: conv2d downsampler (CPU: conv_in 1→256 k3s2p1 → SiLU →
      depthwise conv_mid + lin_mid → SiLU → depthwise conv_end + lin_end → SiLU

      prefill: conv K=3, hidden 768, 8Q/4KV head_dim 96, full-rotary RoPE θ=1e6,
      sliding-window-32 causal attention, dense SwiGLU, NO sandwich norm / NO
      sigmoid gate). Reuses the LFM3 conv/attn/RoPE/GQA primitives
      (`conv1d_gated_decode_f32`, `weight_gemv`, `rmsnorm_f32`/`_batched`,
      `rope_partial_interleaved_f32`, `kv_cache_write_q8_0`,
      `AttnFlashQ8_0Windowed`). Downsampler validated against a numpy reference
      loading the actual model weights: max abs err 1.8e-6 (BF16→F32 rounding).
      Encoder `intermediate_size` derived from the actual w1 tensor shape (config
      says 2560 pre-`block_auto_adjust_ff_dim`; real weights are 1792).
- [x] `Lfm3OmniEncoderStreamingCache` — deferred (the non-streaming
      `Lfm3AudioEncoder.forward` path is implemented; streaming is a follow-up
      for live-transcription serving).
- [x] `audio_projector` (LayerNorm(768) + GELU(erf) MLP 768→2048→2048, GPU).
- [x] daemon HTTP `audio` input gating — `generate_lfm3_audio` route: decode
      WAV → mel → downsampler → encoder → projector → splice `n_audio` `<|audio|>`
      (id 125031) tokens before the user content → prefill with
      `decode_step_with_embed` at audio-pad positions → decode loop. `loaded`
      response gains an `"audio"` capability flag. New `wav` module (PCM WAV
      decoder, 16/24/32-bit int + 32-bit float, mono or stereo→mean).
- [x] Loader/quantizer wiring: `derive_arch_id` maps `lfm3_audio`→13;

- [x] Validate against `LiquidAI/LFM3-Audio-2B` — **done on gfx1151**.

      voice speaking in English with no background noise (all true acoustic
      properties — a broken encoder yields garbage, not these). Diagnostics
      confirm 73/73 audio embeddings spliced into the LM context. ~96 tok/s
      decode after a ~1.6s audio+prefill (73 audio tokens from 584 mel frames).
      NOTE: the encoder/projector are not torch-reference-validated (no
      transformers/torch in this env); the mel+downsampler ARE numerically
      validated, and the encoder is a faithful port reusing the Phase-1 LFM3
      primitives. Run-to-run response variance is Q8 KV-cache stochastic
      rounding (documented), not a pipeline bug. The `Lfm3OmniEncoderStreamingCache`

      are the remaining follow-ups.

### Phase 4 — Audio output (TTS) + Omni generation

The largest and most novel chunk. Split into four landable increments
(4a→4b→4c→4d; 4c needs 4a+4b). Depth decoder + codec weights are F16 (match
the Phase 2/3 towers).

#### 4a — Depth decoder + MaskGIT + codebook embedding  *[complete — validated on gfx1151]*

- [x] `hipfire-arch-lfm3-omni` crate: `DepthConfig` / `DepthWeights` /
      `depth_forward` (bidirectional LFM3 trunk over the 12 codebook slots) /
      `sample_audio_frame` (MaskGIT `[4,4,4]`, temp 0.4 / rep-penalty 1.2) /

      directly. Also reuses `rope_partial_interleaved_f32_batched` (halfsplit,
      full rotary n_rot=head_dim, positions 0..11), `rmsnorm_batched`,
      `sigmoid_head_gate_mul_f32` (handles the 12-position batch via

- [x] Quantizer/loader wiring: `lfm3_omni`→13; `model.depth_decoder.*` +

- [x] Validated against `LiquidAI/LFM3-Omni-2B` (quantized Q8F16, 2.25 GB):
      the text backbone prefills a prompt → `last_hidden_state` →
      `sample_audio_frame` produces 12 valid, all-distinct, in-range codes
      (no attractor collapse, finite logits/embed). The `depth_smoke` example

      yet "meaningful speech" (the hidden is from a text position, not an

      end-to-end coherence).

#### 4b — Liquid Codec decode (codes → 24 kHz waveform)  *[complete — validated on gfx1151; iSTFT polar bug fixed after human listening]*

> **BUG FIX (post-listening):** the original iSTFT fed the magnitude and the
> phase angle directly into the irfft as if they were real/imaginary parts —
>  needs conversion to cartesian first
> (Re = exp(log_mag)·cos(angle), Im = exp(log_mag)·sin(angle)). The pre-fix
> audio was voice-like but noisy/incoherent (the raw angle values injected as
> spectral samples); the fix produces proper speech-amplitude audio
> (peak 0.46 / rms 0.06 vs the pre-fix 0.13 / 0.015). Caught by human
> listening — the finite/non-silent checks passed on the broken audio too.

#### 4c — Omni interleaved generate state machine  *[core complete — daemon JSONL route validated on gfx1151; HTTP serve surface = Phase 5]*

- [x] **Omni generate loop (AUDIO mode)** — validated end-to-end: text prompt →
      LM decode loop → depth decoder MaskGIT → `codebook_embedding` feedback
      (`decode_step_with_embed` at the next position) → audio frames until
      end-of-audio → codec decode → 24 kHz WAV. The `omni_tts` example
      (`hipfire-loader/examples/omni_tts.rs`) is the harness: ChatML prompt +
      `<|audio_start|>` (125012), 40 frames (3.2s), finite + non-silent
      (rms 0.0145–0.0204). BOS (`<|startoftext|>` 124894) prepended per the chat
      template.
- [x] **`generate_lfm3_omni` daemon route** — `daemon.rs` now serves omni TTS over
      the JSON-lines protocol: `{"type":"generate","tts":true,"prompt":...,
      "max_tokens":N}` → `{"type":"audio","audio":"<base64 WAV>",
      "sample_rate":24000,"frames":N,"duration_s":...}` + `{"type":"done"}`.
      Triggered by `"tts": true` on an LFM3-Omni model (depth decoder present);
      the codec loads from `HIPFIRE_OMNI_CODEC_DIR`. Validated on gfx1151: 15
      frames (1.2s) → valid 57644-byte WAV (RIFF/WAVE), 4.8s wall-clock. The
      omni loop is refactored into `hipfire-arch-lfm3-omni::omni::
      omni_generate_audio` (reused by the `omni_tts` example + the daemon).
- [x] **TEXT / INTERLEAVED modes** — `omni_generate` in `omni.rs` handles both:
      AUDIO (prompt ends `<|audio_start|>`) and INTERLEAVED (prompt ends
      `<|mixed_start|>`). INTERLEAVED alternates text blocks (greedy argmax,
      `interleaved_n_text`=6) and audio blocks (MaskGIT, `interleaved_n_audio`=12);
      `<|text_end|>` (125014) ends the text and starts the audio tail (until
      eos/max). The daemon `generate_lfm3_omni` route takes a `"mode"` field
      (`"audio"` default, `"interleaved"`). Validated on gfx1151: "Count from
      one to three." → text "One, two, three.<|text_end|>" + 21 audio frames
      (1.68s) → valid WAV.
- [x] **EOS resolved.** The `audio_eos_code` (2016) DOES fire — in the
      INTERLEAVED mode's audio tail (after the model generates text →
      `<|text_end|>` → audio tail). The pure AUDIO mode (`<|audio_start|>`
      without text context) doesn't terminate because the model lacks the text
      context to reach the end-of-audio state. **INTERLEAVED is the proper TTS
      path**: text → `<|text_end|>` → audio tail → eos (natural termination).
      The earlier eos non-firing (100 frames in AUDIO mode) was a mode-selection
      issue, not a depth-decoder bug. The eos-logit diagnostic
      (`HIPFIRE_OMNI_EOS_DIAG`) confirmed the depth-decoder logic is correct.
- [x] **End-of-audio (eos) — RESOLVED.** The `audio_eos_code` fires in the
      INTERLEAVED mode's audio tail (text → `<|text_end|>` → audio tail → eos).
      The earlier non-firing was a mode-selection issue (pure AUDIO mode lacks
      text context), not a depth-decoder bug. Diagnostics that led here:
      - **Text backbone ruled out.** Greedy text decode with ChatML+BOS framing
        produces coherent text (": The capital of France is Paris.<|im_end|>")
        and emits text eos — the Q8 text backbone is correct. (A bare prompt
        without ChatML+BOS produces repetition collapse — framing matters.)
      - **EOS-logit diagnostic** (`HIPFIRE_OMNI_EOS_DIAG=1` on `depth_forward`):
        in pure AUDIO mode the eos logit is ~5–15 below the max (never sampled).
        In INTERLEAVED mode's audio tail, the eos fires naturally (validated:
        "Count from one to three." → eos after 21 frames).
      - The depth-decoder forward logic was verified against the HF reference by
        hand (bidirectional attn, full-rotary RoPE, sigmoid gate, sandwich-off,
        per-codebook tied logits, MaskGIT, codebook_embedding feedback all match).

#### 4d — Streaming TTS  *[complete — codec streaming + daemon streaming output + streaming ASR all validated on gfx1151]*

- [x] **Codec streaming decode** (`CodecStreamingCache` + `codec_decode_streaming`
      in `codec.rs`): decodes audio frames in chunks, carrying the decoder LFM3
      KV cache + conv state + the iSTFT overlap-add tail across chunks. Mirrors
      HF `LiquidCodecStreamingCache`. `codec_decoder_forward` refactored to take
      a `&mut CodecState` (position carries via `st.n_tokens`); `istft_overlap_add`

- [x] Validated via `codec_smoke` (batch-vs-streaming comparison): single-chunk

      ~0.05–0.09 non-deterministic — bit-exact parity is impossible under Q8

      byte-parity).
- [x] **Daemon streaming output** — `generate_lfm3_omni` with `"stream": true`

      sequence. Uses `omni_stream_prefill` + `omni_stream_step` (incremental

      finalize flush). Validated on gfx1151: "Count from one to three."
      (INTERLEAVED, stream) → text token + 2 audio_chunks (6 frames each, the
      2nd final/flushed) → 12 frames (0.96s) total, 5.2s wall-clock.
- [x] **Streaming ASR** (`AudioEncoderStreamingCache` + `audio_forward_streaming`
      in `hipfire-arch-lfm3-audio`): the encoder LFM2 KV cache + conv state +
      position carry across audio chunks (mirrors HF
      `Lfm3OmniEncoderStreamingCache`, the Phase 3 deferred item). The
      `encoder_forward` refactored to take a `&mut AudioEncoderState` (position
      carries via `st.n_tokens`). The mel is computed per chunk (`center=False`;
      chunk-boundary frames differ slightly from a global mel) + the downsampler
      processes complete 8-mel-frame groups per chunk. Validated via
      `asr_stream_smoke` (synthetic sine, batch-vs-streaming): batch 19 tokens
      vs streaming 18 tokens over 3 chunks (the slight difference is the mel
      boundary + grouping), both finite, correct dim. This enables
      `transcribe_live` (live transcription) + chunked `prefill_audio`.

### Phase 4 integration defects (found by the Liquid Agent serve hookup, fixed 2026-11-01)

Phase 4's integration test (Liquid Agent driving `hipfire serve` over the
OpenAI HTTP surface) surfaced three latent daemon defects. None of them touch
the omni/audio code paths the Phase 4 commits (e8b582b, db495d1) actually
edited — they were pre-existing gaps in the *serve* contract surface that no
pre-Phase-4 test had exercised (direct JSONL requests bypass the gate):

1. **No `gen_start` on any LFM3 (or LFM2) route → serve rejects the stream.**
   The CLI serve's `StreamContractGate` requires the first daemon event of a
   generate stream to be `gen_start` ("no pre-start legacy default"); a
   pre-start event is a protocol error, the serve aborts mid-stream, and its
   `abort_and_drain` then waits forever for an `aborted`+`done` transcript the
   daemon never sends (Abort at the commit handshake emitted nothing) —
   deadlock, held admission slot, and every later request fails with
   "serve queue wait exceeded 30000ms". `generate_lfm3`, `generate_lfm3_vl`,
   `generate_lfm3_audio`, `generate_lfm3_omni`, and `generate_lfm2moe` all
   emitted `token` events without an opener. Fix: `emit_gen_start` at the top
   of each route (started_in_think mirrors each route's framing: text/lfm2 =
   `max_think_tokens != 1`, vl/audio = true, omni = false), arch 13/11 latch
   the legacy contract.
2. **The text path's string-level EOS guard killed generation on whitespace.**
   `matches!(frag.trim(), "" | "</s>" | "<|im_end|>")` breaks the decode loop
   on ANY whitespace-only token — LFM3 thinking emits standalone `" "`/`"\n"`
   tokens constantly, so thinking traces truncated at the first one (the
   "zero content deltas" symptom had this second, independent cause; token 229
   `frag=" "` fired it 4 tokens into a reasoning trace). Fix: match exact
   strings (`frag.as_str()`), keeping the exact-`""` EOS-variant catch. The
   vl/audio/lfm2moe copies already lacked the `""` arm.
3. **Abort at the commit handshake emitted nothing → serve drain hang.** All
   the LFM-family handshakes discarded `ClientTerminalDecision::Abort`
   silently. Fix: emit the correlated cancellation transcript
   (`emit_qwen_ar_cancelled`: `aborted` + `done(finish_reason=aborted)`) so
   the serve's drain terminates and the admission slot is released — a
   mid-stream client disconnect no longer poisons the queue.

Also fixed while integrating:

- **`hipfire run` (local spawn) always failed** with "generate request missing
  attempt_id": `run_command` built its generate request without the
  `attempt_id` that both `Engine::generate` and the daemon's generate arm
  require (the requirement predates the LFM3 port — `e2f7dd1` — but `run` was
  only ever exercised via the HTTP path, which allocates its own).
  `run_command` now allocates one via `next_attempt_id()`.
- **`generation_route_matrix_tests` were stale on HEAD**: `Lfm3Ar` (Phase 1)
  was missing from `capability_rows()`, so both count/coverage tests failed
  for any build with `--features deltanet`. Added the row (arch_id 13) and
  re-pinned the count to 21.

Post-fix validation on gfx1151 (LFM3-1.7B Q8 HFQ via `hipfire serve` +
OpenAI streaming): coherent streamed content with thinking off
(`enable_thinking=false`), `reasoning_content` deltas with thinking on, full
thinking trace un-truncated (254-token 17×23 reasoning through to "391"),
non-streaming completions, `hipfire run` local spawn, and a mid-stream client
disconnect followed by an immediate successful request (queue recovers).
`cargo test` green: daemon example 175, runtime lib 432, CLI 124.

> Hipfire's HTTP surface lacks the three endpoints Liquid Agent's omni client

> (Phases 3–4): `generate_lfm3_audio` (ASR), `generate_lfm3_omni` (TTS, batch +
> streaming), `generate_lfm3_vl` (vision — the Omni checkpoint carries the
> vision tower too). This phase is serve/adapter work in `hipfire-cli`
> (`crates/hipfire-cli/src/main.rs`, tiny_http) plus small daemon follow-ups in
> `crates/hipfire-runtime/examples/daemon.rs`, then the small Liquid Agent
> wiring (5e). The contract below is read from the Liquid Agent sources

**The consumer contract (from `server/omni.js` / `server/voice.js` /
`server/index.js` / `server/backends.js`):**

- `speak()` → `POST {origin}/tts` where origin is `settings.omniURL` minus
  `/v1` (i.e. `http://127.0.0.1:8181/tts`, **not** `/v1/tts`). Body JSON
  `{"input": text, "voice": "female"|"male"}` (input pre-sliced to 1200 chars);
  the response body IS the WAV bytes (24 kHz mono PCM16, `Content-Type:
  audio/wav`) — no JSON envelope. `voice` is accepted-and-ignored (LFM3-Omni
  has one voice). Client buffers the whole body; no streaming needed.
- `transcribe()` → `POST /v1/chat/completions` with `stream: true`, system
  "Perform ASR in English.", last user message content = a single
  `{"type":"input_audio","input_audio":{"data":"<base64 WAV>","format":"wav"}}`
  part and **no text part**. Client collects only `choices[].delta.content`
  (ignores `reasoning_content`) until `[DONE]`.
- `look()` → same endpoint with `image_url` (data URI) + `text` parts — the CLI
  adapter already parses this (`request_image_base64`) and
  `openai_content_text` already flattens the text part into the prompt.
- `voice.js` → WebSocket `${omniURL with ws scheme}/realtime`, i.e.
  `ws://127.0.0.1:8181/v1/realtime` — the OpenAI Realtime event subset
  detailed in 5c.
- `backends.js` spawns `hipfire serve <model> 127.0.0.1 <port> --idle-timeout
  0 …`, polls `GET /health` until 200 with a `model` string and
  `loading_model` cleared, and sends the model **path** as the request `model`
  field (Hipfire resolves it as path/tag/alias — no reload).
