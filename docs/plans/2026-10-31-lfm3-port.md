# Plan — LFM3 (text + Omni) port to hipfire

> **Status:** planning / in-progress (Phase 1 scaffolding).
> **Source models:** `LiquidAI/LFM3-1.7B` (text-only, validation target) and
> `LiquidAI/LFM3-Omni-2B` (omni-modal, local at `/data/liquid-ai/LFM3-Omni-2B`).
> **Ground truth:** transformers `configuration_lfm3.py`, `modeling_lfm3.py`,
> `modeling_lfm3_omni.py`, `lfm3_conv.py` (read 2026-10-31).
> **Related:** [`docs/architecture-ids.md`](../architecture-ids.md) (arch_id registry).

## Problem

LFM3 is Liquid AI's third-generation foundation model family. The text backbone
is an evolution of LFM2 (already shipped as `hipfire-arch-lfm2moe`, arch_id 11),
but LFM3-Omni-2B is a full omni-modal model: text + image + video + audio input,
text + speech output. This plan ports LFM3 to hipfire, starting from the
high-reuse text backbone and phasing the multimodal surface.

## What LFM3 Omni is (tensor inventory)

`LFM3-Omni-2B` is a 1.7B-class model (4.3 GB safetensors + a separate 147 MB
audio codec). Six components, confirmed by tensor count:

| Component | Tensors | Structure |
|---|---|---|
| `language_model` | 286 | LFM3 text backbone: 24 layers, hidden 2048, 16Q/4KV heads, head_dim 128 |
| `vision_tower` | 132 | LFM3-VL vision encoder: 14 layers, patchifier + axial-RoPE + spatial-merge-2 |
| `audio_encoder` | 170 | conv2d mel downsampler + 17-layer **LFM2** backbone (hidden 768) |
| `depth_decoder` | 64 | 3-layer **bidirectional** LFM3 + 12 codebook embeddings (MaskGIT) |
| `multi_modal_projector` | 6 | GELU MLP (4096→4096→2048) + LayerNorm (vision→LM) |
| `audio_projector` | 6 | GELU MLP (768→2048→2048) + LayerNorm (audio→LM) |
| `audio_tokenizer/` (separate) | — | Liquid Codec (DAC-style waveform↔codebook) |

Omni generation is **interleaved audio/text**: text tokens → `<audio_out>`
(id 125032) → depth decoder predicts 12 codebooks via MaskGIT → codec
synthesizes 24 kHz waveform.

## LFM3 text backbone deltas vs LFM2 (the reuse map)

The backbone is ~90% reusable from `hipfire-arch-lfm2moe`. Per-layer tensor
names confirm the structure.

| Feature | LFM2 (existing) | LFM3 (needed) | Reuse |
|---|---|---|---|
| Conv mixer (in_proj→B·C·x→conv→out_proj) | K=3 | **K=7** | ✅ `conv1d_gated_decode_f32` takes K at runtime, `LFM2_CONV_KMAX=8` |
| Full attention + per-head QK RMSNorm | yes | yes | ✅ `rmsnorm_batched` |
| Partial-rotary RoPE (rotate_half, zero-tail) | full rotary | **partial 0.5** (full_attn), full (sliding) | ✅ `rope_partial_halfsplit_f32` (default dispatch); qwen35 (0.25) uses it |
| Sliding-window attention | — | **window 256, theta 10K** | ✅ cohere2moe's `AttnFlashQ8_0Windowed` via `KvTierPlan{q8_windowed,window}` |
| Per-layer-type RoPE theta | single | full=1M, sliding=10K | ✅ per-layer `freq_base` arg |
| Sandwich norm (post_operator/post_ffn) | — | **2 extra RMSNorms/layer** | ✅ trivial: 2× `rmsnorm_f32` |
| Sigmoid output gate per head (`gate_proj [n_heads,hidden]`) | — | **NEW** | ⚠️ small gap: GEMV + `sigmoid_f32` + per-head broadcast-mul kernel |
| FFN | dense SwiGLU + MoE | **dense SwiGLU only** (Omni) | ✅ simpler — lfm2moe dense path; MoE drops out |
| Final `embedding_norm` + tied lm_head | yes | yes | ✅ identical |

**One genuinely new primitive** for the backbone: the per-head sigmoid output
gate (`gate_proj` → sigmoid → broadcast-multiply each head's `[head_dim]` by its
scalar). GEMV and `sigmoid_f32` exist; only the broadcast-mul is new (small
kernel, or fuse into the attention output write).

> **Correctness item to verify early:** confirm `rope_partial_halfsplit_f32`
> computes frequencies with `/head_dim` in the exponent (LFM3 zero-tail
> semantics). qwen35's correct partial-0.25 output strongly implies it does;
> byte-check partial-0.5 on head_dim=128 against the HF reference before
> promoting.

## Phasing

Land value incrementally. Each phase is independently shippable.

### Phase 1 — LFM3 text-only (arch_id 13)  *[current — scaffold complete]*

Port the backbone from lfm2moe. High reuse, low risk. Makes LFM3 text inference
work against `LiquidAI/LFM3-1.7B`.

- [x] Scaffold `hipfire-arch-lfm3` crate from the lfm2moe template
      (`config.rs` / `arch.rs` / `lfm3.rs` / `forward.rs` / `spec_impl.rs` / `lib.rs`).
- [x] `Lfm3Config`: parse `layer_types` (`conv`/`full_attention`/`sliding_attention`),
      per-type `rope_parameters` (theta + partial_rotary_factor), `sliding_window`,
      `use_sandwich_norm`, `conv_L_cache` (7), `head_dim`.
- [x] `Lfm3Weights`/`Lfm3State`: mirror lfm2moe; add `gate_proj` per attention
      layer, `post_operator_norm`/`post_ffn_norm` per layer; drop MoE (dense-only).
- [x] `forward.rs` decode loop: conv (K=7) / full-attn (partial 0.5, theta 1M) /
      sliding-attn (full, theta 10K, window 256) + sandwich norms + sigmoid gate.
- [x] New small kernel: per-head sigmoid output-gate broadcast-mul
      (`sigmoid_head_gate_mul_f32` / `kernels/src/sigmoid_head_gate_mul.hip`).
- [x] Wire sliding attention via `KvTierPlan{q8_windowed:true, window}` (cohere2moe pattern).
- [x] `hipfire-quantize`: support the LFM3 tensor-name layout
      (`model.*`, `post_operator_norm`, `gate_proj`, `model_type:"lfm3"` → 13).
- [x] `hipfire-loader`: `Lfm3Carrier` + `derive_arch_id` for `lfm3`→13 + `ModelState::Lfm3`.
- [x] `daemon.rs`: `arch_id == 13` generate branch (`generate_lfm3`) + warm-pass + `Lfm3Ar` route.
- [x] Validate against `LiquidAI/LFM3-1.7B` (greedy text, byte-check RoPE) —
      **done on gfx1151**. Quantized to Q8 HFQ (1.86 GB), loaded as arch_id 13,
      greedy generate produces coherent correct output (reasons to "Paris";
      RoPE partial-0.5 halfsplit confirmed correct — wrong convention → garbage).
      Fixes landed during bring-up: `flash_partials` scratch for the windowed
      attention dispatch, Jinja `{% generation %}` block strip (minijinja
      doesn't implement it), `loaded`-response arch/dim/layers/vocab arms,
      generate `attempt_id`, and a dropped empty stop-string guard.

### Phase 2 — Vision (LFM3-VL)  *[current — implementation complete, validation pending]*

- [x] `hipfire-arch-lfm3-vl` crate: vision tower forward (patchifier Linear
      1536→1024, axial-RoPE, spatial-merge-2, 14 hybrid conv/attention blocks)
      + `multi_modal_projector` (LayerNorm + GELU MLP). Mirrors
      `hipfire-arch-qwen35-vl`'s structure; arch_id stays 13 (vision detected
      by tensor presence, the qwen35-vl precedent).
- [x] `multi_modal_projector` (LayerNorm(1024) + GELU(erf) MLP 4096→4096→2048).
- [x] Image preprocessing — reused `hipfire_arch_qwen35_vl::image` verbatim
      (LFM3-VL's patchify is byte-identical: patch_size 16 / sms 2 / temporal 2 /
      `pixel/127.5-1` / merge-grouped `(C,T,ph,pw)` per-patch order).
- [x] Visual-token splicing into the LM context (`generate_lfm3_vl` in
      daemon.rs — `decode_step_with_embed` at `image_token_id` positions).
- [x] Axial RoPE: **reused** `rope_2d_halfsplit_f32` (dots.ocr quarter-repeat
      `[h,w,h,w]` layout == LFM3-VL's `cat([freq_hw,freq_hw])` recomposition,
      θ=1e6) + a new `build_axial_rope_tables` host builder. No new kernel
      needed — the 2D vision rotary already existed.
- [x] daemon HTTP `image` gating for arch_id 13 (`generate_lfm3_vl` route +
      `has_vl`/`vl` flag include `lfm3_vision_config`).
- [x] New kernels (beyond the plan's axial-RoPE item): `conv2d_gated_f32`
      (gated depthwise 2D conv — the main new primitive; hipfire had only 1D
      causal conv), `vit_attention_gqa_f32` (bidirectional GQA —
      `vit_attention_f32` was MHA-only), `gelu_erf_f32` (exact erf GELU for the
      projector; only `gelu_tanh_f32` existed).
- [x] Loader/quantizer wiring: `Lfm3Carrier` detects + loads vision;
      `LoadedModel.lfm3_vision_{config,weights}`; `derive_arch_id` +
      quantizer map `lfm3_vl`→13; `is_vision` covers `model.vision_tower.*` /
      `model.multi_modal_projector.*` (F16); LFM3 text loader is
      `model.language_model.*`-prefix-aware + `text_config`-envelope-aware.
- [ ] Validate against `LiquidAI/LFM3-VL-2B` (quantize to HFQ, load as
      arch_id 13, `serve_harness` image query — coherent image description).
      Correctness items to verify early: axial-RoPE cos/sin vs HF reference
      (the quarter-repeat reuse is structurally identical but θ=1e6 vs
      dots.ocr's 1e4 — confirm numerically), and the GQA bidirectional
      attention output.

### Phase 3 — Audio input (ASR / transcription)

- [ ] Mel-spectrogram front-end (new audio DSP — none in hipfire today).
- [ ] Audio encoder: conv2d downsampler + 17-layer LFM2 backbone (reuse Phase-1
      lfm2 conv/attn patterns; conv K=3, hidden 768).
- [ ] `Lfm3OmniEncoderStreamingCache` (bounded downsampler + causal encoder state).
- [ ] `audio_projector` (GELU MLP + LayerNorm).
- [ ] daemon HTTP `audio` input gating.

### Phase 4 — Audio output (TTS) + Omni generation

The largest and most novel chunk.

- [ ] Depth decoder: 3-layer **bidirectional** LFM3 + 12 codebook embeddings +
      `mask_embedding` + `depth_linear` + MaskGIT iterative scheduling
      (`maskgit_schedule [4,4,4]`).
- [ ] New kernel family: **bidirectional (non-causal) attention** — every
      existing hipfire arch is causal. Needs a full-mask flash variant.
- [ ] Liquid Codec (separate 147 MB `audio_tokenizer/` model): DAC-style
      codebook↔waveform encode/decode.
- [ ] Interleaved audio/text generation state machine in the daemon
      (`interleaved_n_audio=12`, `interleaved_n_text=6`; emit `<audio_out>`
      → depth decoder → codec → waveform).
- [ ] Streaming TTS path (`prefill_audio` / `transcribe_live` in the HF reference).

## Wiring (mechanical, applies to all phases)

- **arch_id 13** (next free; lfm2moe=11, cohere2moe=12). One crate may cover
  multiple runtime ids; the file/dir id on the loaded source is authoritative.
- **Carrier** `Lfm3Carrier` in `hipfire-loader`; `derive_arch_id` for
  `lfm3`/`lfm3_omni` → 13 in `safetensors_source.rs`.
- **Forward dispatch stays static** (not trait-routed) — per the existing
  convention (`daemon.rs` and examples call arch free functions directly).
- **Registry** entry in `registry/models.json` (→ generated `registry/v1.json`).
- **`admissions.yml`** is the sole product-admission owner; routing capability
  ≠ admission (see architecture-ids.md).

## Validation route (per docs/VALIDATION.md)

- Phase 1 (text generation/state-lifecycle): `scripts/serve_harness.py`
  (`battery` / `chain` / `session`) against `LFM3-1.7B`.
- Kernel/dispatch/graph changes: `scripts/redline_daemon_harness.py`
  (stable capture, AQL contracts, multi-position parity).
- Byte-parity claims: pin FP32 + `HIPFIRE_DETERMINISTIC=1` (Q8 state stochastic
  rounding makes exact TP/seam paths look non-bit-exact).
- Always eyeball decoded output; tight stddev on a bench is suspicious.
