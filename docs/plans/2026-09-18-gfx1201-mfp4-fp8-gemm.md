## 3. Format and AWQ contract

### 3.1 Weight meaning and rotation

Let `T` be identity for qt21 and the existing signed orthogonal FWHT-256 for qt24; let `s[k]` be the **stored, f16-rounded AWQ sidecar**, or1 for the plain control. Quantization follows the existing calibration helper's rounding convention, not independently recomputed higher-precision runtime scales:

- quantize `Wprepared = T(W * s)`; qt21 skips rotation entirely;
- runtime forms `xprepared = T(x / s)` before FP8 packing; qt21+AWQ still divides by s but must not call a rotating producer;
- `dot(T(W*s), T(x/s)) = dot(W,x)` in real arithmetic before quantization;
- qt24 reuses `fused_rmsnorm_mq_rotate_awq`, `rotate_x_mq_awq`, `fused_silu_mul_mq_rotate_awq` and their batch variants. For qt21, the matching RMSNorm/attention/SwiGLU producer must perform AWQ-only scaling; factor the shared arithmetic without executing FWHT. Missing AWQ-only production is an integration requirement, not permission to reuse a rotating helper;
- the GEMM and common FP8 packer see only prepared inputs. Neither knows or applies T. Below, `xrot` denotes that prepared input even when T is identity; this does not grant qt21 rotation.

For fused projections, one packed X may be shared only when their AWQ sidecars/rotation domain agree under the existing shared-input recipe. Pointer equality alone is insufficient; different sidecar values require separate preparation/groups. This matters for Q/K/V and the small beta/alpha matrices. The quant/runtime worker must preserve the MQ4V2 sidecar grouping contract rather than silently using the first tensor's scales.

For either wire target, the decoded weight in its prepared coordinate domain is

`Wq[r,k] = R[r] * 2^(e[r,floor(k/32)] - 127) * c[r,k]`,

where `R` is the **decoded serialized f16** row scale and `c` is an E2M1 value. Do not substitute the quantizer's pre-f16 `max_abs/6` in this identity. AWQ error, f16 row-scale rounding, and E2M1 quantization are already part of `Wq`; the new GEMM must not add weight-rounding error on its exact admitted path.

### 3.2 One compact GPU representation, no model-sized cache

Both qt21 and qt24 retain `[16-byte header][K/32 blocks of (e:u8, nibbles:[u8;16])]`, `16+17*(K/32)` bytes per row. Preserve header format_flags0/0x05 respectively.

Proposed **device-only** SoA row:

| Offset | Value |
|---|---|
| 0..1 | original f16 `R`, bit-preserved |
| 2..6 | original reserved row scale, block count and FWHT flags, bit-preserved |
| 7 | device-view revision 1; not written to HFQ |
| 8..9 | signed i16 row exponent `q` |
| 10..11 | exact-normal admission certificate/reserved bits |
| 12..15 | f32 `G = ldexp(float(R), q)`; no extra f16 round |
| 16..16+P-1 | original UE8M0 bytes, padding zero; `P=align_up(K/32,16)` |
| 16+P onward | nibble bytes in original K order, length K/2 |

Stride `16+P+K/2` is 16-byte aligned. For K=5120/6144/17408, P=160/192/544 and strides=2736/3280/9264, exactly the old byte counts. K=256 needs eight padding bytes; do not hardcode equality for every K. This view serves GEMV's contiguous 256-K nibble loads and GEMM's 8-byte per-K16 staging loads. Fragment order belongs in LDS, not in serialized weights.

Loader preflight verifies shape, qt21/qt24 identity and matching0/0x05 header flags, row count, finite `R`, exponent bytes, normal certificate and finite exact gain before publishing the corresponding `HFP4G32SOA`/`MFP4G32SOA` tensor. It computes extrema over **nonzero-code blocks**; all-zero blocks contribute no range and may have their device exponent normalized to the row maximum while preserving signed-zero codes. All-zero rows use `q=0`, `G=R`; zero R with nonzero codes is not certified. Reject e=255. The byte-permutation helper preserves flags; the loader checks them against the wire target and never changes transform provenance.

Gain admission requires the dyadic product of decoded f16 R and `2^q` to be exactly representable in f32, not merely nonzero after rounding. Likewise audit decoded weights for finite/exact reconstruction in the stated host reference; extreme underflow/overflow is rejected before the fast route. Completed offline scans each cover497 qt24 tensors and800,686,080 nonzero blocks: **plain e123..128, maximum within-row span5; AWQ e119..128, maximum span8; both have zero e=0/nonzero-code blocks**. Thus both satisfy the normal exponent-range condition (span<=11), not quality, gain representability or GPU arithmetic. Sources: `/home/kaden/ClaudeCode/warpfront/wt-mfp4/scratch-2026-09-17/mfp4quant/exp_scan_plain.txt` and `/home/kaden/ClaudeCode/warpfront/wt-mfp4/scratch-2026-09-17/mfp4quant/exp_scan_awq.txt`.

The qt21 plain/AWQ artifacts require their own exponent/gain scans; the qt24 scan does not certify them. Different transform domains can change the exponent distribution and quality while leaving the fold-free arithmetic unchanged.

The first FP8 route is deliberately **normal-only certified**, independently for each wire target/artifact. A failed tensor certificate causes explicit admission failure before installing the new model route (or selection of the entire existing AoS route before upload); never half-convert a fused group or partially write a residual. No silent lossy fallback. Not every legal qt21/qt24 row is assumed to fit.

The old generic GEMV constructs the f32 scale as `e << 23`, which maps e=0 to zero, while the format specifies `2^-127`. Scan and report e=0/nonzero-code blocks; do not silently resolve this pre-existing discrepancy in favor of a changed dequant result. Ordinary zero blocks are safe. A discovered nonzero case blocks an exact GEMV-parity claim until separately reconciled.

### 3.3 Row normalization and exact E4M3 rewrite

For a nonzero row let `emax = max(e)` over its nonzero blocks. Set

`q = emax - 127 - 6`, `d_b = e_b - 127 - q = e_b - emax + 6`.

Then the normalized operand is `w8 = c * 2^d_b`, and `G * w8 = Wq` in real arithmetic. The largest possible normalized weight is `6 * 2^6 = 384`, strictly below E4M3FN max 448. Thus no upper clipping and no NaN (`0x7f/0xff`) is needed. This is a row renormalization, **not** an arbitrary change of per-block scales.

E2M1 magnitude codes `0..7` map to E4M3 bytes:

`00 30 38 3c 40 44 48 4c` = `0, .5, 1, 1.5, 2, 3, 4, 6`.

The sign is `(code & 8) << 4`. For nonzero magnitude, write the mapped exponent `E` and mantissa `m`; `E` is 6..9 and `m` is 0 or 4. For `-5 <= d <= 6`, `1 <= E+d <= 15`; retain sign/mantissa and add `d` to the exponent, equivalently add `8*d` to the **magnitude byte**. Every result is exactly representable and normal. Zero bypasses the exponent addition, retaining its sign. Therefore the cheap certified condition is `emax-emin <= 11`.

Do not perform a packed signed addition on zero bytes: it can borrow/carry between byte lanes. A safe SWAR normal-path construction uses a positive sentinel for zero in the magnitude LUT, performs the exponent adjustment while every byte stays in [0x08,0x7c], then clears zero magnitudes and restores sign. Any shorter packed rewrite requires exhaustive byte-lane proof.

### 3.4 Edges: exactness is conditional, not an fp8 magic trick

- For `d=-8,-7,-6`, exact E4M3 subnormals are also possible for **every** E2M1 code. Let `j=E+d`. If `j<=0`, emit `mant_sub=(8+m) >> (1-j)` with exponent zero. Divisibility is exact for this restricted codebook/range. If `j>=1`, use the ordinary exponent rewrite. Smallest value is `.5*2^-8=2^-9`, the smallest E4M3 subnormal. This extends the mathematical row-span bound to 14, but a device probe must verify WMMA subnormal handling before admitting this optional edge path. It is not included in the first normal-path packet budget.
- At `d=-9`, `.5*2^-9=2^-10` is exactly halfway between zero and the minimum subnormal; RNE gives zero, hence bit rewriting is no longer exact. For RNE underflow with no upper overflow, normalized absolute error is at most `2^-10`; reconstructed weight error is at most `abs(G)*2^-10`. A dot error is bounded by `sum_k abs(x[k])*abs(deltaW[k])`. This lossy path is **not admitted** by the first implementation.
- At `d=7`, code 6 becomes 768, above 448. The chosen q prevents this; a smaller q is invalid, not an invitation to silently saturate.
- UE8M0 e=255, nonfinite headers, nonfinite G, and impossible row-normalization ranges fail preflight. Zero rows do not use log2(0).
- Float32 multiplication/accumulation and the changed summation order still round. “Exact” applies to **weight operand decoding**, not bit identity with an f16-WMMA or GEMV dot product.

A CPU rational-arithmetic check executed for this plan covers all 16 codes × 15 shifts [-8,6] (240 cases), including signed zero encoding and the underflow/overflow counterexamples. Evidence: `/home/kaden/ClaudeCode/warpfront/wt-mfp4/scratch-2026-09-17/Mfp4Fp8Plan/exactness-arithmetic.json`. This is mathematical/CPU evidence only, not an on-device codec result.

### 3.5 Activation scale and epilogue

Reuse the MQ4V2 F32-input, whole-K dyadic-224 rule:

`a[t] = 2^clamp(ceil(log2(max(abs(xrot[t,:]))/224)), -31, 9)`, zero row → 1;
`x8[t,k] = RNE_E4M3FN(xrot[t,k] / a[t])`.

Keep the clamp for parity with the existing prelude, but count saturated/underflowed activations in oracle evidence. Values above the clamped representable range do not have an exactness guarantee. For nonsaturated normal values the usual RNE relative bound is at most 1/16; subnormal absolute error is at most `a[t]*2^-10`. For large clamped values, use the actual measured `xhat=a*decode(x8)` difference, not that bound.

One full-K f32 accumulator `C[t,r]=sum_k decode(w8[r,k])*decode(x8[t,k])` survives all slabs. Drain performs, in a specified two-multiply f32 order, `v = (C * G[r]) * a[t]`; gate_up/QKV/QKVZA overwrite their routed output; residual reads `Y_old` once and stores `Y_old+v` once. Do not move R into per-block partials or apply a twice. With power-of-two a, the scale operation is exact when finite and not underflowing, but do not assume that for arbitrary fixtures. Record compiler contraction/rounding policy in the oracle.

## 4. Staging, ownership, and instruction contract

### 4.1 Mapping

Use BM=128 tokens, BN=128 weight rows, BK=64, 256 threads. Wave tile is 64 tokens × 32 rows: 4 token fragments × 2 row fragments, 8 independent WMMA accumulator chains, 64 f32 accumulator VGPRs/lane.

Producer lane: `quad=tid&3`, `row=(tid>>2)+64*round`, rounds 0,1 for each plane. It stages one K16 segment per round. For slab `k0` (multiple 64), scale index is `(k0+16*quad)/32`; quads 0/1 share block 0 and quads 2/3 share block 1. Each producer owns two consecutive 8-code packs from the aligned nibble plane. Load the block exponent once per producer's 16 elements, expand both packs **once**, and publish the resulting bytes into LDS. The repeated exponent read by the adjacent quad is bounded duplication, not a per-WMMA scale load.

Fragment address for row r, K16 step ks, half pp:

`F=((r>>4)*4+ks)`, `slot=F*288+(r&15)*8+pp*128`.

Each 16×16 fragment has 256 useful bytes and 32 padding bytes. Its two K8 halves occupy lanes 0..15 and 16..31. All K16 step addresses in the four-step compute bundle are compile-time immediate offsets from loop-invariant per-wave pointers. A per-32 scale boundary is **between** K16 steps 1 and 2, never inside either K8 half or a K16 fragment. Different rows may use different scales because each row's staged operand already includes its own exponent. No common block-scale broadcast into C is necessary.

Each element is expanded once **per workgroup slab**, not once for the entire model: separate token tiles reread the weights. Claim that distinction explicitly.

To realize the paired LDS-read packet target, precompute **two A bases** (token-fragment pairs0/1 and2/3) and one W base. Within each pair the largest b64 immediate is `(1152+3*288)/8=252`, fitting the two-address8bit offset field. Do not let the compiler synthesize the second A base inside the compute bundle; a single A base for all four fragments would exceed that paired-immediate range.

### 4.2 Transitions and invariants

| Transition | Owner / invariant before | Invariant after |
|---|---|---|
| Artifact → loaded view | Model loader owns immutable qt21/qt24 bytes and AWQ sidecars; no published SoA tensor | Validated upload has one owner and unchanged transform tag; host bytes may be released; no second GPU copy. Failure publishes nothing. |
| Input → AWQ/optional FWHT | Existing scratch owns raw normalized/attention/SwiGLU input and target transform tag | `xrot=T(x/s)` in F32 with sidecar identity; T is identity for HFP4 and FWHT for MFP4. GEMM never transforms again. |
| xrot → x8 | Gpu-owned scratch, eager; old prepared views are not reusable by pointer identity | Fresh `[N,K]` FP8 bytes + `[N]` f32 scales produced on the same stream. Prepare always overwrites; borrowed pointers valid only until next prepare/growth/teardown. |
| Slab load → publish | LDS buffer is free; optional next-slab raw globals live in registers only | Exactly one writer per live operand byte; masked A/W rows publish zeros; all waves pass publish barrier before reads. |
| Compute → reuse | Every wave may still read current LDS | All-wave read-completion barrier precedes any overwrite. Then publish next slab and barrier again. Never drop the former barrier: v2 already found this race. |
| K16 compute | W and A bytes final, pointers fixed; C is partial full-K sum | Only WMMA modifies C; no P bank, no per-half reset, no scale/zero VALU; next K16 advances via immediates. |
| Last slab → drain | Last LDS readers finished; C owns complete sums | A/W LDS may be aliased by the existing row-skewed store-transpose tile; row gain can be loaded late because it is immutable. |
| Drain → output | Each destination has unique WG/lane owner; residual initialization happened upstream | Overwrite projections written once; residual added once; masked tails untouched. No atomics, no split-K, no recurrent/KV mutation. |

Single-buffer LDS and register prefetch are sufficient. Two complete LDS buffers would use 36,864 bytes and break the conservative 32 KiB/WG residency budget. Keep prefetch raw (8 A + 4 W + 2 exponent VGPRs/lane at this geometry), expand at publish, and retain scheduling fences if removing them hoists register lifetimes. No global/prelude allocations inside the K loop.

### 4.3 Packet census: units matter

“Packet” below means one **wave-issued ISA instruction**, not one lane operation, one byte transaction, or a wall-time fraction. `_2addr_b64` carries two logical b64 operations in one packet. Counts exclude fixed prologue/drain and separately list scalar waits/control. Logical targets are not compiled results.

For one 128×128×64 WG tile, 8 waves:

Useful raw weight bytes are 4096 payload + 256 scale bytes per tile; duplicated exponent lane requests are not 256 unique memory transactions.

A safe scalar-operation-count normal expander, before VOP3/VOPD fusion, has this target budget per eight-code dword:

- split even/odd nibbles and gather consecutive byte lanes: 5 VALU;
- for each four-code half: magnitude mask (1), one register `v_perm` LUT (1), sign mask/shift (2), zero mask add/and/shift/multiply (4), exponent add and zero-mask (2), sign OR (1): 11 × 2;
- total **27 logical VALU operations**, plus exponent-delta subtraction/replication once per producer's K16 segment.

The reusable uniform MQ4 `mq4_qpk_to_e4m3` expression has about 19 logical operations per eight-code dword before compiler fusion. Thus do **not** call qt24 expansion free: proposed budget is `4*27+2*2=112` logical VALU/wave/BK64 versus `4*19=76` for that MQ4 expression. Zero/sign/exponent instructions are paid at staging, never per consumer WMMA. A native conversion/shorter SWAR idiom may replace this only after byte-exact exhaustive comparison and load-fed timing; it is not necessary for functional implementation.

**Inner compute target per K16 / wave:** 8 WMMA, 6 logical b64 LDS reads (=3 two-address packets when encodable), 1–2 DS waits; **0 VALU, 0 global loads, 0 conversions, 0 fold reads**. Per BK64: 32 WMMA + 24 logical LDS reads (12 paired packets) + 4–8 DS waits. Scalar loop/publish control remains outside this straight-line bundle. ### 5.1 Primary 128×128 / 8 waves

- C accumulators: 64 VGPR (old T+P cost 128).
- streamed A/W operand window: 8–12 VGPR, not all K16 operands held together.
- next-slab raw prefetch: 14 VGPR (A 8, W 4, exponents 2).
- row pointers/q, stage/read offsets, masks, index/routing and temporaries: target at most 38 combined, with dead-range reuse between expand/compute/drain.
- **Hard compiled allocation ceiling: 128 VGPR**, no scratch/spills, preferably used count <=120 for allocation granules. QKVZA must meet the same gate, not inherit gate_up's occupancy claim.
- A LDS 9216 + W LDS 9216 = **18,432 bytes**. Store transpose uses 16,384 aliased bytes. No S/SZ planes. Two WGs use 36,864 bytes, below the conservative 64 KiB pool.
- 512/128 = 4 waves/SIMD; 4 SIMDs/WGP ×4 =16 waves = **2 eight-wave WGs/WGP**, i.e. one WG/physical-CU on average. This doubles the old two-wave/SIMD cover, but is **not two WGs per physical CU**.

### 5.2 Literal two-WG/physical-CU option, bounded control

Two eight-wave WGs per physical CU means eight waves/SIMD, requiring **allocated VGPR <=64**. A 128×128 tile already needs 64 C registers, so that target is impossible without spills/recomputation and is rejected.

The only admitted smaller control is **64 tokens ×128 rows ×64 K, still 8 waves**, wave tile 32×32, four accumulator chains / 32 VGPR. Budget: 32 C +8 operand +4 A-prefetch +4 W-prefetch +2 exponent +14 addressing/expand =64; if real codegen exceeds64, it does not satisfy the claimed residency. LDS operands 4608+9216=13,824 bytes; retain a 16,384-byte aliased drain budget. Four WGs/WGP use64KiB at that conservative budget and 32 waves/WGP. No claim of better speed: per-WMMA staging pressure and repeated W traffic increase, and four chains may lose instruction-level latency cover. Test it only after the primary's resource census, keep it only on same-session five-row TIME wins. No tile sweep or 256×128 speculation in this slice.
