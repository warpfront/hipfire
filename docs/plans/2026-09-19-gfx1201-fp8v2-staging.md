# gfx1201 MQ4V2 FP8-v2: make the prefetch real, then cross the half boundary

## Decision and scope

**Recommend a small exact raw-prefetch cut first, followed by a gated two-slab register lookahead across 128-K boundaries. Do not start with LDS double buffering, split-K, another occupancy geometry, or W-stationary doubling of the token tile.** The current source issues the next slab's loads early, but the shipped ISA immediately waits for them to perform OOB zero-selection **before issuing the current slab's first WMMA**. Moving those selections to publication removes that dependency and measured about 4% from the actual kernel body. This is not evidence for a 20–30% staging win.

This is a plan, not a production implementation. Production source is untouched. Scratch-only probes and ablations are not shippable kernels or numerical acceptance receipts.

### 2.1 The decisive dependency

In `E/gu_shipped.s:407-426` the next slab loads are:

1. two `global_load_b128` A loads and two `global_load_b64` W loads;
2. `s_wait_loadcnt 3`, eight A `v_cndmask` operations, further waits;
3. `s_wait_loadcnt 1/0`, four W `v_cndmask` operations;
4. only then the current slab's LDS operands and first WMMA.

Thus the source comment at K:569-575 overstates the actual overlap. It is not enough to move a C++ load above compute. The first dependent mask has already consumed the future data.

In scratch `E/gu_rawpref.s:407-444`, the same four future loads precede current WMMA **without any intervening load-counter wait**. Selections occur after compute, before LDS publication. An opaque, register-only identity at that consumption point prevents optimization from hoisting them back. This diagnostic preserves the current valid-address clamps; it does not issue an invalid masked load.

### 2.3 Bytes, barriers, and duplication

For one workgroup and one BK64 slab, there are 256 wave-level WMMAs, 2,097,152 floating-point operations:

- Global A: 8192 B. Global packed W: 4096 B. The half's metadata adds 1024 B of S loads and 1024 B of header loads once per two slabs; both include duplicated producer loads.
- LDS A/W planes: 9216 B each including padding. S: 512 B; SZ: 1024 B. Total **19968 B**. The 16-KiB output transpose reuses these dead planes.
- Compute A reads: 32768 lane-requested B/slab = **128 B/WMMA**. Each A fragment feeds two W fragments, but four weight partitions reread A from LDS.
- Compute W reads: 16384 lane-requested B/slab = **64 B/WMMA**. Four token fragments reuse a loaded W operand; the two token partitions reread it.
- Total compute operand read requests: **192 B/WMMA**, not 512 B/WMMA. Eliminating global A duplication is not the same as eliminating this LDS traffic.
- Per half/WG global requests: 26624 B = 52 B/WMMA. Physical producer LDS stores: 34816 B = 68 B/WMMA, including duplicate S stores. Fold lane-requested reads add 72 B/WMMA; broadcasts mean that is not 72 B of distinct bank traffic.
- Barriers: prologue-ready; slab0-readers-done; slab1-ready; slab1/fold-done = **four workgroup barriers per half, two/slab**, plus eight output-transpose barriers. Gate K5120: 168 dynamic barriers/WG; residual K17408: 552.

Example gate_up N512 global A requests are 713 MB: each 128-weight-row tile rereads the same A. This is a request-byte budget, not a measured DRAM-byte count; cache reuse matters. A staging-only change cannot claim to remove those bytes. The new pipeline keeps the bytes and arithmetic unchanged and changes the dependency lifetime.

## 4. Pipeline contract

### 4.1 R1: late-consumed raw values, one-slab lookahead

Change only K's v2 prefetch/publication sites:

1. Retain all existing clamped global addresses and valid-row predicates.
2. `A_pf` and `Wpk_pf` hold **raw loaded bits**, not masked values.
3. Current slab's LDS reads and WMMAs complete without consuming those raw future registers.
4. At the publication boundary, constrain raw-register consumption so the optimizer cannot hoist its zero-selections before compute. The scratch diagnostic uses an opaque register-only identity; use the smallest compiler-supported equivalent whose emitted dependency is verified. No memory clobber or device/global fence.
5. Keep the readers-done workgroup barrier; apply A/W valid-row masks and nibble expansion only when publishing the next slab; retain the ready barrier.
6. Keep P reset, WMMA sequence, fold order, source routing, transpose drain, `at*T`, and residual addition byte-for-byte arithmetically unchanged.

The scheduling identity has no arithmetic or memory effect. Treat absence of premature waits in emitted ISA as an acceptance condition, not a permanent compiler assumption. Do not replace workgroup barriers with scheduling barriers.

### 4.2 R2: cross-half raw-register ring, depth two

Only after R1 passes exactness and timing gates, replace the repeatedly cold half prologue for the default geometry with a statically phased register ring. Define lookahead depth D as **D future BK64 slabs held in registers, in addition to the current slab in LDS**.

For linear slab q:

- activation offset = `64*q`;
- group `g=q>>2`, half `h=(q>>1)&1`, in-half slab `q&1`;
- packed-W base = `136*g + 8 + 64*h + 32*(q&1)`;
- S index = `st_soff + (q>>1)`; header offset = `136*g + 4*h`.

Use two statically indexed raw slots. Prime current LDS q0 and future raw q1/q2, with finite-K guards. Replenish the consumed ring slot with q+2 while the current LDS slab computes. Carry the next half's raw S/header words alongside its first slab so the next even slab does not restart with blocking metadata global loads. Decode/mask metadata only when its owning half is published.

Prefer a four-phase unrolled body inside the 256-K group loop: phase index determines ring slot at compile time. **No variable-index VGPR arrays, scratch-backed queues, modulo address VALU in each WMMA step, or general-purpose staging abstraction.** Phase 2/3 lookahead may address group g+1 only under `g+1<gpr`; do not clamp an out-of-range K prefetch and accidentally consume it.

This changes load lifetime, not K arithmetic order. P still resets at the first K16 of each even q, accumulates the eight K16 steps in their original order, and folds once after odd q. Every output's T still receives `fma(s_h,P,T)` followed by `fma(z_h,S_h,T)` in increasing `(g,h)` order.

R2 is not measured in this planning pass. Its admission depends on recovering at least another 2% over R1; deeper lookahead is not a presumed free win.

### 4.3 State ownership and transition invariants

| Transition | Before | Required action | After |
|---|---|---|---|
| prepared activation → launch | `Gpu` scratch owns X8/S/row-scale buffers; prepared `(n,k)` validated; eager guards passed | no new allocation/preparation; existing stream ordering | inputs remain immutable for this launch; no pointer retained beyond existing prepared lifetime |
| EMPTY → RAW_PENDING slot(q) | slot is no longer consumed by any publication | issue only valid clamped row loads and in-range K loads | slot belongs to q; values may be outstanding, cannot yet drive masks/stores |
| RAW_PENDING + COMPUTING(current) | current A/W/S/SZ are stable in LDS | current WMMAs use LDS, not future raw registers | future VMEM may complete during compute; no future `loadcnt` consumer before useful WMMA |
| current read/fold → LDS_FREE | all waves may still be reading current A/W; at odd q metadata participates in fold | finish each wave's current reads and exact fold, then workgroup readers-done barrier | all A/W readers done; S/SZ become free only when the old half's fold is done |
| RAW_READY(next) → PUBLISHED(next) | single A/W LDS buffer is free; next raw bits available | wait as needed, mask, expand W, publish A/W; publish S/SZ only on an even slab | LDS contains precisely next slab and its half metadata; no concurrent old-reader access |
| PUBLISHED → COMPUTING | producer stores may be outstanding | workgroup ready barrier | every consumer sees complete A/W/S/SZ for the same logical half |
| odd slab → T folded | P covers exactly 128 K; old T contains preceding halves | ordered two-FMA fold, no reassociation/reduction | T contains exactly this half; P can be reset for the next half |
| final fold → output transpose | no K reader/writer or prefetched value remains live | complete terminal synchronization, alias LDS for existing 16-KiB transpose | each valid output stored once; residual reads/adds prior Y once; invalid rows/tokens untouched |

No transaction is added to recurrent state or KV state. Failure before launch follows existing errors; a failed launch does not trigger a new fallback after outputs may have been written. The existing prepare function's scratch-growth invalidation and capture/replay rejection stay intact.

### 4.4 Register, LDS, occupancy, and packet admission

R1 has the measured/compiled register counts in §2.2. R2's **engineering budgets, not measured allocations**, are:

| Family | R1 VGPR | Additional budget | R2 cap | LDS / scratch |
|---|---:|---:|---:|---:|
| gate_up | 192 | 12 raw slab + 4 metadata + 4 control | 212 | 19968 / 0 B |
| residual | 204 | same | 224 | 19968 / 0 B |
| qkv | 212 | same | 232 | 19968 / 0 B |
| qkvza | 213 | same | 233 | 19968 / 0 B |

A raw slab is eight A dwords + four packed-W dwords = 12 VGPR/lane. Keep the universal hard cap **240 VGPR**, no VGPR or SGPR spills, no private segment. Do not spend the remaining headroom on larger output accumulators. Preserve the task's established effective occupancy class (two workgroups/WGP); do not re-open the slower ≤128-VGPR geometry.

`E/occupancy.txt` is explicitly an **API upper-bound diagnostic**, not an achieved-residency measurement: this runtime reports 32 MPs, 65536 shared bytes/MP and three possible 256-thread blocks for these 19968-B kernels; 38400 or 56832 B reduces that answer to one. That does not override the supplied two-WG/WGP effective measurement. It does establish that two full A/W LDS buffers are not “free” in the current API's LDS accounting. Preserve measured runtime performance rather than treating compiler occupancy comments or the API answer as a throughput oracle.

Two LDS A/W buffers plus shared metadata need **38400 B**; three need **56832 B**. Duplicating metadata too raises them further. Reject both as the primary design. R2 stays single-LDS-buffered and keeps two barriers/slab; it does not bank on removing synchronization. Dynamic memory bytes, 64 WMMAs/half, 128 FMA operations/half, and output operations remain unchanged. Target no more than +16 dynamic VALU packets per half for ring bookkeeping and `.text` growth ≤25%; excess bookkeeping that consumes the recovered window fails admission.

Depth three would add another 12 raw VGPR plus metadata/control. It is a scratch-only contingency: qkv/qkvza approach/exceed the 240 cap. It must beat depth two by ≥1.5% on same-session medians without a family regression. Otherwise abandon, rather than retaining a tuning switch.
