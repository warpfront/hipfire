## 4. Q tile and KT decisions, with honest units

**The existing kernel is not a 64-token Q tile.** Four wave32s allocate four16-row WMMA slots, but only three slots compute:48 live query-head rows = eight token positions x six heads. Merely duplicating its ownership gives96 live rows in a padded Q128 block. The packet-minimal candidate instead removes helper-only roles: enumerate `(query,head_local)` densely, so **Q64/Q128/Q256 below mean64/128/256 actual query-head rows**. GQA does not require every WG boundary to fall between tokens; a token's different heads can be owned by adjacent WGs sharing the same KV head. Literal token tiles of64/128/256 would require384/768/1536 live rows and at least24/48/96 compute waves, not the geometries below.

| Capacity | Threads / compute waves | Live rows / token positions touched | Same-total-current-fill cost / live row | KV code bytes / live row / KT64 | Candidate fill target / live row |
|---|---|---|---:|---:|---:|
|Current padded Q64|128 /3|48 /8|4736/48 =98.67 packets|682.67 B|not a candidate|
|Dense Q64|128 /4|64 /11–12|74.00|512 B|40.00 packets|
|**Dense Q128**|**256 /8**|**128 /22**|**37.00**|**256 B**|**20.00**|
|Dense Q256|512 /16|256 /43–44|18.50|128 B|10.00|

`4736=4*(204+980)` is measured ISA fill work; spreading it unchanged over different block shapes is an **ideal amortization model**, not their compiled work. Bounds, shorter fill loops, transpose and scale publication have different costs. Candidate2560 is an inclusive unmeasured WG-fill ceiling. Add256 unique header bytes/WG/KT64: total unique native payload33024 bytes, hence516/258/129 bytes per dense Q64/Q128/Q256 live row. Cache-line/DRAM traffic can exceed these unique-byte budgets; the global row remains1032 bytes. Retaining the old3:1 role pattern would instead charge49.33/24.67 current-fill packets per live row for padded Q128/Q256, so dropping helper-only roles is separately accounted for, not hidden in a tile-name change.

Two O tiles in one wave are rejected: one D256 fp32 output already needs128 VGPR/lane; two need256 **before** scores, Q, m/l/b, pointers or P. Serializing two blocks by spilling O to LDS/global defeats the register-resident packet goal. Instead Q128 uses eight waves with **one** O tile each; every wave fills and computes. Head/query divmod6 is a one-time ownership calculation, not arithmetic inside the KT loop. There is no register donation.

At batch64/512 and four KV heads, old grid has32/256 WGs; dense Q64 has24/192, Q128 has12/96, Q256 has8/48. Small-batch underfill is a serious veto risk: eight waves concentrated on fewer scheduling units need not match the old distribution of three compute waves per WG. Do not add an unmeasured small-batch dispatch heuristic to conceal this; the frozen candidate must pass the existing admitted-row gate or be abandoned. The512-thread floor is nearly twice the256-thread floor for twice the math, not a per-row math win. Q256 is separately gated; after optimized fill its incremental modeled8K advantage is only about1.9 us/token at c=4 with the same reserve.

### Real LDS budget and why KT128 is not selected

For native fp8 at D256: K = `KT*256` bytes, V = `KT*256` bytes. Thus KT64 payload is32768 bytes; **KT128 payload alone is65536**, leaving zero bytes for scales or transpose scratch. Candidate layout:

| Half-open interval | Size | Owner/lifetime |
|---|---:|---|
|0..16384|16384|paired K fragments, immutable from publication through turnover|
|16384..32768|16384|paired V fragments, same lifetime|
|32768..49152|16384|eight private2KiB raw-V transpose scratch regions; each owned by one wave|
|49152..49280|128|64 native f16 K scales|
|49280..49408|128|64 native f16 V scales|

Static LDS0, dynamic **49408**; query actual allocation granularity/resources rather than assuming byte precision. KT128 with the same scratch plus128 K/V scales would need **82432 bytes**, illegal under64KiB. A legal64KiB KT128 variant could alias raw-V staging with K and keep headers direct, but would require phased cross-wave barriers before overwriting raw V, lose shared-scale savings, and retain all eight ordered KT16 recurrences. It saves only tile-loop/barrier amortization, not half the softmax/rescale work. Reject it unless a standalone equal-work measurement beats the admitted KT64 kernel by >=5%; no such measurement exists here. A smaller two-pass scratch reduces bytes but adds wave sync and does not regain two-WG residency, so it is not the packet-minimal starting point.

KT (storage) and online-softmax update size are different knobs. Combining KT16 updates into KT64/128 would change max/sum rounding and fp8 P block quantization. It is **inexact**, not a free benefit of a larger K/V tile, and is excluded.

## 5. Frozen minimum-packet candidate

### Geometry, paired fragments, and fill

For wave `w=0..7` and lane `16*kg+ml`, **all waves compute**:

```
row_base = 128*blockIdx.x
row = row_base + 16*w + ml
query = row / 6
head = 6*kv_h + row % 6
qok = row < 6*batch_size
```

This bijection gives each `(query,head_local)` one owner, duplicated only across the two kg halves for disjoint output dimensions. The body-local old `q_base` parameter becomes `row_base`; public kernargs are unchanged. Grid is `[ceil(batch_size*6/128),4,1]`, block256. Bounds cover `qlo=row_base/6` through `qhi=min((row_base+127)/6,batch_size-1)`; at most22 positions, so every wave loads the same guarded prefix through its lanes0..21 and performs the same min/max reduction. Invalid query lanes clamp immutable Q reads to row0 as today and retain fully masked scores. A full tile requires `row_base+127 < 6*batch_size` as well as the key bound. Partial split units/output records remain unchanged.

For `sub=0..3`, paired dimension `p=0..7`, lane0..31, use **local route-N-only** byte offsets:

```
Kpair = ((p*4+sub)*32+lane)*16
Vpair = ((sub*8+p)*32+lane)*16
pair bytes 0..7   = current fragment(dc=2*p)
pair bytes 8..15  = current fragment(dc=2*p+1)
```

One aligned `ds_load_b128` now supplies two fp8 WMMA operands. Preserve dc order in each QK chain and output updates. K packet count remains32/KT64, because current K already pairs two b64 loads; V drops from64 to32. Do not accidentally issue one b128 **per**8-byte operand. Keep only a bounded operand pair live, not a64-address table. K global rows are only8-byte aligned on odd tokens (`1032 mod16=8`): load through a legal8-byte-aligned representation or memcpy lowering, never strengthen alignment with a16-byte cast. Paired LDS stores are16-byte aligned.

All eight waves fill their share of K. Wave w owns raw V keys `ktile+8*w .. +7`, its private scratch at `32768+2048*w`, and final V fragments for `sub=w>>1, kg=w&1`. Vector-stage those eight256-byte native rows, zeroing OOR rows without reading them. In scratch dword units use `S(k,word)=(k*64+word)^((k&3)*8)`; it is a bijection preserving each16-byte store. A convergent wave synchronization publishes every lane's stores before transpose reads.

For a dimension dc and output ml, set `r=ml&3`, `dq=ml>>2`. Read scratch dwords for keys r and r+4 at word `dc*4+dq`. For each dword, xor1 exchange then packed byte selection `[0,4,2,6]` for even r / `[5,1,7,3]` for odd r; xor2 exchange then `[0,1,4,5]` for r<2 / `[6,7,2,3]` otherwise. Concatenate the two transposed dwords. Do this for the paired dc values and issue one b128 V store. For each wave, `p=2*t+(lane>>4)`, t0..3, covers all pairs; xor1/xor2 stay within the four-lane transpose groups. Prefer the existing constant DPP xor1/xor2 idiom, not generic variable lane-address shuffles. There are **no global byte gathers, fp8 decode/reencode, or cache writes** in this fill.

Threads0..63 copy the two native f16 scale headers for their key into sk/sv; other waves do not duplicate header loads. Each consumer loads the eight owned keys' scales as one aligned16-byte LDS vector per cache/KT16, then performs the same f16->f32 conversions in the current scale register file. Key ownership is `sub*16+8*kg+j`, never K supplier row ml. Scale storage is WG-local, not a new global format or persistent allocation. Zero OOR scales exactly as today.

`python3 R/layout_contract.py` executed PASS: all16384 bytes of each paired K/V plane are bijective; every scratch word and packed-transpose key/dimension label is correct; regions are disjoint and total49408. Dense row ownership and min/max position coverage pass for every batch1..512, including heads straddling WG boundaries. This is **host address/label proof only**. Device byte equality, tail reads, LDS banks and timing remain the transpose gate. Fragment-order/swizzle does not itself prove bank throughput.

### Arithmetic and packet scheduling

1. Hold the sixteen two-dword Q fragments and sq-derived qs resident once per consumer, rather than reloading Q64 times/KT64. Retain compile-time fragment indices; dynamic private-array indexing/spills fail admission. Extra32 Q registers are explicitly charged.
2. Hoist one full-tile predicate: `all_query_rows_valid && ktile+63<=gmin`. On that path all K/V/header keys are valid and every score is unmasked; eliminate per-key guards, mask diamonds and redundant global positions/header loads. This is a proven range branch, not an input-specific approximation. The edge path retains current guarded load/zero/mask semantics and identical update order, including nonmonotone/duplicate positions.
3. Preserve the existing16-wide row reduction: eight values reside in each lane and only the xor16 partner is remote. Current max already lowers largely to `v_max3`; it does **not** perform a five-step16-lane DPP tree. Use one fixed `permlanex16` per max, sum and weighted max: **three exchanges/KT16**, rather than `ds_bpermute` plus LDS-counter dependence. Preserve the serial sum association; a balanced sum tree is a numerical change.
4. P-pack is already four `cvt_pk_fp8`/KT16, packed once outside PV. No conversion-count saving is available. Keep the true divisions and their exceptional-value behavior. Simplify unnecessary pack passthrough moves only if emitted ISA and exact output prove it; budget **zero** saving from this speculation.
5. Preserve128 rescale multiplications/KT16. Schedule independent pairs to permit VOPD; do not change rho association or absorb rescaling into a differently rounded WMMA. Minimum ideal rescale issue count is64 VOPD packets, not zero.
6. Bound K/V operand loading to one/two paired fragments and schedule the matching WMMAs after the actual dependency. Paired V loads can save32 loads and roughly32 waits/KT64. Current memory-clobber asm does not prevent all load hoisting: shipped PV hoists sixteen b64 loads despite its source comments. Source loops are not evidence of bounded live ranges; ISA and register counts decide.
7. Keep the compiler hazard scheduler's `s_delay_alu` and wait correctness. Scheduling independent scalar/WMMA/loads can reduce emitted waits; **never delete required wait/delay instructions to meet a packet number**. A `s_wait_dscnt` is not a VGPR WMMA dependency fence, and barrier rendezvous is not memory completion. Charge the compiler's actual global invalidations if wave/WG fences retain them.

Two full-WG barriers per KT64 remain: after all K/V/scale publication and after all consumer reads. Wave-private transpose adds one wave publication synchronization. Removing either full-WG barrier without an ownership replacement is wrong. The four existing barrier instructions are tiny in packet count; the unmeasured stall cost is not zero, but replacing them with atomics/polling would buy complexity, not an established count reduction. No FA3 ring, named subset barrier, producer ping-pong or co-execution assumption enters this design.

## 6. State ownership and every transition

| Transition | Before | After / invariant |
|---|---|---|
|Dispatch/preconvert|Caller owns immutable Q, positions and committed readable KV prefix; scratch owner is Gpu|Existing same-stream preconvert writes only code-Q/sq scratch. Growth invalidates stale graph/blob pointers before allocation. No additional persistent allocation.|
|WG initialization|No invocation-local state escapes|Each of eight waves owns one O tile; Ofr=0,m=-inf,l=0,bprev=1. Dense row mapping is bijective, bounds agree across every wave, and tile/split limits are finite.|
|Acquire tile storage|First tile unused, or previous full-WG turnover completed|Every previous K/V/scale read finished before any overwrite. Eight scratch regions have unique wave owners.|
|Stage raw inputs|Each wave owns disjoint K destinations/raw scratch; scale writers own disjoint native halfwords|Global loads valid or guarded to zero. No cache mutation. Wave sync completes all scratch writes before any cross-lane scratch read.|
|Transpose/publication|Each wave reads only its completed private raw scratch and writes disjoint paired V fragments|First WG barrier publishes complete K/V/sk/sv. Consumers may now read immutable payload; no wave can reuse it early.|
|QK|Resident Q, current slot and owned-key scales valid|Ordered dc0..15 QK accumulation; score expression `(sacc*qs)*sk` unchanged. Only one score tile live.|
|Softmax/PV|This wave alone owns prior m/l/b/O; four KT16 updates in increasing key order|Same recurrence below. Fixed partner exchange changes transport only. No update from another query/wave is combined.|
|Turnover|All eight waves completed every PV/scale read; invalid query lanes still participate|Second WG barrier releases K/V/sk/sv and raw scratch for next tile. No wave can run ahead and overwrite.|
|Direct/partial completion|Final O unit and denominator belong to query owner|Direct stores existing normalization expression; partial writes physical numerator and unchanged258-float record. No retained LDS/flags.|
|Graph/replay/reuse|Captured inputs/scratch allocations remain live; committed positions identify readable KV|Each invocation initializes local state anew. Repeated launches neither mutate Q/KV/positions nor retain m/l/O. Scratch growth invalidation and upstream transaction ownership remain unchanged.|

Exact per-KT16 invariant and arithmetic graph:

```
score = (qk_acc * (sq*scale_attn)) * sk
mask -> mx -> m_new
alpha = m_old == -inf ? 0 : exp(m_old-m_new)
e = m_new == -inf ? 0 : exp(score-m_new)
l = l*alpha + ordered_sum(e)                  # never V-scale weighted
w = e*sv
b_new = wmax>0 ? max(wmax/448,2^-64) : b_prev
p8 = E4M3_RNE(w/b_new)
rho = (alpha*b_prev)/b_new
Ofr = rho*Ofr; Ofr = WMMA(V8,p8,Ofr)
b_prev = b_new                               # physical numerator = b_prev*Ofr
```

Keep exp intrinsic, rounding/FTZ policy, current FMA contraction, sum order, all-masked behavior and zero-weight bprev retention. Direct remains `Ofr*(bprev*(l>0 ? 1/l : 0))`; partial remains physical `bprev*Ofr` plus m/l, then unchanged merge. Compare same split partitions, not differently associated direct versus split results. `K:1582-1587` partitions in KT64 units and stays so. Empty splits store m=-inf,l=0,O=0 without a divergent barrier or invalid read.
