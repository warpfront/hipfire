## 2. Exact mathematics, rounding contracts and range proofs

For output row r, token n, group g, half h in {0,1}, let

- `A_h = sum_128(qW*qX)`, `S_h = sum_128(qX)`;
- `qW in [0,15]`, `qX in [-8,7]`;
- `A_h in [-15360,13440]`, `S_h in [-1024,896]`;
- XMASTER `d_h = D_n * 2^x_h`, `x_h in [0,2]`, with one D over **all K of the token**, not a tile-local master;
- the ordinary affine answer be `y = sum_h d_h*(s_h*A_h + z_h*S_h)`.

No FWHT, AWQ, weight codes, activation rounding/clamping, or scale selection changes are authorized. `RN`, `FMA_RN`, and `float` below specify f32 round-to-nearest-even operations/conversion. Mathematical equality to the ordinary affine answer is **not** equality to the current `IU4_FOLD_RN` rounding DAG.

### 2.1 M1 — C2, one floating accumulation update per 256 K

C2 means `s_gh = B_rg*m_rgh = G_rg*m_rgh/16`, `m in [1,16]`, **where `G=16B` is the constrained reference**, not necessarily the maximum of the two lowered half scales. B is the f16 base with low four significand bits cleared, floor bits `0x0010` for positive groups. The original paper's rare floored groups need not attain m=16. Zeros `z_g0,z_g1` are independent f16 numbers, not assumed integer multiples of B.

Define

```
T_g = (m_g0 << x_g0)*A_g0 + (m_g1 << x_g1)*A_g1
U_gh = S_gh * 2^x_gh
F = sum_g [ B_g*T_g + z_g0*U_g0 + z_g1*U_g1 ]
y = D_n*F
```

Factoring D outside the **entire** floating reduction is cheaper than recomputing `B*D` and `z*D` inside every group. It does not make unrelated B or free zeros integer-compatible across groups. Freeze this implementable f32 DAG:

```
f = +0
for g in K order:
    p = RN(float(B_g) * float(T_g))
    p = FMA_RN(float(z_g0), float(U_g0), p)
    p = FMA_RN(float(z_g1), float(U_g1), p)
    f = RN(f + p)
y = RN(D_n * f)
SET: Y = y;  ADD: Y = RN(Y_old + y)
```

This is one **f32 fold/update** per 256 K, not one f32 instruction; both zero FMAs remain. No bias exists in this GEMM ABI; preserve surrounding bias operations, if any, separately. The integer part obeys

`|T_g| <= 256*120*16*4 = 1,966,080 < 2^21`, `|U_h| <= 4096`.

Thus integer products, the group sum and their f32 conversions are exact. This is the paper's C2 group bound **491,520**, multiplied by XMASTER's maximum factor 4. For K=5120 and 17408 the running integer state is **still reset every group and bounded by 1,966,080**. The corresponding whole-row boxes are 39,321,600 and 133,693,440; they do **not** license whole-K accumulation because B and z vary by group. Free floating zeros have no int32 accumulator to prove.

#### Keep two half sums without a third accumulator bank

Naively carrying `float f[64]`, `int T_first[64]`, and `int cacc_second[64]` consumes **192 VGPR before addresses, fragments and staging**, so it violates the approximately 200-VGPR/three-workgroup requirement. Smaller tile/double staging/LDS scratch is outside this ticket.

The bounded alternative is to retain **raw**, not scaled, half sums in the existing 64-register `cacc` bank:

1. Half 0 uses the ordinary four K32 WMMAs from zero. Pack each result as the bit pattern `uint32(A0) << 16`.
2. Half 1 starts its first WMMA from that packed value instead of zero, then accumulates its four K32 contributions into the same bank. Its completed signed value is `P = 65536*A0 + A1`.
3. Recover `A1 = sign_extend_16(P & 0xffff)`, `A0 = arithmetic_shift_right(P + 32768,16)`. Then form T_g using ordinary nontruncating integer products/MAD, consume both DS/SZ parity planes, fold once and reuse `cacc`.

All A1 partial prefixes fit the same 15,360 bound; no low-half overflow defeats recovery. `P in [-1,006,648,320,880,817,280]`, and `P+32768` also fits i32. The **executed** 201,607 checks enumerate every A0 in its legal interval against A1's extrema and sign/carry boundaries; the interval argument covers the interior. Use unsigned left shifts plus explicit bit reinterpretation and defined arithmetic extraction, never C++ left-shift of a negative signed integer. WMMA must be nonsaturating. This packing is an algorithmic possibility, not a measured kernel win; its instruction cost is decisive in section 5.

### 2.2 M2 — whole-K integer state and one epilogue scale

Weight relation: `s_rh = B_r*2^w_rh`, `w in [0,8]`. Let `e_rnh=w_rh+x_nh`, hence **0 <= e <= 10**.

**C4z, integer zero:** `z_h=s_h*k_h`, `k_h in [-15,0]`.

```
Q_h = A_h + k_h*S_h
T = sum_h 2^e_h * Q_h
scale = RN(B_r * D_n)
y = RN(scale * float(T))
SET: Y=y; ADD: Y=RN(Y_old+y)
```

Compute Q before the shift and before adding to T. A, k and S fit signed i24 for `v_mad_i32_i24`; T does not. Only the multiplicands may use i24 semantics. Arbitrary `qW+k` spans [-15,15], so there is no exact signed-i4 recode for general k. Separately summing weighted A and weighted kS would require another accumulator bank and extra work; it also hides the cancellation needed for the tight bound. The cheapest straightforward exact affine correction is **one integer MAD per component**, followed by the combined-exponent shift-add.

**C4s, fixed k=-8:** stage `qW xor 8` and use `signed_a=true`, `signed_b=true`. This reinterprets each weight nibble as `qW-8` without expansion. Then

```
Q_h = sum_128((qW-8)*qX)
T = sum_h 2^e_h * Q_h
y = RN(RN(B_r*D_n) * float(T))
```

A packed DWORD is recoded with XOR `0x88888888` **once by the cooperative W producer**, not on each fragment consumer. Four b64 W loads per lane per 128 K mean eight XOR instructions/wave/trip before any incidental pairing. This beats computing `A-8*S` separately for all 64 output components. Do not alter original qt44 bytes or GEMV interpretation.

**Plain C4 is not this M2.** Its correct expression is

`T=sum_h 2^e_h*A_h; Z=sum_h z_h*2^x_h*S_h; y=B*D*float(T)+D*Z`.

Free z retains per-half f32 correction. The real artifact `qwen3.8-27b.mq4e8-c4.hfq` must never be run through the C4z/C4s epilogue or quietly requantized by the loader. A true free-zero C4 kernel is an explicit non-goal, not a hidden third fast mode.

### 2.3 Whole-K i32 proof and admission

For C4z, each corrected product is `(qW+k)*qX`, with magnitude at most **15*8=120**, so `|Q_h|<=15360`. This uses correlated A and S, not the looser `|A|+|kS|` triangle bound. C4s products have magnitude at most **8*8=64**.

| Integer state | K=5120 | K=17408 | Required invariant |
|---|---:|---:|---|
| M1 group T (both K values) | 1,966,080 | 1,966,080 | reset every 256; m<=16, x<=2 |
| M1 whole-row numeric box, **not a legal fold** | 39,321,600 | 133,693,440 | unrelated B/free z forbid using this state |
| M2z whole-K `K*120*1024` | 629,145,600 | **2,139,095,040** | k in [-15,0], w+x<=10 |
| M2s whole-K `K*64*1024` | 335,544,320 | 1,140,850,688 | exact signed recode, w+x<=10 |

`INT32_MAX=2,147,483,647`; M2z K17408 margin is only **8,388,607**. Its next aligned K17664 bound is **2,170,552,320**, rejected. C4s's conservative maximum aligned K is 32512; K32768 reaches 2^31 and is rejected. Initial model integration admits only the required K=5120/17408 plus smaller positive 256-aligned K under these limits. No saturation, exponent clamp, positive k, or e>10 fallback. Combined weight/activation exponent 16 would invalidate the proof.

All partial T prefixes are bounded by the same per-element absolute-sum argument. Implement shifted additions in u32 bit arithmetic, with explicit signed reinterpretation only where the proved in-range result is required. The final i32-to-f32 conversion is generally rounded for M2; neither bit identity to the old half folds nor monotonic KLD improvement is claimed.

## 3. Frozen compile-time and metadata interfaces

These are interfaces for the implementing caller, not changes made by this document.

### Modes and kernel ABI

- `IU4_INTFOLD_MODE=0`: shipped scalar/paired RN fold, unchanged ABI and entry names.
- `IU4_INTFOLD_MODE=1`: M1 C2.
- `IU4_INTFOLD_MODE=2`: M2, with compile-time `IU4_INTFOLD_SYMMETRIC=0` for C4z or `=1` for C4s. No per-output runtime mode branch.
- A single default-OFF process/model configuration, proposed `HIPFIRE_IU4_INTFOLD=off|c2|c4z|c4s`, selects separately compiled gfx1201 modules. It requires `HIPFIRE_IU4_PREFILL=1` and `HIPFIRE_IU4_XMASTER=1`. Illegal combinations fail before launch; do not silently run an integer fold on arbitrary qt44.
- Keep the current seven-argument mode-0 entries. Mode-specific entries have suffixes `_intfold_m1`, `_intfold_m2z`, `_intfold_m2s`, each with `_full_set` and `_full_add`, avoiding the runtime's function-name cache collisions. Frozen argument order: **`A, Xq, Y, M, K, N, add, H, Wmaster, Xmaster`**. H is immutable packed weight metadata, Wmaster is null for M1 and f32[M] for M2, Xmaster is the existing f32[N] master array.
- Same grid `[ceil(M/128),ceil(N/128),1]`, block `[256,1,1]`, dynamic LDS **19456 B passed /16384 B used**. Runtime-add entry, if retained for the oracle, must select only SET versus ADD, not fold mode.

### Weight metadata: one prepared header, not a second weight tensor

Retain qt44's original **136-byte groups** and original nibble payload. Produce H as **8 bytes/group**, group-major within each row, two 4-byte half records; the ordinary packed-header load is redirected to H rather than adding another hot-loop header load.

- M1 half record: low u16 `B_bits | (m_h-1)`, high u16 original `z_h` bits. B's low four bits are zero by C2 contract. At LDS publication/fold, mask to recover B and extract m+1; charge that work. SZ slots remain 8 B/row, containing the packed base/m word and widened zero.
- M2z half record: low u16 w, high i16 k. SZ slots hold widened integer e_w and k. M2s uses low u16 w, high u16 zero/reserved; k=-8 is compile-time, no k load/use is needed by the fold.
- Recover a deterministic representable base from the **lowered exact headers**, not original-parent heuristics: enumerate at most 16 C2 base candidates from one nonzero half, or nine row-master candidates from a nonzero C4 half, require every decoded relation to match exactly, and choose the largest admissible base. Re-basing by a common power of two is algebraically harmless and must stay within the same exponent bounds. Reject absent candidates, nonfinite headers, invalid integer zeros and mixed unconstrained tensors. Canonical all-zero scales/zeros are admitted explicitly (B=0, selectors harmless); do not confuse them with the positive-base floors.
- Validate `s=B*m`, or `s=B*2^w` and `z=s*k`/`z=-8s`, for **every half**. Artifact metadata/provenance is necessary for experiment labeling but never substitutes for these checks. No new qtype, disk header, or compact artifact is required. H costs about **0.80 GB across the study's 100,085,760 groups**, plus row masters; it is not compressed-file savings.

Runtime integration should reuse the existing `Gpu::ensure_fp16_shadow`/`invalidate_weight_caches` ownership pattern for an immutable derived-weight cache, not add fields to every `GpuTensor` or propagate a new argument through all model-layer APIs. Proposed central helper: `ensure_mq4e8_intfold_weight(a_raw,m,k,mode) -> {header_ptr, row_master_ptr}`. Cache key includes pointer, M, K and mode; cache validity additionally depends on the existing model/weight lifetime. On first uncaptured use, gather **headers only** from A, validate/repack privately, upload H/master, and publish the cache entry only after success. Never copy the full nibble tensor to recover metadata. Reuse the existing pool ownership and unload invalidation, remove entries on individual weight release, invalidate retained replay before freeing derived buffers, and refuse an unprepared cache miss during capture. Warmup prepares all admitted weights before graph capture. Pointer reuse is not a new identity.

### Activation ABI and lifetime

Do **not** change the 72-byte `block_i4_128` global ABI: `[f32 d, i32 S, 64 B nibbles]`, layout `[K/128,N]`. Existing XMASTER already emits `d=D*2^x`, exact S and unchanged signed-i4 packing. Pass the current master pointer explicitly; never recover/cache it from an X address or invent a local per-tile master.

At cooperative DS publication, derive x by exact equality against D, 2D and 4D (three candidates, no logarithm/division or normal-only exponent-bit assumption). The current staging token's D may be loaded once at kernel entry; consumer D is loaded only at the epilogue. Store `(x,S)` in the **same** 8-B DS slot. This handles a valid subnormal D without losing exponent information. Every legal producer output must match one candidate; finite positive D and exact emitted relations are part of the producer domain. The all-zero token has D=1,d=1,q=S=0,x=0. Oracle includes zero/subnormal boundaries and a malformed producer record rejection; no approximate exponent fallback.

The existing `ScratchState::int4_mmq_xmaster_scratch` owns `[N] f32 master + [N] i32 rowzero`, 8 B/token, refreshed on **every** preparation. `Gpu::ensure_int4_mmq_x` invalidates retained replay before block/master allocation growth; `ScratchState::ensure_int4_mmq_x` increments `int4_mmq_generation` before overwrite and returns only after all three launches enqueue. The integer consumer must obtain `{Xq,Xmaster,K,N,generation}` from that same successful preparation. A prepared producer handle without the token-wide master is ineligible; XMASTER already disables the incompatible gfx1151 producer sidecar. No stale successful handle may survive failure, resize, generation mismatch, or subsequent preparation. No extra activation copy or changed quantizer recipe is authorized.

## 4. State transitions, LDS and VGPR budget

### Same staging, different accumulator meaning

Keep A at LDS 0 (4096 B), W0 at 4096, W1 at 8192, DS0/DS1 at 12288/13312, SZ0/SZ1 at 14336/15360. Preserve fragment-order addresses, b64 loads, masks/clamped tails, two 64-K slabs per half, eight waves, four barriers per half, next-block fetch epoch and stride-20 coalesced stores. C4s changes only W DWORD values by the producer XOR, not ownership or addresses. Metadata values are mode-specific, not additional planes. No extra LDS group-partial buffer.

| Transition | Before / owner | Action | After / invariant |
|---|---|---|---|
| Weight prepare | Original A immutable; no public H | Private header gather/validation/upload | H and Wmaster belong to weight cache; all relations validated; failure publishes nothing |
| Activation prepare | Previous generation may exist | Invalidate before growth, bump generation, quantize/reduce/fixup on one stream | Current Xq and master are a single ready-to-enqueue generation; old prepared handles invalid |
| Prologue | Accumulators zero; no shared generation | Publish kb0/slab0 and metadata, existing barrier | Every wave sees the same A/W0/DS0/SZ0 |
| Compute slab0 | Current A/W0 immutable; next raw registers private | First two K32 bundles; prefetch slab1 | cacc contains current first 64 products, or M1 half1's packed seed plus those products |
| B0, publish1, B1 | All old A readers complete | Existing fences; publish A/slab1,W1 | All waves may consume current slab1; no early overwrite |
| Fetch next + compute1 | Current metadata remains immutable | Six next raw loads in private registers; final two current bundles | All 128 current products in cacc; next payload not yet shared |
| M1 half0 close | cacc=A0, floating F includes only prior groups | Pack A0 into high half; **no F update** | Existing cacc bank retains raw A0; DS0/SZ0 must remain readable until half1 fold |
| M1 half1 close | cacc=P, DS0/SZ0 and DS1/SZ1 both current | Unpack, exact T/U, one group RN fold | F includes group g exactly once; old parity-0 metadata is now dead |
| M2 half close | cacc=unscaled Q/A; T includes previous halves | C4z MAD or C4s recoded dot, e=w+x, unsigned shift-add | T includes this half once; raw cacc can restart at zero next half |
| B2a, next publish, B2b | Current consumers have finished | Preserve waits/fences; publish next generation only if !last | No slab or metadata read/write race. In M1, next group's parity-0 writes occur only after half1 consumed both planes |
| End K / epilogue | All folds complete; no A/W/metadata readers | M1 D*F or M2 RN(B*D)*float(T), then existing LDS transpose/store | SET overwrites, ADD reads old Y and adds once; no early float rounding in M2 |
| Reprepare/unload | Kernargs may retain pointers | Existing replay invalidation and stream/lifetime discipline before overwrite/free | No graph/replay packet names a stale master/header; KV, recurrent state and commit cadence untouched |

Keep h rolled. Half1 in M1 must use `FIRST=false` for its first bundle; all other current integer order is unchanged. M2 restarts the raw cacc every half and never feeds the shifted whole-K T into WMMA.

### Resource budget, not an occupancy promise

- Current measured state: **202 raw VGPR**, SGPR 40 for full entries /43 dispatcher, zero spills/private scratch, HIP occupancy result **3** with 256 threads and LDS19456. Historical “3 WG/CU” is the HIP reporting unit/WGP here: **24 resident wave32s/WGP**, nominally six/SIMD, not twelve. Record the same API/unit instead of inferring residency from a generic register table.
- Both viable layouts use **128 accumulator registers/lane**: M1 `F[64]+packed_cacc[64]`; M2 `T[64]+raw_cacc[64]`. M1's naive third bank is rejected at design time. Conversion of final T to float must reuse dead accumulator storage, not allocate a second 64-float epilogue array.
- Planning envelope: 128 accumulators +12 current A/W fragment registers +10 raw prefetch/header registers +12 fragment-address registers +16 other live address/mask registers +up to22 transient metadata/scalars = **200**. Reuse dead fragments during fold, consume one row-group/column-block at a time, and load final B/D late. This is a **liveness target**, not a verified allocation partition; the current 202-register result shows how tight it is.
- M2 target **192–200 raw VGPR**. M1 target **<=200** with packing; inability to realize it is a stop, not permission to spill or change geometry. A 201–202 result needs explicit reviewer acceptance of the same rounded allocation and measured residency as baseline; **>202, any spill/private scratch, or occupancy <3 fails**. No promise is based solely on `__launch_bounds__(256,2)` or the source-level arithmetic budget.
