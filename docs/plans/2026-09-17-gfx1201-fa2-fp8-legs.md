# gfx1201 FA2 prefill: fp8 K/V planes + fp8 QK/PV legs

Date: 2026-09-17 · Target: exact gfx120x · Branch `mq4-lloyd` · Plan of record

## 0. Why, and what the number is

hipfire gfx1201 prefill on the canonical trunk (`qwen3.8-27b.mq4-xt`, graphs ON):
pp512 1464 / pp2048 1435 / pp8192 1327 / pp32768 1044. The curve falls 29 % from
512 to 32K, and attention's share grows with depth. A competing gfx1201 stack
holds 3552 @2K → 3192 @64K (−10 %) and attributes its flatness to fp8 QK+PV legs
(+10.8 % @106K, 96→150 TF at an 8K chunk). Ideas only; nothing of theirs is read.

Measured today on the R9700 (`/tmp/wmma_probe/wmma_probe.hip`, ISA-verified,
<1 % spread): `wmma_f32_16x16x16_f16` 182 TFLOPS; `wmma_f32_16x16x16_fp8_fp8`
**330 TFLOPS (1.81×)** at the same K=16 with half the operand bytes. The fp8 op
does **not** double K per instruction; the win is issue rate + operand density.

is the first-order cause of the 64K falloff and is scoped separately (§7).

## 2. The mechanism

fp8 e4m3 planes halve LDS per KT64 tile: 65,536 → **32,768 B** → 2 WG/CU
becomes reachable (registers already allow it: 239 VGPR = 2 waves/SIMD ×
4 SIMD = 8 waves/CU ≥ 2 WG × 4 waves). Both legs then run the fp8 op at 1.81×.

Where fp8 rounding enters, and the scale that goes with it:

| operand | today | fp8 form | scale |
| --- | --- | --- | --- |
| K | q8_0 int8 × f16 block scale → f16 | **e4m3 codes, block scale kept f16** | q8_0's own 32-elem block scale `sf` (:236) — apply it in QK's f32 epilogue per key-block instead of at fill. **NOT lossless** (corrected 09-17 by the CPU screen): e4m3 is exact only for integers ≤ 14; codes 121..127 round by up to ±4 (127→128). Measured on real layer-35 data: max-abs 0.096 / tail-1 % 0.0063 on O. Bounded, but it is a real rounding. |
| V | q8_0 int8 × f16 scale → f16 | **e4m3 codes**, scale `sf0/sf1` (:285) | same rounding as K. Scale applied in PV epilogue per key-pair block. |
| Q | f32 → f16 (F4b pre-convert) | f32 → **e4m3 + per-row f32 scale** (absmax/448) | one rounding, per-row. Measured: row absmax 3.6..13.4, mean \|dQ/Q\| 2.2 %; stage-b tail 0.0050 (lower than stage-a alone — within the screen's noise). |
| P | f32 softmax → f16 `prow` | **stays f16 — stage c KILLED** | CPU screen: 95.6 % of P entries are below e4m3's normal floor at ×1; even at ×64 **31.5 % underflow to zero**, at ×256 13.6 % (gate: 0.1 %). Tail alone would have passed (1.66× stage-b); underflow is the kill. PV keeps `wmma_f16` on a f16 `prow`; V plane is read back e4m3→f16 in-register. |

**Corrected summary:** the K/V planes carry a bounded but real rounding
(§4 stage a numbers), Q adds a per-row rounding (stage b), and P cannot be
fp8 at any scale that keeps its tail. The QK leg goes fp8; the PV leg stays
f16 and takes only the LDS-halving occupancy win. Both surviving stages were
screened on real Q/K/V before any kernel work (§4).

**Op-order fact for implementers:** `fa_attn_out_batch` is POST-gate — the
engine applies `sigmoid(gate)·attn` in place (`prefill.rs:6667`). Any oracle
or memcmp must compare gated O, and Ub must preserve that order.

Softmax state (m, l, alpha) stays f32. Accumulators stay f32 (`sacc`, `Ofr`).

## 3. Occupancy arithmetic

- LDS: K plane 64 keys × 256 dims × 1 B = 16 KiB; V plane 16 KiB; +2 mailbox
  dwords (already in the K plane) = **32,768 B** → 2 WG/CU at 64 KiB LDS/CU.
- VGPR: 239 today. Adds per lane: Q e4m3 fragments are half the size of f16
  ones (−); per-row Q scale (+1); P scale fold (+0, constant 1/64 → one
  `v_mul` per dc per subtile, or folded into `l_val` normalization at
  completion: **fold it at completion**, zero inner-loop cost); K/V block
  scales now needed in the epilogue instead of the fill: per key-block (8 per
  KT64 for K, 8 per key-pair set for V) — keep them in LDS (a 64-entry f16
  table per plane = 128 B each, inside the freed budget) and read per subtile.
  Net VGPR expected ≤ 239. **F6 spilled here at +K-prefetch; this plan adds no
  prefetch.** Gate: `-Rpass-analysis=kernel-resource-usage` ≤ 256 VGPR, 0
  scratch, before any timing.
- If 2 WG/CU is not reached (VGPR > 128 per lane at wave32 means 2 waves/SIMD
  max = 8 waves/CU = exactly 2 WG): it IS reached at ≤ 256 VGPR. The risk is
  only spill.

## 4. Pre-kernel quality screen (unit 0b, CPU, kills the plan in an hour)

Dump real Q, K, V for one FA layer at a 4K prompt
(`crates/saddle-lab/examples/dump_qwen35_hidden_states.rs` or the attention
oracle's fixture path) and compute attention four ways on CPU in f64:

1. reference: f16 Q/K/V/P (today's numerics, reproduce the kernel's rounding points)
2. stage-a: e4m3 K/V codes with f32 block scales in epilogue (should be bit-identical to 1 modulo f16-vs-f32 scale-multiply order — **verify it is**)
3. stage-b: + Q e4m3 per-row
4. stage-c: + P e4m3 ×64

Metrics per stage vs 1: max-abs and **tail-1 %** error on O (not RMS — RMS has
failed to predict KLD in this repo, `tools/quant-design/README.md`), plus the
fraction of P entries that underflow at ×1 vs ×64. Kill: stage-c tail error
> 2× stage-b's, or P underflow > 0.1 % of entries at ×64.

## 5. KLD gate

Not bit-exact by construction (Q and P round). Gate is the pinned WT2 eval on
gfx1201, 24 chunks, prefill scoring, q8 KV, canonical trunk. Baseline: the
current fp8-GEMM/f16-FA2 default measured today at **0.046713** (IU4 off) /
0.046821 (XTX cross-check). Precedents: X128 admitted at `on ≤ off + 0.0005`;
fp8 GEMM admitted on byte-identical greedy. This change touches attention,
which is more KLD-sensitive than a GEMM operand; **cap: `on ≤ off + 0.0005`**
(same as X128), i.e. ≤ 0.047213. Stage a is NOT lossless (§2 corrected), so it
carries the same KLD gate as b — there is no md5-only stage. Establish the
gfx1201 1-chunk and 2-chunk `.kldseq` md5s at stage 0 as the first gfx1201
pins in AGENTS.md §5.

## 7. Split-KV is a separate unit, and it is the bigger one at 64K

Production never dispatches `partial`+`merge`; >32K leaves FA2. Flattening the
curve to 64K needs: (1) a production launcher for the split path with an
n_splits policy (bench launcher at `attention.rs:4354` is the template),
(2) the merge kernel's cost measured, (3) the 32768 hard-coded coverage in the
partial kernel lifted. Exact by construction (same math, different tiling —
gate by device memcmp against direct at ≤32K). Spec after stage a lands; it
shares the fp8 planes.

## 9. Kill criteria and risks

| risk | detection | action |
| --- | --- | --- |
| spill on any stage | metadata gate | drop that stage's register additions (P scale fold at completion, scales in LDS); if still spilling, stop at the previous stage |
| stage-a not bit-exact | memcmp | bug in scale-order; §2 says it must be exact — fix, do not widen the gate |
| KLD > cap at b or c | eval | keep the passing stage only; report the number |
| P underflow at ×64 | CPU screen | try ×256 (e4m3 max 448, P ≤ 1 so ×256 is safe); if tail still bad, PV stays f16 (stage c dropped, stage b kept) |
| 2 WG/CU reached but slower | prefill row | LDS bank pressure from 2 WGs; keep `(128,1)` and take the op-rate win only |
| decode leakage | flag + entry names are prefill-only; decode never dispatches FA2 | gfx1201 tg ≥ 36.5 graphs ON checked at every stage |
| gfx11/gfx10 breakage | new symbols exist only under exact gfx120x dispatch; `#if` guards in the .hip with `#error` on non-gfx12 when `HIPFIRE_FA2_FP8` is set | `.text` md5 of gfx1100/gfx1151 code objects unchanged at every stage |
