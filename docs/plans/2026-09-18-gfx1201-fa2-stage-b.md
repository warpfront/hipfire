## 1. Decision: one body, two sources, one arithmetic contract

Stage b makes Q, K, P and V **fp8 (OCP E4M3FN) WMMA operands** while scores,
online-softmax state (m, l) and O stay f32. It keeps every structural decision
slice A admitted: one KT64 tile, four waves (three compute + one helper), 48
query rows, four ordered KT16 subtiles, 64 QK + 64 PV WMMA per compute wave per
full tile, mailbox-free wave-local bounds, two steady-state barriers per tile,
and the frozen fragment formulas with the element width changed from 2 to 1:

```
Kfrag(sub,dc,lane) = ((dc*4 + sub)*32 + lane)*8   bytes, K plane at byte 0
Vfrag(sub,dc,lane) = ((sub*16 + dc)*32 + lane)*8  bytes, V plane at byte 16384
lane = 16*kg + ml;  K byte j = K[key=sub*16+ml][dim=dc*16+kg*8+j]
                    V byte j = V[key=sub*16+kg*8+j][dim=dc*16+ml]
```

Each fragment is 8 bytes, 8-byte aligned, contiguous, no wrap: one
`ds_load_b64` per operand, exactly as slice A uses one `ds_load_b128`
(`K:79-94, 389-445, 511-519`). Dynamic LDS becomes **32768 exactly**
(16384 + 16384); no static LDS, no second tile, no scale table in LDS.

Two **sources** feed those planes. They share 100 % of the QK/softmax/PV/O code
and differ only inside the cooperative fill:

* **Route Q — q8_0 cache (existing production format).** K/V arrive as
  34-byte q8 blocks (`K:242-285, 287-338`). The fill requantizes each 256-dim
  head row to one positive f16 **row scale** and 256 e4m3 codes (§2.2). No cache
  format change, no decode-side change, no writer change. This is the arithmetic
  isolation arm and the only route that can run today.
* **Route N — native fp8 cache (`HIPFIRE_FA2_KMODE=8`).** Codes are copied
  verbatim from the token-local row
  `[codes: 4*256 B, head-major][scales: 4 f16]`, stride 1032; the scale comes
  from the row header at `+1024+2*kv_h` (`N/kernels/src/attention_q8_0_fa2_gqa.gfx1201.hip:211-260,353-405`).
  **No fill decode, no per-element VALU, no f16 rounding.** This is the
  performance route.

Both routes produce the identical operand semantics at the WMMA boundary:

```
K operand byte = e4m3 code ck[key][dim],  with one positive scale sk[key] per (key, head)
V operand byte = e4m3 code cv[key][dim],  with one positive scale sv[key] per (key, head)
Q operand byte = e4m3 code cq[query][dim], with one positive f32 scale sq[query]
```

so the body is **source-agnostic** below the fill. Route Q's scales come from
requantization at fill; route N's come from the row header. Everything in
§3–§7 applies unchanged to both.

### 1.1 Why route Q cannot be the performance route (stated up front)

Route Q keeps the per-element fill decode: `int8→f32`, block-scale multiply and
a pack, 128 of each per wave per side, 712/714 VALU packets per wave
(`docs/plans/2026-09-18-gfx1201-fa2-restructure.md:55-68`). Fill is
`4*2376 = 9504` of the baseline's `21558` issue-equivalents at c16=16, so
leaving it intact caps route Q at **0.907 of baseline / 0.944 of slice A**
(c16=16, r=1.81) and it **loses at c16=4** (1.003/1.056) — §6.4. Route Q is
therefore planned as the *attribution and quality* arm (it isolates fp8
arithmetic error on an unchanged cache) and is admitted on performance only if
the measured c16 is high. Route N is where the prefill win has to come from,
because it removes the fill *and* halves matrix service.

## 2. Fill: three producers, one destination contract

Out-of-range keys (`gk >= seq_len`) write **code 0 and scale 0** in both routes.
e4m3 code 0 decodes to +0.0 exactly, so zero fragments contribute exactly zero
to both WMMA legs, matching today's zero-f16 fragments (`K:254-261, 298-315`).

### 2.1 Route N — K: contiguous 16-byte gather, two 8-byte stores

For a fixed key, source dims `dc*16 .. dc*16+15` are 16 contiguous bytes at
`k_cache + gk*1032 + kv_h*256 + dc*16`. They land in exactly two destination
fragments, `Kfrag(sub,dc,ml)` (dims `dc*16+0..7`, kg=0) and
`Kfrag(sub,dc,16+ml)` (dims `dc*16+8..15`, kg=1), 128 bytes apart. So:

* Slot assignment: one lane per `(key, dc)` pair; 64×16 = 1024 pairs per tile,
  **256 per wave, 8 per lane**.
* Per pair: **one `global_load_b128` + two `ds_store_b64`**. No decode, no
  multiply, no pack, no byte stores, no RMW.
* Scales: one `global_load_u16` per key per wave-slot group; lanes of a group
  share it. Scale bytes are never written to LDS.

Estimated **≈60–90 packets per wave** for the whole K fill (8 iterations × {1
global, 2 LDS stores, 2–3 address, waits} + loop control) against a measured
baseline of 1216. **Unmeasured.** Global coalescing is 2×16 B segments per
instruction across two 1032-byte-strided rows — the same shape as today's
34-byte-block reads, and a measured risk, not a proven improvement.

### 2.2 Route N — V: the transpose is real, and costs byte loads

A V fragment holds **8 keys at one dim** (`V byte j = V[key=sub*16+kg*8+j][dim]`),
but the native row is token-major: those 8 bytes are 1032 bytes apart. There is
no vector load for a V fragment. Frozen design:

* One lane per `(sub, dc, lane)` fragment: 2048 fragments per tile,
  **512 per wave, 16 per lane**.
* Per fragment: **8 `global_load_u8` + one `ds_store_b64`**. Within a wave, the
  16 lanes of one kg half read 16 contiguous bytes of one row, so each byte-load
  instruction touches two 16-byte segments — the same locality class as K.
* Estimated **≈300–420 packets per wave** (vs 1160 baseline). **Unmeasured.**
* **Prohibited in this plan:** an LDS/shuffle transpose stage, a staging array,
  byte LDS stores into a shared fragment (RMW race), or a second V plane.
  `docs/plans/2026-09-18-gfx1201-fa2-restructure.md:88` already refused
  crediting an uncosted V transpose; that refusal stands.

Nominal route-N fill for the budget model: **600 packets/wave** (sensitivity
400…1200), i.e. K+V together, all four waves participating.

### 2.3 Route Q — requantize q8 → e4m3 with a header-only row scale

Naive per-row absmax needs a 256-code scan per key. It is unnecessary. q8_0
sets `sf_b = amax_b/127`, so for the block with the largest scale the maximum
|code| is 127 by construction, and

```
amax_row = max_b (sf_b * amax_code_b) <= 127 * max_b sf_b     (equality at the argmax block)
s_row    = smallest f16 >= (127 * max_b sf_b)/448, floor 2^-24; all-zero row -> s_row = 1
code'    = E4M3_RNE(c * (sf_b / f32(s_row)))
```

The eight 2-byte block headers are the only extra input: **8 scale loads, 1
max-reduction over 8, 1 divide, 8 ratio multiplies per (key, head)**, then the
existing per-code path with `cvt_pk_fp8_f32` replacing the f16 pack. This is the
same rounding placement stage a used (scale applied in f32 before the operand
rounding, never after the dot) and keeps the **exact** `448*f32(s_row) >= amax`
invariant — host-checked in §13.

Bit-width note, so nobody claims equivalence: stage a stored `e4m3(code)` and
multiplied by the block scale in the consumer; route Q stores
`e4m3(code * sf_b/s_row)` and multiplies by the row scale in the QK epilogue.
Both lose the same ~3 mantissa bits on large codes; neither is exact. Stage a's
KLD certificate does **not** transfer, but it is the strongest available prior
that the K-side operand rounding is benign (§8).

V route Q is identical with its own per-key row scale, so `sv[key]` exists and
is separable out of the key reduction only after this requantization. **Never**
multiply a completed PV dot by an averaged V scale.

### 2.4 Contingent variant (not baseline): keep per-32 K scales

If §8's ag-corpus investigation shows the one-scale-per-256-dims format is the
quality limiter, route Q — and only route Q — may retain q8's eight block
scales by splitting the dc chain: for `b = 0..7`, zero one `float8_t` temp, run
the two WMMAs for `dc = 2b, 2b+1` into it, then `score += sf_b * tmp`. Cost:
+8 VGPR live, +8 zero-inits and +64 FMAs per subtile (+256/tile/wave), and the
dc reduction order changes. This is a **separate proposal with its own KLD
gate**, not a fallback to be slipped into the baseline slice.

## 3. Q pre-convert, sq, and where the scales enter the softmax path

Q keeps its own kernel and its own symbols (`K:611-681`; the host function cache
is symbol-keyed, `K:626-637`). Stage b's pre-convert, one wave32 per Q row
(rows disjoint, no LDS, no barrier — unchanged shape):

```
amax = wave_max(|q[0..256)|)                     # 5-step shfl_xor tree, existing idiom
sq   = (amax == 0) ? 1.0f : amax / 448.0f        # f32, NOT f16: sq is never an operand
cq[d]= E4M3_RNE(q[d] / sq)                       # cvt_pk_fp8_f32, 8 codes/lane = 2 dwords
write cq (8 B/lane, one aligned store) and sq (lane 0, one f32 store)
```

`sq` is **f32** deliberately: it is a multiplier in the score epilogue, never a
WMMA operand, so there is no reason to round it to f16 and no half-scale
representability problem. Division by the stored `sq` (not by an unrounded
amax/448) keeps `|q/sq| <= 448` exactly. Zero rows produce zero codes with
`sq=1`, so a zero query row yields zero scores, then the existing
`m == -INFINITY` guards (`K:482-495`) produce zero probabilities and a zero
O row — identical observable behaviour to today.

Scratch (`crates/rdna-compute/src/scratch.rs:198-203, 605-622`) becomes one
owning buffer:

```
[ batch*24*256 bytes: fp8 Q codes ][ batch*24 * 4 bytes: f32 sq ]
```

16-byte aligned at both section starts for every admitted batch (host-checked,
§13). Grows-never-shrinks with the existing pre-growth capture invalidation
(`crates/rdna-compute/src/attention.rs:3651-3664`). Q is never mutated:
replay-idempotent, exactly as F4b established.

**Scale folding into the row-max path.** The per-query factor is constant for
the whole call, so it is formed once per WG at init (`K:141-156`):

```
qs = sq[query] * scale_attn          # 1 VGPR, computed once, not per subtile
```

and the subtile epilogue replaces the single `sacc[j]*scale_attn` multiply
(`K:471`) with

```
score[j] = (acc[j] * qs) * sk[key_j]
```

*before* masking and before the row max — the same position in the graph as
today's scale multiply, so masking, `mx`, the `shfl_xor(16)` partner max,
`m_new`, `alpha`, `l_val` and the `-INFINITY` semantics are structurally
unchanged. Both `qs` and `sk` are positive and finite (writer guarantees a
positive stored scale; zero rows use 1), so the multiply can never flip a sign
or manufacture a NaN, and a masked lane's `-INFINITY` is untouched. Folding
`qs` into `sk` first (8 multiplies instead of 16) is **not** permitted: it
changes the f32 rounding point of every score and destroys the ability to
attribute a KLD delta to one factor.

## 4. QK: accumulator-side scale ownership

Swapped operands are unchanged (`K:24-34`): A = K fragment (row `ml` = key),
B = Q fragment (row `ml` = packed query), `acc[j] = S[query=ml][key=8*kg+j]`.
The builtin changes from `__builtin_amdgcn_wmma_f32_16x16x16_f16_w32_gfx12` to
`__builtin_amdgcn_wmma_f32_16x16x16_fp8_fp8_w32_gfx12`, operands from `half8_t`
(4 dwords) to `v2i_t` (2 dwords) — the idiom already shipping in
`kernels/src/gemm_gate_up_mq4g256v2_wmma_fp8.gfx12.hip:589-630`. Count, order
and the four-`dg` Q-sharing group structure with its scheduling barriers
(`K:369-448`) are retained exactly.

**Scale ownership is transposed and this is the single most likely
implementation bug.** Lane `(ml,kg)` *supplies* K row `sub*16+ml` but *owns*
accumulator keys `sub*16+8*kg+j`, `j=0..7`. Therefore:

* the lane must load `sk` for keys `sub*16+8*kg+0..7`, **not** for key
  `sub*16+ml`;
* the eight values are eight 2-byte header reads at
  `k_cache + (ktile+sub*16+8*kg+j)*1032 + 1024 + 2*kv_h` (route N) or eight
  precomputed row scales (route Q — see below);
* there is **no** 64-key scale array and **no** cross-lane broadcast: direct
  bounded loads, L1-served, lifetime one subtile.

Route Q's row scales are derived inside the fill, so they must be published
somewhere the QK epilogue can read. Frozen choice: a **64-key scale plane per
side appended to the Q scratch buffer**, not LDS (LDS is exactly 32768 and
full). Layout, per KV head and KT64 tile, indexed by the WG's `(blockIdx.x,
kv_h, split)` slot:

```
base = batch*24*256 + batch*24*4
slot = ((blockIdx.x*4 + kv_h)*n_splits + split)
K scales at base + slot*256 + 0   .. +127   (64 f16)
V scales at base + slot*256 + 128 .. +255   (64 f16)
```

Host-checked disjointness for batch ∈ {1,7,8,9,512} × splits ∈ {1,8} (§13); at
batch 512 / 8 splits the whole scratch is 3,719,168 B. The fill writes each
scale exactly once, before the existing fill-publish barrier (`K:339`), so the
same barrier that publishes codes publishes scales — no new synchronization.
Route N does **not** use this plane: it reads the row header directly, and the
launcher must not allocate it.

## 5. Softmax, P packing, and the bounded changing-unit O

Online softmax stays f32 with the same KT16 order and the same operations
(`K:450-520`). The only additions are the weighted-P quantization:

```
m_new = max(m_old, max_j score[j] combined with shfl_xor(16))     # unchanged
alpha = (m_old == -inf) ? 0 : exp(m_old - m_new)                  # unchanged
e[j]  = (m_new == -inf) ? 0 : exp(score[j] - m_new)               # unchanged
sum   = sum_j e[j] + shfl_xor(sum,16); l = l*alpha + sum          # unchanged: UNWEIGHTED
w[j]  = e[j] * sv[key_j]                                          # new: 8 mul
wmax  = max_j w[j], combined with shfl_xor(16)                    # new: 8 max + 1 shfl
b_new = (wmax > 0) ? max(wmax/448, 2^-64) : b_prev                # new
p8[j] = E4M3_RNE(w[j] / b_new)                                    # new: 4 cvt_pk_fp8_f32
rho   = (alpha * b_prev) / b_new                                  # new: 1 mul + 1 div
Ofr[dc] *= rho                                                    # replaces *= alpha, same 128 values
Ofr[dc]  = WMMA_fp8(V8[dc], p8, Ofr[dc])
b_prev   = b_new
```

Invariants and their proofs:

* **Denominator purity.** `l` accumulates unweighted `e`; the V scale lives only
  in the numerator. Moving `sv` into `l` is prohibited.
* **O unit invariant** `O_physical = b_prev * Ofr`, maintained across subtiles
  and tiles. Direct completion stores `Ofr * (b_prev / l)` (`K:531-543`);
  partial completion stores the **physical** numerator `b_prev*Ofr` into the
  unchanged 258-float record (`K:545-577`), so the existing merge
  (`K:765-807`) is untouched and never sees a scale-tagged record.
* **Real-valued identity**: `b_new*(rho*Ofr_old + dot(p8,V8)) = alpha*O_physical_old + b_new*dot(p8,V8)`.
  Host-verified over 64 trials × 17 subtiles with zero/one-key/all-masked/
  wildly-varying-`sv` cases, max f64 relative error **2.298e-14** (§13).
* **Floors are safety, not tuning.** With `sv <= 65504`, `|Vcode| <= 448` and
  ≤32768 keys the accumulator in these units is bounded by ~1.774e31 < f32 max;
  `rho` must be formed as `(alpha*b_prev)/b_new`, never as a quotient evaluated
  before `alpha` is applied. The `2^-64` floor's worst-case rounding
  contribution is ≤1.273e-11 before division by `l >= 1` on a valid attended
  row.
* **Both lane halves must agree** on `m_new`, `sum` and `b_new`; `wmax` reduces
  all 16 valid keys including the partner `ml^16` lane. A per-half `b` is a
  correctness bug, not an optimization.
* **All-zero weight rows** keep `b_prev` and store zero P — no zero scale, no
  division by zero, no NaN. Fully masked rows still return exactly zero.

`prow` packing replaces the 8 `(_Float16)` conversions with 4
`cvt_pk_fp8_f32`; the f16 pack disappears, so the P path is net **+4** packets,
not +12.

## 8. KLD risk ranking of every rounding point, and the ag anomaly

New rounding points, ranked most → least dangerous, with the discriminating
evidence each one owes:

1. **P → e4m3 with a per-(query, KT16) block scale `b`.** This is the only
   rounding applied to the *weights themselves*, and it is new to hipfire: 3
   mantissa bits (≤6.25 % worst-case relative error per weight) directly
   multiplying V, plus tie-to-zero underflow for any valid weight with
   `w/wmax <= 2^-10/448 = 2.180e-6`. Partial cancellation across ≤32768 keys is
   an assumption, not a result. Gate: the corrected real-data screen's
   **underflow ≤0.1 % of positive valid weighted entries** with published
   numerator/denominator and lost mass, *before* any GPU timing; then
   kernel-isolated KLD. e5m2 for P is the *only* pre-approved fallback (same
   issue rate — `E/wmma_probe/coexec_RESULTS.md:35`), and it trades mantissa for
   range, so it must be justified by measured underflow, not by preference.
2. **V → e4m3 (route N: storage; route Q: requantized code).** Error is
   systematic per key and enters O multiplied by a positive weight, so it does
   not average to zero. It is also the side implicated by the format's
   one-scale-per-256-dims granularity (see the anomaly below).
3. **`s_row` collapse in route Q** (eight per-32 scales → one per 256 dims).
   This is a *range* loss, not a mantissa loss, and it is exactly the
   granularity native fp8 already has — which is why it is the prime suspect for
   the ag delta. Contingent escape hatch in §2.4, separately gated.
4. **Q → e4m3 with per-row f32 `sq`.** Qwen3.5 applies QK-L2-norm before
   attention (`fused_qk_l2_norm_scale_interleave_f32_batched` appears in the
   retained kernel profiles), so Q rows are range-controlled and `amax/rms` is
   modest. Medium-low risk; measurable directly as score error in the screen.
5. **K → e4m3.** Lowest risk. Stage a ran precisely this operand rounding with
   per-block scales and was KLD-clean; native-fp8 storage of both K and V passed
   the 24-chunk WT2 gate at 0.048413 ≤ 0.048659. Neither result transfers as a
   certificate, but both point the same way.
6. **f32 bookkeeping (`qs`, `sk`/`sv` widen, `rho`, `b` floor).** Negligible:
   host identity error 2.298e-14 over the recurrence, floor contribution
   ≤1.27e-11.

## 9. Decode side: what the fp8 reader needs to reach ≥36.4 tok/s

Reported state (from Main; not re-derived here): native fp8 decode is **32.7
tok/s** against the **≥36.4** clean floor, with F's scalar
`attention_fp8_e4m3_kv`. Required: **+11.31 % tok/s = −10.16 % token time =
3.109 ms saved per token** (30.581 → 27.473 ms). Prefill admission cannot
proceed past a decode-floor failure, and prefill changes cannot fix it: the FA2
body is prefill-only. Four mechanisms, all present in the read-only reference
and all *identified by source inspection, not measured*:

1. **Software e4m3 decode on the hot path.** Both native readers call a
   branchy bit-twiddling decoder per byte — `hipfire_fp8_e4m3_to_f32`
   (`N/kernels/src/attention_q8_0_kv.hip:160-175`) and
   `hipfire_fp8_e4m3_to_f32_tile` in the tile kernel — with an `e==0` subnormal
   branch and an `e==15` NaN branch, ≈8–10 VALU ops plus control per code.
   The q8 sibling pays one `v_cvt_f32_i32` equivalent per code. Requirement:
   on exact gfx1201 use **`__builtin_amdgcn_cvt_pk_f32_fp8`** (2 codes per
   instruction, hardware OCP e4m3), keeping the software decoder compiled only
   for the reference/non-gfx1201 arms. Per token per FA layer per head that is
   256 software decodes → 128 hardware converts.
2. **Byte-at-a-time loads.** The tile kernel reads `kb[0..3]` as four separate
   bytes (`N/kernels/src/attention_flash_q8_0_tile.hip:539-554`) where the q8
   sibling reads dwords. The fp8 addresses are provably dword-aligned
   (row stride 1032 = 8·129, head offset `kv_h*256`, `k_bi*32`,
   `k_off = (tid%8)*4`), so one `global_load_b32` per 4 codes is legal.
   Requirement: dword loads with the alignment argument recorded in the
   receipt, not assumed.
3. **Per-element scale multiply that is provably separable.** Both readers
   multiply every decoded code by the per-head scale
   (`ks * decode(...)`, `:539-554`, `:250`). With one scale per (token, head)
   the scale factors out of the whole dot: `dot = ks * Σ q·code`. Requirement:
   apply `ks` **once per token per head** after the reduction — 255 multiplies
   saved per head per token on the K side, and on the V side fold `sv[k]` into
   the weight `w = p·sv[k]` once per key instead of once per (key, dim).
   This changes f32 rounding, so it is KLD-gated with the decode-arm pins, and
   it must *not* be applied to a per-32-scale format where it is simply wrong.
4. **Missing fused epilogue.** `qwen35_fa_epilogue_route_supported` admits only
   the q8 and asym3 routes (`N/crates/hipfire-arch-qwen35/src/qwen35/forward.rs:4289-4295`),
   so on fp8 `fused_epilogue = false` and the gate/MQ-rotate/AWQ reduce runs as
   separate work for every FA layer of every decoded token; the dispatcher even
   hard-errors if a gate is supplied (`N/crates/hipfire-dispatch/src/families/attention.rs:1262-1270`).
   The fp8 tile kernel already writes partials with **the same `[2+head_dim]`
   stride so the shared q8 reducer consumes them unmodified**
   (`N/kernels/src/attention_flash_q8_0_tile.hip:630-635`). Requirement: verify
   the gated/AWQ reducer's inputs are genuinely format-independent
   (`N/crates/rdna-compute/src/attention.rs:9198-9234`), then admit the fp8
   route into the fused epilogue and delete the refusal — or, if it is not
   format-neutral, state that and cost the separate epilogue explicitly. A
   claim that the decode floor is reachable *without* resolving this is not
   accepted.

Decode admission protocol: separate decode-only run, no preceding 32 K heat
soak, graphs ON, native writer + native readers, **tg64@128 ≥ 36.4**, plus a
long-prefix row to expose the conversion cost, plus a per-kernel profile table
showing the attention and epilogue rows for both arms. The removal mechanisms
above must be visible in that table as the source of the 3.109 ms/token; a
matching total with unexplained attribution is not proof.

## 11. Abandon criteria and the reviewer veto

One implementation of this contract plus **at most one** targeted correction per
leg, each justified by emitted ISA/lifetime evidence. Abandon the offending leg
immediately on:

* any spill, scratch byte, >240 VGPR without an explicit Main decision, or a
  wave-count drop;
* a K/V/P/Q operand path that still contains an fp8→f16 conversion inside
  QK/PV (that is stage a, which measured −26 %);
* underflow >0.1 % on the corrected real-data screen, or a NaN/Inf on any
  admitted shape;
* kernel-isolated KLD > matched OFF + 0.0005, or combined > 0.049159, or an ag
  delta that survives §8.1(A) without the §8.1(B) attribution;
* route-N fill that measures ≥1200 packets/wave — at that point §6.4 puts the
  whole-tile ratio at ≥0.689 and the forecast margin over slice A's measured
  neutrality is thin enough that the bench must decide before more work;
* **the unmeasured-idea rule**: route Q is abandoned as a *performance*
  candidate the moment its measured whole-tile ratio fails to beat slice A by
  >1.5 % on a prefill row; it survives only as the quality/attribution arm.
  Likewise the §2.4 per-32 variant and any P-encoding change to e5m2 are
  abandoned unless a measurement demands them.

Ship-nothing is an acceptable outcome: if stage b cannot clear the quality
gates, the admitted arm remains slice A's exact f16 body, and this plan records
the failing number. Do not resurrect stage a, do not ship the slower Q0 bridge,
and do not convert route Q into an open-ended precision search. Reviewers hold
the final veto after claim-scoped evidence, not after packet counts.

## 12. Cross-architecture behaviour and explicit non-goals
