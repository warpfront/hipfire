## 3. Frozen conditional architecture and storage contract

The design is recorded to make the rejected proposal actionable without inventing illegal resource assumptions. It is not permission to bypass P0.

### Roles and query ownership

Use eight waves: consumers `0,1,2,4,5,6`; producers `3,7`. Each producer supplies one KT16 half of a KT32 tile. Consumers own the same 16-query WMMA shape as stage b. For consumer wave w, `g=w>>2`, `c=w&3`:

```
q_base = 16*blockIdx.x
head = 6*kv_h + 2*c + (ml>>3)
query = q_base + 8*g + (ml&7)
lane = 16*kg + ml
```

One WG therefore owns 16 positions x 6 heads = 96 query rows; each query/output has one owner. Grid `ceil(batch/16),4,1`, block 256. Producers own no m/l/O. Every wave derives identical bounds over the same sixteen positions, lanes 0..15 guarded by query validity; integer min/max order is immaterial to the exact integer result. Invalid-query consumers still participate in all protocol events.

**Tile size correction:** two full KT64 native-fp8 K/V pairs use `2*64*256*2 = 65536` bytes, leaving **zero** bytes for persistent flags or an LDS transpose scratch. Do not append either past the allocation or borrow live payload bytes. Freeze **two KT32 K/V tiles**, accounting and reporting work per two visits (= KT64). The four ordered KT16 softmax updates remain exactly the same. This is a legal double-buffered K/V design under the requested 64KiB budget, not a claim that two KT64 tiles plus metadata fit.

| Byte interval (half-open) | Owner/lifetime |
|---|---|
|0..8192, 8192..16384|slot 0 K8, V8, readable only after both ready epochs|
|16384..24576, 24576..32768|slot 1 K8, V8, same contract|
|32768..36864|producer 3 private 4KiB V transpose scratch|
|36864..40960|producer 7 private 4KiB V transpose scratch|
|40960..40976|`ready[2][2]`, four u32 epochs, one writer each|
|40976..41024|`done[2][6]`, twelve u32 epochs, one writer each|
|41024..41216|padding; no mailbox or scale arrays|

Dynamic LDS **41216**, static LDS zero. Padding is included; hardware allocation granularity must be measured. Flags never alias payload. The scratch is per producer, not per ring slot: a producer finishes the transpose before beginning another tile. All native KV rows remain `[4*256 code bytes][4 f16 scales]`, stride **1032**, including contiguous and admitted VMM storage. Header scale reads stay direct, one subtile lifetime; no scale plane.

Within each slot (`s=0,1`, `dc=0..15`, lane `0..31`), byte offsets are:

```
Kfrag32(s,dc,lane) = ((dc*2+s)*32+lane)*8
Vfrag32(s,dc,lane) = ((s*16+dc)*32+lane)*8
K byte j = K[key=32*tile+s*16+ml][dim=dc*16+kg*8+j]
V byte j = V[key=32*tile+s*16+kg*8+j][dim=dc*16+ml]
```

Producer p owns sub=s=p. Existing K byte copy is preserved, two b64 stores from a 16-byte contiguous row segment, with safe unaligned global loading: 1032 is 8 mod 16, so do not strengthen the source alignment through an unjustified `uint4*` cast. Consumer loads are aligned b64 with bounded base plus compile-time dc immediate offsets. No per-tile 64-address register array.

### Concrete V transpose, without a global format change

Each producer stages its sixteen token-major V rows in its 4KiB scratch. In dword units use `S(k,word)=(k*64+word)^((k&3)*8)`, k=0..15, word=0..63. It is a bijection, and XOR does not disrupt the four consecutive dwords of a 16-byte store. Global loads and scratch stores are vectorized; out-of-range source rows generate zero without reading past the live prefix. A wave memory synchronization separates scratch writes and transpose reads.

For each dc and lane, let `r=ml&3`, `dq=ml>>2`. Read two dwords from scratch keys `kg*8+r` and `kg*8+4+r`, word `dc*4+dq`. Each four-lane group performs a packed 4x4 byte transpose on each dword:

1. XOR-1 lane shuffle. Byte selection from `(own,partner)` is `[0,4,2,6]` for even r, `[5,1,7,3]` for odd r.
2. XOR-2 shuffle of that result. Select `[0,1,4,5]` when `(r&2)==0`, otherwise `[6,7,2,3]`.
3. Concatenate the two resulting dwords and store one b64 V fragment.

This is LDS-staged transpose plus packed lane permutation, not eight global byte gathers, not decoding, not byte-store RMW, and not a new KV layout. Budget two LDS dword reads, four lane shuffles and four packed byte permutes per output fragment, plus its b64 store and address/wait work. Do not assume an unsupported transpose instruction is available because a newer compiler lists its builtin. The swizzle targets the supplied 32-bank x4-byte LDS organization; only GPU/ISA measurements can establish its actual bank performance.

`R/host_contract.py` was executed: exhaustive K/V slot-byte bijections, scratch dword bijection, and the packed transpose's key/dimension labels all pass. This proves address/label algebra only, **not** emitted instructions, bank throughput or device byte equality of this proposed transpose.

## 4. Exact synchronization and pipelining transitions

### Available primitives, not a Hopper mbarrier fiction

On gfx1201 the public hardware workgroup barrier is ID **-1**. The compiler emits `s_barrier_signal -1` plus `s_barrier_wait -1`; memory completion is separate (`s_wait_dscnt`, global load waits when needed). Arbitrary named/subset barriers 0..16 in LLVM's current documentation are **GFX12.5**, not gfx1201. Never wait on a full-WG barrier from only producer waves. See [LLVM execution synchronization, GFX12 barrier IDs](https://llvm.org/docs/AMDGPUExecutionSynchronization.html#amdgpu-execution-synchronization-barriers-sbarrier-ids-gfx12) and its explicit statement that execution barriers alone do not publish memory.

Use one convergent full-WG `__syncthreads()` after flag initialization, and one at final drain if retained by the implementation. Steady-state uses the following LDS epoch protocol, not `volatile` polling:

- `release_epoch(ptr,e)`: all lanes execute `__syncwarp()`; lane 0 performs `__hip_atomic_store(ptr,e,__ATOMIC_RELEASE,__HIP_MEMORY_SCOPE_WORKGROUP)`.
- `await_epoch(ptr,e)`: lane 0 performs `__hip_atomic_load(ptr,__ATOMIC_ACQUIRE,__HIP_MEMORY_SCOPE_WORKGROUP)` until equality; `s_sleep 1` in failed polls; reconverge and all lanes execute `__syncwarp()` before using the synchronized data.
- HIP wave sync supplies release/acquire wave fences around its wave barrier. The compiler must wait for **every lane's** prior LDS operations before the leader publishes ready or done. Do not replace these with a leader-only wait that omits other-lane work.
- Epochs count from 1 within this invocation/split, not a single toggled bit; at most 1024 KT32 visits under 32K context. Flags initialized to 0 on every invocation, including graph replay. No wraparound, inter-WG rendezvous or retained flag allocation.

`R/ring.hip` implements this producer/consumer ownership protocol as a standalone sentinel-copy probe, with six readers and two writers, 41,216-byte LDS, 64 WGs. **Executed PASS** for 1,2,3,7,65,513 tiles, every reader's checksum equal to host expectation. `R/ring.log`; 17 VGPR, 0/0 spill, zero scratch in `R/ring_build.log`. Its emitted ISA has `s_wait_dscnt 0` before ready stores, acquire `ds_load_b32`/wait paths, and full-WG signal/wait only at initialization/drain. It also emits `global_inv scope:SCOPE_SE` on the general acquire path: charge this cost; the probe does not establish a zero-cost LDS-only fence lowering. This is a **protocol smoke proof**, not full attention/capture/race-tool certification or a ring speedup measurement.

No hard phase barrier may create a dependency cycle with a producer waiting for a consumer's slot acknowledgement. Per-role slots, not blind lockstep, govern progress. **P0 says not to implement the phase-staggering leg.**

Never split a KT16 softmax update or compare differently partitioned results for bit identity.

## 5. Numerical invariant and per-role registers

No arithmetic optimization is bundled into scheduling. For each live query and each ordered KT16:

```
score[j] = (qk_acc[j] * (sq * scale_attn)) * sk[key_j]
mask -> mx -> m_new
alpha = (m_old == -inf) ? 0 : exp(m_old-m_new)
e[j] = (m_new == -inf) ? 0 : exp(score[j]-m_new)
l = l*alpha + ordered_sum(e)             # NOT weighted by sv
w[j] = e[j]*sv[key_j]
bnew = (max(w)>0) ? max(max(w)/448,2^-64) : bprev
p8 = E4M3_RNE(w/bnew)
rho = (alpha*bprev)/bnew
Ofr = rho*Ofr; Ofr = WMMA(V8,p8,Ofr)     # same per-component order
bprev = bnew
```

Invariant between updates: `Ophysical = bprev*Ofr`. Direct uses the existing expression `Ofr*(bprev*(l>0 ? 1/l : 0))`; do not reassociate it to a differently rounded expression. Partial stores `bprev*Ofr` and m/l in the unchanged 258-float record, then unchanged merge. The eight sk/sv values belong to keys `sub*16+8*kg+j`, **not** the K operand's supplying key ml. All-zero V retains the previous unit with P=0; all-masked rows never manufacture a 0/0 or NaN. Keep f32 divisions, exp intrinsic, FTZ/rounding mode, partner reduction, sum order, and no new FMA contraction. Moving immutable Q/sq loads changes their lifetime, not their value or quantization.

| Role | Logical VGPR allocation target | LDS ownership |
|---|---|---|
|Consumer|Ofr128 + resident Q32 + current score8 + reused sk/sv8 + operands/P4 + scalar state/predicates/address work about32 = **212**, target <=224; one-ahead score adds8, ceiling **240**|read-only ready slot; one done word; no private O/P plane|
|Producer|one global vector4 + two transpose dwords2 + shuffle/perm temps <=8 + address/epoch/predicates <=24: target <=48 logical live registers|one 4KiB scratch and its two KT16 payload halves; two ready words|

**HIP allocates a single kernel VGPR count at the maximum branch pressure. Producers do not physically get a cheap 48-VGPR allocation while consumers get 224.** No assumed dynamic register donation. Q is sixteen two-dword fragments held across tiles; dc accesses must be compile-time/unrolled to avoid private indexed-array spills. Keep only one current scale file, and at most one optional ahead score. Zero VGPR/SGPR spill and zero scratch are hard gates, target <=224 and ceiling240 for both direct and partial. The baseline's '8 waves' is a compiler register capacity, not eight waves in its four-wave WG or guaranteed residency. With the new LDS/WG shape, derive actual residency from rounded LDS, VGPR granules and block shape; do not add the role budgets as independent hardware allocations.
