# Joint plan: exact XDNA2 GEMM toward 50 TOPS, alongside GPU prefill (historical planning)

> **Historical research note: superseded by the 0.4.2 serving route.** This file records a reconciled planning document (no experiments run) for exact XDNA2 GEMM toward 50 TOPS and GPU co-execution from the 2026-10 NPU research cycle. It is not current guidance, and any figure in it is a dated fixture-bound measurement or an explicitly labelled historical estimate, not a product claim. The shipped 0.4.2 NPU route is the Flash-Next gfx1151 trunk input projection described in [npu-trunk.md](npu-trunk.md): `HIPFIRE_QWEN4_NPU_TRUNK=off|auto|on|emulate` (default `auto`, effectively `off` on every architecture except gfx1151), calibration schema 4, BF16-direct only. There is **no I32 serving contract** (no int32 partial, combine or fold exists in the product route). The out-projection program exists but is **not wired** into serving; `qsa.o` and the GDN o-projection are **not shipped**. Environment-variable names and flag syntax below are historical proposals or experiment switches, not supported configuration.
>
> Its experiment order, window policy, kill thresholds and the co-op (section 8) sync design were planning proposals; none of it became a serving contract.

**Joint plan, 2026-10-02. Planning only.** Two independent analyses were written, cross-read and reconciled: Plan A ([levers-astra.md](levers-astra.md), the V9 resource model) and Plan B ([levers-fable.md](levers-fable.md), the lever space). Detailed derivations and the independent positions remain in those files. This document is the reconciled execution plan. No NPU experiment, build, project test, or code/host/driver change was performed by this planning pass. Arithmetic and a semaphore counterexample were evaluated locally; neither is a performance measurement.

**Decision:** pursue a measured combination of backing-path selection, core-bank scheduling, deeper/earlier operand delivery, and a wider gate_up geometry. There is **no evidenced single 25→50 lever**. Current gate_up geometry cannot reach 50 even with infinite memory bandwidth. Down already has a legal byte-efficient V10, but it was slower; do not promote it without a measured overlap/startup improvement. GPU integration follows a measured exact-kernel win and retains an explicit producer/consumer lifetime contract.

## 1. Evidence and the budget that every lever must meet

Numbers labelled **derived** or **estimate** are not measurements. Useful ops are `2*M*N*K` (`G:1448-1453`); 1 MiB=2^20 B and bandwidth is decimal GB/s (`crates/npu-tools/src/bin/npu-bw.rs:9-15`).

### Exact V9 byte model

From `G:38-126,513-555,574-598,647-674,1291-1334`:

`MW=ceil(M/512); NW=ceil(N/512); kc=K/64; W=MW*NW; Q=W*kc`

`A_DDR = 8*4096*Q; B_DDR = 8*4096*kc*NW; C_DDR = 32*8192*W`

B is fetched once per N-wave; A is still fetched once per M×N wave. Memtile→array A+B is `2*8*4096*Q`. Each injected operand stream fans out to four core DMA consumers; this multiplies **core-received traffic**, not DDR traffic (`G:773-833`). Memtile DMA memory-access volume is `A_DDR+B_DDR+2*8*4096*Q+2*C_DDR`; no single shared SRAM port is assumed.

### Cycle model and binding-resource attribution

The array arithmetic peak is `32*512*2*1.8e9 = 58.9824 TOPS` (59.0 rounded in `report.md:308`; `G:720-732`). Gate_up pads N from 1280 to1536, so its useful arithmetic ceiling is **49.152 TOPS**. Down has no padding (`report.md:340-344`).

The existing straight-through pair schedule averages `(1131+1123)/2=1127` issue cycles/chunk, plus530 per-wave SRS cycles (`C:699-705`). For these shapes `G::estimate_v8` gives `W*(kc*1127+530)+4096`; it explicitly excludes bank stalls, most lock waits, startup and DDR contention (`G:1511-1547`).

| Optimistic current issue-model TOPS | **43.98** | **50.74** |

1357×Q alone yields an optimistic marginal-compute ceiling of **37.09/44.51 TOPS**; it excludes control, epilogue and other waits and is not a second independent timing result (`report.md:416,420`; `C:11-13,699-705`). The report's `1470*Q+5800*W` was fitted to **two different variants/shapes** (`report.md:457-460`); it does not uniquely identify physical chunk and wave costs.

| Resource | What is known to bind or cost time | What a lever can actually move |
|---|---|---|
| DDR/backing path | Aggregate measured plateau; existing gate reads too many bytes to reach50 at55.4; down needs substantial mixed writes too. | Backing/AXI experiments move measured envelope; residency/geometry move bytes/op. |

| Stream switch | Dedicated routes avoid multiple drivers, but a slow destination backpressures its broadcast (`G:814-817`). | Reduce coupling/idle cycles, or change bytes and fanout; cannot infer throughput from route legality. |
| Core/local memory | Bank relocation gave a real gain; residual peer-A/core/DMA conflicts remain (`report.md:408-421`; `C:37-70`). | Balanced A/C visit order can lower marginal chunk cycles; geometry changes useful MAC utilization. |

**Unknown hard limits remain explicitly unknown.** The source assumes4 B/AIE-cycle/channel (`G:1511-1517`), but one shim channel measured11.8 GB/s, exceeding4×1.8=7.2 GB/s. Consequently4 B/cycle is not a valid hard shim bound. Measure memtile→core delivered bytes per AIE cycle separately; do not infer a physical stream width without clock-domain evidence. Under the source's assumed core-lane rate, A and B each need1024 cycles/chunk, core C2048 cycles/wave, and each memtile C drain4096 cycles/wave (4 KiB/8 KiB/two-row sizes from `G:38-85`). Exact memtile-port and switch ceilings cannot be derived from the evidence presently available.

## 2. Ranked top five

Rank is information/value and implementation order, not an additive speedup model. All kill thresholds below are **proposed engineering decisions**, not measured facts. Every silicon experiment gets **one ≤90 s window** under the timing lock (`tools/npu/npu-window.sh`), hard external deadline, prebuilt simulator-exact artifacts and safe teardown. A failed gate abandons the candidate; do not keep tuning an unmeasured idea because its theoretical roof is attractive.

**Incident and recovery policy (project policy, 2026-10-02 UTC evening):** a shim AxQOS=15 probe hung the fabric and SMU resume failed with −22; the test machine was force-rebooted at 22:54:48 UTC, amdxdna initialized cleanly, and the health window matched pre-incident rates (V8 FastSlowCtl 512² exact; gate_up 19.88 busy /16.17 wall, vs `report.md:318`). A wedged NPU is therefore a ~30 s recovery, and hazardous probes are permitted only when informative, **declared first** with exact configuration and wedge risk, run alone and last in their own window, with risky attributes (nonzero shim AxQOS, any non-vendor BD word 5) **rejected by the emitter by default** behind a per-probe opt-in flag. On a wedge: stop, report, the operator reboots; the first window after recovery is the standard health check. AxQOS=15 is a known wedge and is never repeated. No shim-attribute experiment is in the 48 h order. Agents never reboot or reload anything themselves.

### 1 — Resolve the memory path and isolate delivery costs

**Mechanism/owner:** consume the backing-path track's backing matrix, not duplicate it: SHMEM, HIP VMM host dma-buf, device allocation after any migration to GTT, userptr/page-size, shim attributes. At this plan's reconciliation time no replacement bandwidth verdict had been delivered to Plan A; **all three branches below remain live**. Current proven zero-copy path is host-backed HIP VMM, not unmigrated `hipMalloc` (`report.md:376-401`).

**Moved ceiling:** DDR read/write envelope only. The V9 requirements are65.918R+11.719W and54.932R+39.063W GB/s at50; a faster A allocation alone does not accelerate B/C or remove49.152 gate padding /43.98 gate issue-model limits. No predicted TOPS gain is assigned before a measured backing win.

**Two bounded diagnostic additions:**

1. **Delivered link-rate probe:** finite memtile source, exact transfer count, core sink; compare minimally gated sink versus normal two-slot ring, and4 versus8 KiB descriptors. A release-only sink can publish a completion credit per chunk for a core counter, but the source must be finite and counters must stay in their legal range. Finish only after the last sink transfer, then return a normal C completion token. Verify restart/pattern/count semantics in simulation. `bw_probe.rs:32-48` explains why an infinite source corrupts reused contexts with residual stream words. Report bytes/AIE-cycle, not inferred physical width. Extend from one receiver to the actual broadcast if the isolated link is fast: a single fast sink does not exonerate the slowest-destination coupling.
2. **Fixed-variant latency fit:** V9 no-compute at fixed N=2560, K=64/128/320/640 and at least two M values. `T=T0+W*F+Q*c+startup` is a fit, with residuals reported. A fixed-W K sweep alone cannot separate fixed submit startup from per-wave intercept. Never relabel the two-variant1470/5800 fit as a hardware law (`report.md:457-460`).

**Callsites:** `bw_probe::{BwConfig,design}` (`crates/peacemaker-npu/src/kernels/bw_probe.rs:85-107,317-329`); `npu-bw::run_config` (`crates/npu-tools/src/bin/npu-bw.rs:51-121`); `Device::import_dmabuf` (`crates/railgun/src/npu/mod.rs:342-380`); V9 dispatch `crates/npu-tools/src/bin/npu-gemm.rs:493-497`. The backing-path track owns live AXI/backing changes; use its measured table and source snapshot rather than editing behind it.

**Kill window:** same-clock/backing pure read, verified write, mixed traffic and same V9 real/no-compute. Reject a gain due only to cache warmup, changed bytes, migration relabelled “fast VRAM”, or altered verification. A port-limit diagnosis needs the matrix, not the LPDDR spec. Link probes are timing diagnostics, never exact-GEMM TOPS.

### 2 — Balanced Upper-core A/C half order

**Mechanism:** both pair cores currently access the same E/O owner's A bank at the same scheduled times. For `PairRole::Upper`, exchange E/O A visit order **and matching C-row load/store pointer ownership**, leaving final C memory order unchanged. This is a steady-state complementary order, not a one-time phase delay that the peer barrier erases. `C::{pair_a_bases,chunk,wavefront}` at709-714,483-517,413-471; peer protocol721-778; caller `program_pair`855-896.

**Moved ceiling:** the measured ~1357-cycle compute-region marginal cost, toward ~1067/1070 issue cycles (`C:11-13`; `report.md:416-420`). If an estimated half of290 stalls disappeared,1357→about1210 implies marginal-compute-only41.6/49.9 TOPS, **not end-to-end predictions** (Plan B estimate). Existing optimistic full-schedule ceilings remain43.98/50.74 and DDR/geometry still apply. No byte counts change.

**Frozen contract:** same acquired A/B generations, same increasing-K accumulation, first-chunk overwrite, signed SRS floor/saturate, same descriptors/routes/packed-C byte positions. Do not remove peer lifetime notifications. The implementation may need more than pointer swaps once loop offsets are traced.

**Kill:** simulator pair/array exactness, decoded issue/rule check, bank-access trace. Then one window: exact V9 baseline/candidate plus repeat2/3 slopes, explicitly non-GEMM for repeat probes. Abandon if slope remains≥1330 cycles or exact wall time fails to improve beyond baseline variation. Do not promote a trace-only win.

### 3 — Ordered memtile A depth; prefix-ready B for V10 down

These are separate, independently measurable descriptor experiments. They may share code files but must not be combined before attribution.

**3A, V9 A ring:** move A staging to a contiguous depth8 or16 ring in the free tail, one iteration-stepped producer BD and one consumer BD, with one ordered empty/full semaphore pair. At gate kc40, resident B ends at0x64000;112 KiB remains (`G:317-333`). A16 ring takes64 KiB. Predicate `0x14000+2*kc*4096+D*4096 <=0x80000` must hold; baseline layouts remain explicit for unsupported K. Keep B/C offsets, core buffers, host packing and routes unchanged. Producer/consumer task starts remain on the current A channels; use available odd/even BD IDs, not an unproved allocation.

**3B, V10 down B prefix:** current `mw_outer_operand_descriptors` fills all B then releases MW credits (`G:148-174,979-1005`). Replace that barrier with **per-chunk fill readiness** and a guarded first replay covering the entire `NW*kc=50`-chunk segment. Queue a first finite replay task repeated50 times, then a whole-segment read-only task repeated`MW-1=7` times, subject to descriptor/task limits. The first pass's completion proves all B resident before unguarded repeats. B stays immutable for the submit. Fill must itself release readiness per chunk; merely changing the consumer cannot make the existing whole-segment producer prefix-ready. Reset/rewrite both tasks and iteration phases at each submit.

**Moved ceilings:** depth moves overlap/waiting, not bytes/op; current V9 real→DMA-only gap is a diagnostic target31.21/25.19, not a hard future ceiling if DMA itself changes. Read roofs42.02/50.43 remain until traffic/backing changes. V10 down reads4.0625 MiB: read-only roof174.55 TOPS, required15.869R+39.063W GB/s at50, while the current TN64 optimistic issue-model limit is50.74. Whole-B-ready delay has a **derived bandwidth floor**1.5625 MiB/55.4 GB/s=29.574 µs on this path, about5% of observed V10's0.584 ms (`report.md:450`); prefix streaming can overlap some of it, not guarantee a fixed gain or solve the array limit. Existing V10 slower-than-V9 evidence remains the adoption gate.

**Callsites/ownership:** `G::{nw_outer_operand_descriptors,mw_outer_operand_descriptors,resident_descriptors,memtile_locks,ring_tasks,build_txn_dynamic}` at941-1005,1120-1207,1358-1408. `design_v9/design_v10` at1637-1669 own geometry predicates. CDO and TXN descriptor generation must remain one source of truth.

**Kill:** exact multiwave/repeated-context and asymmetric-backpressure simulation first; verify traffic totals, BD-bank IDs, address bounds and phase resets. One window per descriptor experiment: depth2/8/16 real+no-compute, or V10 baseline/prefix real+no-compute. Proposed gate: depth must improve no-compute≥10% **and** real wall time; prefix must improve real wall≥3% beyond noise. Otherwise abandon. If an isolated locked sink is at line rate, do not claim DDR-latency recovery; test actual broadcast coupling before discarding all queue-depth ideas.

### 4 — Gate_up-only 256×1280 wave, 128×80 core tile

**Why this replaces the tail-only idea:** a homogeneous narrow wave increases A rereads; Plan A's tail remap keeps A30 MiB and a42.81 read-only roof. Plan B's wider wave removes padding **and** makes gate_up one N-wave. This is the highest-ceiling structural lever, but it is a **simulator/paper feasibility project, not a promised kernel**.

Proposed mapping: core `(column c,row r)` owns M tile`r/2`, N tile`2*c+r%2`, giving256 rows×1280 columns over32 cores. Keep signed int8×int8→int32 exact semantics. There are16 M-waves, kc40,640 per-core chunk steps, each1280 VMACs. Four A-half injection streams cover the256-row wave; route the halves to all required columns. Each memtile must supply **two independent5 KiB B streams/chunk**, one to each row parity, not serialize them through the old single B channel. Two B MM2S +one A MM2S where needed +two C drains fit a six-channel budget only after BD-bank and switch-route proof. With one four-byte B lane,2560 cycles/chunk would cap arithmetic at**29.4912 TOPS**, defeating the idea (derived from `C:77-82` sizing and the proposed tile).

| Conditional traffic/roof, derived from proposed geometry | gate_up |
|---|---:|
| DDR A /B /C | **10 /3.125 /5 MiB** |
| Read /write bytes per useful op | **0.0005126953125 /0.0001953125** |
| Total DDR bytes | **18.125 MiB**, vs V9 39.75 |
| Read-only roof at55.4 GB/s | **108.06 TOPS** |
| At50: required read +write | **25.635 +9.766 GB/s** |
| Useful MAC ceiling | **58.9824 TOPS**, no padded work |
| All-in budget per1280-VMAC chunk | **1509.95 cycles** |

These numbers are arithmetic, not a claim the mapping has legal/sufficiently fast routes. New issue/control/bank cycles must be measured; do not reuse the old1127 constant for a larger tile.

**Capacity and lifecycle gates:**

- Per-core C40 KiB +two A halves8 KiB +two B slots10 KiB =58 KiB. A separate10 KiB Cout would overflow64 KiB. Proposed reverse-order in-place SRS writes output into C's upper10 KiB: relative destination`30720+64*j`, source block`256*j..256*(j+1)` for`j=159..0`. Load the whole current block before writing; destination never overlaps still-unread lower blocks. Preserve DMA's expected ascending packed-C order even though conversion executes backwards.
- That within-epilogue proof is **not** next-wave safety. Start the next wave only after `C_EMPTY` proves the previous Cout drain finished, unless a separately proved finer-grained scheme exists. At the assumed4 B/cycle,10 KiB drain is2560 cycles per wave, an estimated exposed penalty. It is not free overlap.
- C40 KiB touches at least three16 KiB double-bank windows; A8+B10 do not fit a wholly disjoint remaining16 KiB. A/B or C bank conflicts are unavoidable under a naive map; the new bank trace is a veto gate (`C:37-70,129-134`).
- Gate memtile B400 KiB +double-buffered C80 KiB leaves**32 KiB** before A, including in non-injecting columns—not112 KiB. A staging16–32 KiB gives496–512 KiB used. Prove every actual offset/BD/lock, including both B streams, before coding the schedule.
- Whole-B-ready startup would cost at least3.125 MiB/55.4 GB/s=**59.148 µs**,11% of the536.871 µs target. Use prefix-ready B only with **separate ready credits for the two B streams**. A single fill channel needs a legal alternating/strided descriptor plan to publish the two streams independently; each first pass proves residency before later unguarded replays. No shared `FULL+=2` shortcut.

**Down stays TN64:** V10 already gives the same all-once read4.0625 MiB without TN80's in-place-C penalty (`G:140-147`; `report.md:444-460`). A hypothetical TN80 down with whole-B startup, even MAC-only+minimum640-cycle epilogues+last5120-cycle drain, requires about488433 cycles at the measured read plateau, exceeding the483184 budget; it is not the recommended down route. Use lever3B and core improvements first.

**Implementation boundary:** one geometry owner changes `C::{wavefront,chunk,epilogue,program_pair,tile_bds_pair}` and `G::{Geometry,pack_a_pair,pack_b,pair_c_offset,unpack_c,pair_column_circuits,resident_descriptors,emit_shim,design_pair}` atomically. Existing callsites: `G:1674-1694` calls `program_pair`; `crates/npu-tools/src/bin/npu-gemm.rs:493-497` selects designs; `ArrayDesign::{pack_in,unpack_out,reference,output_tile_ranges}` at1460-1491 own the public byte/verification contract. Introduce an explicit experimental design selection, not silent mutation of V9 or global TM/TN used by older variants.

**Kill:** simulator-only memory/BD/lock/route and exactness proof first, including two B readiness streams, reverse SRS, repeated-context and tail input cases. Abandon if the capacity/critical-path proof fails, if the program exceeds16 KiB (`G:1676-1678`), or if new bank conflicts erase the cycle budget. Only a surviving design gets a single ≤90 s gate_up baseline/candidate exact+no-compute window. Require useful busy **and wall** improvement beyond same-window variation; then compose with prior winners and remeasure. No40–45 or50 claim before silicon.

### 5 — Real GPU producer buffers and byte-aware co-scheduling

**Moved ceiling:** application staging/coordination and contention, not standalone NPU arithmetic. Proven host-VMM dma-buf path measured22.65 vs normal22.70 TOPS in the older layout—zero-copy was not a kernel speedup (`report.md:388-400`). Current concurrency baseline is GPU pp8192 **5563.3→6126.3 ms (+10.1%)**, NPU **25.60→22.16 TOPS** (`report.md:466-475`). These do not predict a new schedule's performance.

Use the actual producer to create the exact packed A layout, not a synthetic host upload timed outside the application. Record producer/packing duration, NPU busy+wall, GPU prefill distribution and completed useful expert work. Byte-efficient geometry reduces traffic at equal useful TOPS; running the NPU faster can increase instantaneous fabric demand, so traffic savings do not imply proportional contention savings. Scheduling by GPU phase is an unmeasured option only after identifying bandwidth-light phases; do not assume attention is always such a phase. AXI QoS results belong to the backing-path track, and any concurrent QoS win must include the GPU cost.

**Ownership interface:** one exported buffer has one live imported `Bo`; immutable shape/layout/epilogue metadata accompanies it. `Free → GPU-writing → producer-complete/visible → NPU-in-flight → NPU-complete → consumer-complete → Free`. Producer completion precedes submit; NPU timeline completion precedes overwrite or GPU consumption; all consumers precede teardown. `Device::import_dmabuf` owns GEM mapping/handle, not caller fd, and repeated imports on one device can return the same handle (`crates/railgun/src/npu/mod.rs:342-380`). HIP allocation/VA/fd lifetime exceeds imported BO and contexts (`npu-gemm/src/hip_dmabuf.rs:17-24,290-305`). Import is not an implicit GPU execution fence. The existing CPU-fenced path remains an explicit valid mode until an interop fence is proved.

**Callsites:** producer helper `HipDmabufA::{create,build}` (`hip_dmabuf.rs:202-268`), argument import (`crates/npu-tools/src/bin/npu-gemm.rs:563-590`), `HwCtx::{submit,wait}` (`crates/railgun/src/npu/mod.rs:420-468`). Preserve packed A contract from `G::pack_a_pair`574-598. A GPU packing kernel does not itself remove repeated NPU DDR reads.

**Kill window:** after a measured exact NPU win, one preloaded ≤90 s GPU-alone/NPU-alone/concurrent comparison with finite in-flight slots, first/final exact outputs and changed producer data between uses. Reject stale data, premature reuse or schedules that fail an explicit application latency/throughput and GPU-slowdown policy. The previous240 s exception is not inherited. Do not add unlike GPU/NPU TOPS or use the report's inferred241-TOPS break-even as model-level acceptance (`report.md:472-475`).

### State invariants before and after every DMA transition

1. **V9 resident B baseline:** initialize empty2/full0 and both slot indices0. Fill reserves an empty credit, writes slot`j%2`, publishes full only on completion. Replay reserves full once, consumes allMW passes of that slot in strict order, releases empty only after its final read. Thus `empty=2-fills_started+replays_finished`, `full=fills_finished-replays_started`; no overwrite of an active reader (`G:103-125`).
2. **One-producer/one-consumer A ring:** initialize emptyD/full0 and both indices0. Fill reserves empty → writes complete chunk → publishes full. Consumer reserves full → completes all reads → returns empty. `empty=D-fills_started+reads_finished`, `full=fills_finished-reads_started`; both sequences use the same `seq%D`. This shared counter is safe because consumers cannot steal one another's generations.
3. **Pair core A ownership:** own A must be ready before peer notification. Both cores read only the same agreed chunk/slot generation. Own A is returned to DMA only after own final read and peer acknowledgement; B is returned after own last B read. Maintain first-chunk overwrite and all later accumulation (`C:719-778,855-895`).
4. **Prefix B:** fill-chunk completion creates exactly one ready credit for that stream's first-pass reader. First pass consumes every chunk in order; only its completion permits lock-free replay of the whole immutable segment. Gate G80 has two independent B readers/ready streams, so no shared ready pool. No write to retained B before final replay/submit completion.
5. **C:** baseline int8 has separate Cout; acquireC_EMPTY before conversion, publishC_FULL only after SRS stores retire, returnC_EMPTY only after DMA finishes reading. G80 overlays C/Cout, so the next wave must acquireC_EMPTY **before any store that could overwrite prior Cout**, conservatively before its first chunk. Reverse conversion must never clobber an unread i32 block (`C:785-847,849-895`).
6. **Submit/reset:** prior completion is a precondition. Halt/reset cores; reset persistent core/memtile channels, never shim; rewrite stateful descriptors because iteration `current` survives channel reset; initialize every lock and program index; PC0; queue rings/finite tasks; enable cores last; wait for both C channels across all eight columns. Sources `G:176-191,1337-1408`. No phantom source words may remain in switches (`bw_probe.rs:32-48`). Timeout is not completion: quarantine the buffers/context and perform controlled teardown, not reuse.

**Rejected shortcut with a concrete counterexample:** `A_FULL+=2` shared by two cores is not generation-safe. With both slots initially holding two ready credits, a fast core can consume slot0 once, slot1 once, then consume the slow peer's remaining slot0 credit as a new chunk before DMA refills it. Both plans withdrew this proposal. The current pair functions emit **eight** lock operations; the nine-step description includes compute (`C:719-778`). A counting-empty optimization with independent readiness is separate, small and outside the first48 h; do not sneak it into the bank experiment.

## 8. CoOp: gfx1151 + NPU as one PM-scheduled machine

Requested framing: frame co-op as a **speed lever** for Flash-Next pp8192 on the Halo, in ms saved per step, with the NPU adding throughput on top of the GPU's ceiling, PM owning both devices, and GPU-driven (railgun-style) dispatch to the NPU over a shared fast-memory ring. ### 8.1 What GPU work can move, and the step-time model

**Only the routed-expert IU4 GEMMs are int-exact candidates.** On the default IU4 route the per-layer MoE is `qwen4_moe_rotate256_i4` (FWHT-256 + `block_i4_128` activations) → `gemm_qwen4_moe_gate_up_silu_iu4_sym` → `qwen4_moe_rotate128_i4` → `gemm_qwen4_moe_down_iu4_sym` → `moe_down_combine_grouped_top10_bf16in` (`crates/hipfire-dispatch/src/pipeline/qt44_qt53_prefill.rs:432-446,650-672,748-762`). Everything else in the step (MQ6 trunk 1421 ms, BF16 HC-down 413, HC non-GEMM 446, QSA 358+73, GDN 218, shared experts 103+128: `fn-halo-2500.md:41-62`) is BF16/F32 arithmetic the int8 array cannot reproduce exactly. A8 (W4A8, opt-in, `fn-halo-2500.md:75`) would also fit int8×int4 but is not the default route.

**Shape reality:** per expert and layer the average row count is `8192*10/512 = 160` (`fn-halo-2500.md:35`), not the 4096 of the NPU benchmarks (`report.md:79-80`). The current 512-row wave pads 160 → 512, so the NPU's useful MAC ceiling at expert slices is **18.44 TOPS** (`58.9824*160/512`), 36.88 with a 256-row wave; measured 25.36 at M=4096 does **not** transfer. Weight streaming bounds it too: per expert gate_up+down is 4,915,200 parameters, i.e. **2.46 MB int4 / 4.92 MB int8**; at 160 rows that is 640 useful ops per int4 byte or 320 per int8 byte, so at the measured 55.4 GB/s plateau the weight-stream roof is **35.5 TOPS with native int4 B** and **17.7 TOPS with int8-expanded B**. All 512 experts of all 48 layers are **60.4 GB int4 per step**; the NPU's share must stream its fraction every step, exactly as the GPU does. Consequence: consuming the model's int4 experts natively on the NPU (Plan B L5, `AIE2PInstrPatterns.td:35-38` `BMODE_8x4`, output shape unverified; or in-core nibble expansion at a core-cycle cost) is **mandatory** for co-op, and it is not a precision change: the experts are int4 at rest (symmetric `zp == -8*sc`, `CHANGELOG.md:12`), so the exact reference is int4×int4 → int32 either way. §6's "int4 outside scope" applies to the standalone 4096-row benchmark contract only.

### 8.2 Sync and kick: what the sources allow

**NPU → GPU completion (Q1).** NPU side: feasible as designed today. Each shim S2MM channel is length-driven and in order (FoT disabled, `G:34-36`), so a finite done-record BD queued after the C-stream BD on the same channel writes a word only after that channel's C bytes have been issued; there are 16 C channels (`G:80-83`), so the GPU must wait on 16 words (or the controller core must join the 16 drains before one word). GPU side: railgun/redline already emit `WAIT_REG_MEM` memory polls (`crates/redline-rocr/src/pm4_gfx10.rs:430-446`, `crates/redline/src/dispatch.rs:276-281`) and `RELEASE_MEM`/`WRITE_DATA` publishes (`pm4_gfx10.rs:393-428`). Two gaps: (a) **visibility** — the NPU writes DDR non-coherently with the GPU's caches, so the polled word must be read system-scope by the CP and the C data needs a GPU-side acquire before the consumer dispatch; railgun's boundary model has the `System` rung but **no gfx1151 G4 receipt** (`crates/railgun/src/plan.rs:24-28,79-89`); (b) **AQL is not interchangeable** — `BarrierAndPacket` takes HSA signal handles (`crates/redline-rocr/src/packet.rs:328-391`), not raw dwords, so the AQL route needs an imported or interrupt-backed signal; the PM4 wait is the direct path. Kill (one ≤90 s window, after a simulator proof of the done-record ordering): poison C, GPU `WAIT_REG_MEM` on all 16 words + system acquire + a GPU checksum kernel over C versus the CPU reference; any poison seen after all words = ordering/visibility failure → the NPU cannot publish without a GPU-side fence it does not control → fall back to the host syncobj, which stays the only path that reports NPU errors (`aie2_ctx.c:348-365`).

**GPU → NPU kick without the CPU (Q2).** Verified in the 7.0 driver: every command enters through `EXEC_CMD` → `drm_sched` → `aie2_sched_job_run` → mailbox (`aie2_ctx.c:281-331`); `ERT_CMD_CHAIN` is implemented (`aie2_ctx.c:316-317` → `aie2_cmdlist_multi_execbuf`, `aie2_message.c:962-1027`; chain buffer `MAX_CHAIN_CMDBUF_SIZE = SZ_4K`, `cmd_chain_slot_npu` 52 B + args, `aie2_msg_priv.h:364-396` — the railgun runtime derives ≤36 START_CU per chain); `force_cmdlist = true` already routes single submits through the chain path (`aie2_ctx.c:26-28`); a job times out at **60 s** and the context is stopped and restarted (`aie2_ctx.c:30,348-365`). The uapi carries `umq_bo`/`umq_doorbell` (mirrored in `crates/railgun/src/npu/mod.rs:89`) but the aie2 driver never reads them (source grep): **option (b), a GPU-written doorbell, is a driver change → proposal only**; writing the mailbox MMIO from the GPU is additionally unsafe because message ids are kernel-managed (Plan B: `amdxdna_mailbox.c:157-173`). Option (c), the CPU relay, exists today: one `ERT_CMD_CHAIN` per layer-phase and one syncobj wait; measured per-submit host overhead in the NPU loops is ≈7 µs (wall − busy at `report.md:436`), so a relay handoff is of order 10–50 µs (estimate) before the GPU-side word write.

Option (a), the persistent ring, is the design chosen; it is **offline/desired, not an existing API**, and has three proof gates. The railgun runtime's frozen ABI: shared dma-buf in HIP VMM host memory, 64 B lines; line 0 header `{magic 'RGNP', ver 1, nslots (pow2), slot_bytes 64}`; line 1 the done word `{u32 done_seq (NPU writes, monotonic, after the slot's C), u32 status}`; slot `i` at `4096 + 64·i` = `{u32 seq (written last), u32 prog, u32 m, u32 flags, u64 a, u64 b, u64 c, u32 k, u32 n}`. Producer (GPU PM4): `WAIT_REG_MEM(done_seq ≥ seq − nslots)` for a free slot, `WRITE_DATA` body, `WRITE_DATA seq` (write-confirmed); consumer wait `WAIT_REG_MEM(done_seq ≥ seq, GEQ)`. GPU owns slot bodies and seq words, the NPU owns the done line only. NPU side (proposal, simulator first): nothing on-chip can wait on a DDR word (shim BDs gate on shim locks that neither cores nor memtile DMAs can touch, `G:80-83`, `C:111-120`), so a **dedicated controller core** polls: a self-looping shim MM2S BD re-reads the next slot line into that core through the memtile, the core compares `seq`, and on a match programs the shim BD addresses/lengths and pushes the task queues **via control packets from its stream master to the shim's TileCtrl port**; the done record is an S2MM BD queued after the last C BD. Gates: (1) the core→shim control-packet register-write/queue-push path must be shown in the ISA/aie-rt references and the simulator before silicon — without it, a data-only ring is unsafe because the shim would prefetch a slot's A bytes before the GPU wrote them (`bw_probe.rs:32-48` shows the residual-word hazard of any unbounded source); (2) one done word on one channel cannot certify the other 15 C channels; (3) 32-bit `seq`/`done` need an epoch/reset before wrap and the done sequence must never skip an unfinished slot; (4) a never-completing context versus the 60 s watchdog: the design must complete its job (a TXN without `SYNC`) and leave rings live, and a later submit on any context must not reset them; (5) one chain per step is not generic — ≤36 commands per chain and the producer dependencies inside a layer need several chain epochs; (6) the controller costs one of 32 cores (31/32 in §8.1).

**Sync cost in the model.** Per layer the minimum is two handoffs (kick after the GPU's `rotate256_i4` produced the NPU rows; wait before the combine); four if the inter-GEMM producer runs on the GPU (§8.3): **96–192 handoffs per step**. Ring path: `H_sync` ≈ poll period + CP poll, a few µs (estimate) → ≈ 0.2–1 ms per step. Chain relay: 10–50 µs (estimate) → ≈ 1–10 ms per step. Sensitivity on the P = 25 row: `H_sync` = 20 µs → 186.7 ms saved; 200 µs → 169.4; 2 ms → −3.4; so **the kick mechanism is not the speed determinant at pp8192**; it decides CPU load and robustness, and it would matter for decode-scale work, which is out of scope. The persistent ring should be adopted for elegance only after the relay version has shown the gain exists.

### 8.3 Bit-exact reproduction of the IU4 route (Q3)

The integer core matches: per K128 epoch the GPU forms the exact int32 chain `C_h` (A nibbles rebiased by XOR 0x88888888, `|C_h| ≤ 8192`) seeded with the magic 0x4b400000 (`qwen4_moe_sym.rs:25-29,386-411`); an int8 MAC over the same int4 values gives the same `C_h`. The epilogue does not match as-is: `sum = fma(RN(d_h·sc_h), C_h − 12582912.0, sum)` from +0 in ascending epoch order, then BF16 RNE, then for gate/up `rt(silu(rt(g))·rt(u))` with the hipcc `g/(1+expf(−g))·u` DAG (`qwen4_moe_sym.rs:25-33,462-470`). What AIE2P offers (`ref/llvm-aie/llvm/lib/Target/AIE/aie2p/AIE2PInstrPatterns.td`): fp32 **accumulator** add/sub (`VADD_f`/`VSUB_f` with `AMODE_FP32`, lines 69,249-259), multiplies with **bf16 inputs** only (`VMUL_f_vmul_bf…`, 262-279), bf16↔fp32 conversions (1140-1148); no fp32×fp32 vector multiply or fma pattern. The obligations and their status:

1. `RN(d_h·sc_h)`: both are f16 (11-bit significands), so the product is exact in f32 and can be formed by integer significand multiply — reproducible.
2. The fma: `p·C_h` has up to 38 significant bits, so a single-rounded fma cannot be built from one fp32 add; exact emulation needs integer or error-free-transformation sequences whose IEEE-RN equivalence and denormal/tie behaviour must be proved against the GPU, and whose cost is an estimate of the same order as the GEMM itself on the vector unit (scalar-unit emulation is prohibitive). This is the parity gate; today it is **unestablished**.
3. BF16 RNE and the final multiply/round: integer ops — reproducible given 2.
4. SiLU: the input `rt(g)` is BF16-valued, so a **65,536-entry f32 table generated on the GPU by the production kernel's own DAG** reproduces `silu(rt(g))` bit-for-bit by construction (precedent: the exhaustive 2³² SiLU proof in `CHANGELOG.md:500`); only the final `·rt(u)` multiply and RNE remain.
5. Producers stay on the GPU: `rotate256_i4` (A4 quantization with the {5,7} candidate search) and `rotate128_i4` are f32 kernels; the NPU writes its gate/up rows as BF16 into the shared `Y_grouped`, the GPU's existing per-slot `rotate128_i4` covers those rows, and the NPU reads the resulting `xq` for down. Cost: two extra handoffs per layer (§8.2) and GPU time already in the glue bucket; benefit: no f32 FWHT or quantizer parity on the NPU.
6. Layouts: the NPU consumes GPU-produced `block_i4_128` activations and QT44/QT53 expert tensors; a GPU packing kernel must write A in `pack_a_pair` order (`G:574-598`) and the NPU's expert range must be stored in `pack_b` order at load (`G:647-674`), with int4 nibble consumption per §8.1.

**Verdict:** bit-exactness is *possible in principle* (integer core exact, table SiLU, GPU producers) but hinges on an exact fma emulation whose cost may erase the gain; if it fails, the only remaining form is a **non-bit-exact NPU expert route admitted under a quality gate**, like the lossy trunk (`fn-halo-2500.md:72`), which this plan does not request. Kill order: (i) CPU model of the planned NPU epilogue versus the GPU kernel bytes on captured expert tiles (W4A8 fixture precedent, `fn-halo-2500.md:75`); (ii) simulator-exact NPU epilogue against that model including denormals and ties; (iii) one ≤90 s window on silicon comparing NPU bytes with the GPU's on real tiles. Any byte mismatch, or an epilogue cost above ~25% of the GEMM time (estimate threshold), kills the bit-exact route for the 48 h.

### 8.4 Shared LPDDR5X budget (Q4)

M4 measured GPU **5563.3 → 6126.3 ms (+10.1%)** while the NPU ran V9 gate_up at **22.16 TOPS** (≈ 29 GB/s read + 5 GB/s write) and lost 13% itself (`report.md:466-475`). The speed framing makes the "net positive" condition explicit: with contention confined to the overlapped expert phases, co-op is net positive for any `P ≥ ~4 TOPS` at expert shapes (the `f` balance absorbs the 10.1%); with contention over the whole step it is net negative below `P ≈ 45` (374 ms penalty versus the table). The condition is therefore **traffic placement**, not a GPU useful-rate threshold; the report's 241-TOPS break-even (`report.md:472-475`) was an inference for the standalone-NPU framing and does not apply here. Work the NPU should take: compute-dense relative to its *own* bytes — the expert GEMMs are 640 ops per int4 weight byte at 160 rows, which is why native int4 B is mandatory (§8.1); the trunk (M = 8192, bandwidth-light) would be ideal but is MQ6/BF16 and not int-exact. Kill: an M4-style window with the GPU running its *expert share* (not an idle pp8192) and the NPU streaming its slice; record GPU slowdown and NPU rate; reject if `slowdown·phase > saved`.

### 8.5 PM integration shape (Q5)

One author layer, two backends: `peacemaker-author` already types targets and capabilities (`Gfx1100/1151/1201`, `MmaIu4`, `SplitBarrier`; `crates/peacemaker-author/src/target.rs:56-115`), LDS ownership states and `Pending`/`Drained` tokens (`lib.rs:9-18`), with `peacemaker-isa`'s `Builder` as the evaluator; the shipped IU4 kernels re-emit byte-identically through it (`CHANGELOG.md:28`). An `Aie2p` target would add: the core data memory as the ownership domain (8 single-port banks, `C:37-70`), DMA/lock acquires as the wait model instead of counters, `MmaI8x8` (8×8 int8, `docs/gemm_i8.md:9-23`) as the MMA capability, and `peacemaker-npu`'s `Assembler` (`C:242-333`) with its `isa::rules` gate as the backend. Cross-device handoffs as typed ledger resources: railgun's `Resource`/`Binding`/`Effect` and the boundary `Visibility`/`Hazard` rows (`crates/railgun/src/lib.rs:77-123,199-205`; `plan.rs:38-77,263-272`) gain a device axis and two new edge kinds — *GPU-write → NPU-read* (GPU `RELEASE_MEM` write-confirm + ring publish) and *NPU-write → GPU-read* (done word + `System` acquire) — each an open obligation until it has a gfx1151 receipt (`plan.rs:79-89`). The dispatch side is an EP-style exactly-one-owner expert partition (`crates/hipfire-arch-qwen35/src/qwen35/config.rs:526-532` is the existing contract shape) with the NPU as the second owner. Kill for the integration shape: the existing V9 program must re-emit byte-identically through the typed layer (M0's standard), and the two cross-device rows must each pass a receipt probe before any product route uses them.

### 8.6 Rank against the single-device levers, and order

Co-op's *potential* (≈100–190 ms per step at `P` = 15–25, up to ≈330 at 50) exceeds every exact single-device GPU lever except the lossy trunk, but it carries three unresolved gates that none of the §2 levers has: expert-shape throughput (`P` unmeasured; current geometry ceilings 17.7–18.4), epilogue parity (§8.3), and real-profile contention (§8.4). The §2 NPU levers remain the prerequisite: they raise `P`, and G80's 256-row wave is also the right shape for 160-row experts. Order: (1) measure `P` at 160-row shapes with the existing V9/V10 and int8-expanded B (one window, immediately informative); (2) CPU parity model of the epilogue (offline); (3) relay-based (chain) single-layer prototype with GPU producers, exact versus the GPU route; (4) real-profile contention window; (5) persistent ring and typed cross-device rows afterwards. If (1) gives `P < 10` and the native-int4 path is not available, co-op falls below HcDownTile in ms per engineering day and should wait for the single-device levers.
