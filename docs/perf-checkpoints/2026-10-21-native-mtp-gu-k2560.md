# Native PD: exact K2560 GU control specialization

## Decision

Adopt the literal-K2560 inverse R2 entry for the existing gfx1151 few-row
GU admission. This removes runtime control/address work while preserving
the existing FP32 arithmetic and storage contract. The user explicitly
prefers retaining proven work elimination after correctness and regression
checks, even when a small speed difference is not stable.

**No stable kernel or whole-model speedup is claimed.** Three isolated
packet timings are flat. Formal AR is 33.7 -> 33.7 tok/s; MTP is
52.8 -> 53.6 tok/s, with walltime-dependent scheduling and differing tau.
This is a local source checkpoint, not a merge, admission-row update or push.
The full GPU-NPU Prefill + AR/MTP Decode effort remains active; the old
complete NPU drafter direction stays stopped.

## One production lever

The new exported entry
`gemm_mq4g256v2_moe_grouped_top10_o4_r2_x4_inverse_k2560`
calls the existing inline `grouped_top10_o4_body<2, true>` with literal 2560.
The original body and three exported entries remain present. Registry adds
the entry; the existing exact-shape Rust API selects it. Native admission
remains gfx1151, M1280/K2560/divisor10, N1..8, F32 and pad16. No scheduler,
quantization, unroll pragma, allocation, copy or synchronization change.

Six pointers plus six i32 retain the 72-byte logical ABI. Block128,
`__launch_bounds__(128,2)`, inverse even-leader ownership, grid
`[ceil(M/16),total_slots]`, empty-pair no-store, padded sibling +0 and guard
rules remain. The four FP32 chains, eight-term expression, g&3 assignment,
`(c0+c1)+(c2+c3)` and lane reduction are unchanged. M, divisor, grouped
rows, expert count and slots remain runtime values.

| Compiler metadata / bounded function | Original inverse R2 | Fixed K2560 |
|---|---:|---:|
| Function bytes | 11,700 | 8,724 |
| VGPR | 111 | 107 |
| SGPR | 47 | 38 |
| LDS bytes | 2,048 | 2,048 |
| Scratch bytes | 0 | 0 |
| HIP active workgroups/MP, block128 | 12 | 12 |

There is **no occupancy increase** demonstrated. Weight bytes and FP32
MAC count are unchanged. ISA uses fixed 0x550 weight and 0x2800 X row strides;
the quad loop still exists. Tail control narrows to groups8/9 but retains
counter==10, bit0 and prefetch control: not every branch/tail disappears.
Only the executed function shrinks; retaining the old exports increases the
whole module and frozen daemon slightly.

Bounded raw function bytes for all three old entries are unchanged on
gfx1151. gfx1100 and gfx1201 compile-only comparisons also preserve their
three old entries; those targets have no new hardware/performance claim.
The production entry equals the isolated alias byte-for-byte. Actual runtime
JIT source and all four bounded functions equal the hand-built production
object. New function SHA256:
`34519688041bc60311c4f3e96359f48b78377aad7c09af22f159b34ef734b53a`.
