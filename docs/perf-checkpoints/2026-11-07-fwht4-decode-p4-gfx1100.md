## P4b: GQA-shared decode tile (PARKED — correct but slower)

- New kernel (`attention_flash_fwht4_tile_gqa.gfx11.hip`): one 256-thread
  workgroup per (kv head, tile); K tile resident in LDS once, V in 16-key
  LDS slabs, Q rotated at stage-in; same partials ABI (existing reduce).
- Correctness proven: `tmp_fwht_gqa_oracle` (lab-gated) is **bit-identical**
  vs the scalar tile on T=1/2/16/17/32/128/256 × q8/lloyd4 synthetic
  inputs; greedy battery 10/10 vs scalar.
- Perf: long-ctx (92K prompt) decode 28.65 → 16.2 tok/s (**-44%**),
  short 49.1 → 48.0 (-2%).
- Why it loses: the 6× traffic cut is real but LDS staging + barriers +
  256-thread workgroups collapse occupancy (30 KB LDS → 2 WGs/CU), while
  the Infinity Cache already absorbs most scalar re-reads. Revival would
  need occupancy work first (smaller LDS footprint, double-buffered fill).
- PARKED: dispatch arm reverted to a comment; nothing slow ships. Kept
  with the oracle as reference. Debug trail: K staging must gather
  per-head (a contiguous copy reads the wrong head past key 0 — caught by
  the oracle, not by KLD); LDS budget is 64 KB total incl. dynamic;
  entry symbol must match the launcher lookup.
