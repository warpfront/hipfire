# Model-load refusal wording inventory (0.4.3)

Status: **shipped / ref-pinned** for the strings listed as *rewritten*; the other sections record the audit scope.

Scope: `crates/hipfire-runtime/src`, `crates/hipfire-loader/src`, `crates/hipfire-cli/src`. A string is in scope when a normal user can reach it by loading a model with an ordinary setting, flag or model file: admission refusals, config/flag conflicts, VRAM/RAM fit, GPU-support gaps, and damaged or incompatible model files. Developer-only variables, internal invariants, serve request validation and other crates are listed as excluded.

Method: every string literal of 30+ characters in non-test code of the three crates that carries a refusal/failure keyword (`refus`, `cannot`, `unsupported`, `must`, `requires`, `invalid`, `failed`, `missing`, `mismatch`, `exceed`, `truncat`, ...) was extracted (1,302 candidates) and classified by reachability. Rule applied to each reachable string: say what happened, name the setting/flag that changes it (or the command that repairs the file), keep internal symbol names out, keep the semantics (same loads refused/admitted) and keep the stable tokens below.

## One sentence per parallelism axis

Every refusal of a split the model family has no route for is built by `hipfire_runtime::loader_api::topology_refusal(family, axis, degree, is_dir)`, so the three axes read alike, name the family (the carrier name), the setting and the fix. Admission refuses before the daemon unloads the resident model and reports class `validation`:

| Axis | Sentence |
|---|---|
| pipeline (`topology.pp`) | `<family>: this model family cannot be split across GPUs in pipeline mode (topology.pp = N). Set topology.pp = 1 to load it on one GPU` (a safetensors directory: `<family>: a safetensors model directory cannot be split across GPUs in pipeline mode (topology.pp = N). Set topology.pp = 1 to load it on one GPU, or convert it to a packed .hfq file first`) |
| expert (`topology.ep`) | `<family>: this model family cannot be split across GPUs in expert-parallel mode (topology.ep = N). Set topology.ep = 1 to load it on one GPU` |
| `--tp N` / `params.tp` | `<family>: this model family cannot be split across GPUs with --tp N (tensor/expert parallelism). Set tp = 1 to load it on one GPU` |

Which axes a family has a route for is **declared by its carrier** (`Carrier::topology_caps()`, [`topology_caps.rs`](../crates/hipfire-loader/src/topology_caps.rs)); the front door (`topology_axes_refusal`) refuses every requested axis the carrier does not declare, ep then tp then pp, so no `ep > 1` load reaches a carrier that does not declare it. The declaring carriers per axis are listed once in [multi-gpu.md](multi-gpu.md#which-carriers-declare-which-axis). The Raon carrier keeps an `ep` backstop that uses the same sentence for callers that bypass admission; it declares `pp`, so `topology.pp` on Raon is admitted (HFQ only) and its own option refusals are listed in [multi-gpu.md](multi-gpu.md#raon-1-mini-pipeline-parallelism).

Replaced by these uniform sentences: Muse Glimmer's old special `single-device only` refusal (Glimmer declares nothing, so it gets the three sentences above) and the per-carrier pipeline-only overrides of Cohere2Moe, Maple and Gemma4 (rows 11-16 below, which now fire from the declared-nothing verdict rather than from carrier code). Qwen4 declares no `tp`, so `--tp N` on Qwen4 gets the uniform `--tp` sentence (it used to get the Qwen4-specific `parallelism combination` sentence, row 27).

## Stable text that was preserved on purpose

- The `load refused:` prefix and the `pp=N`, `tp=N`, `num_experts=N`, `n_layers=N`, `visible HIP device count=N` tokens (`hipfire-loader` admission, pinned by tests and by users' logs).
- Carrier-name prefixes (`qwen2:`, `qwen4:`, `qwen35:`, `llama:`, `minimax:` ...) on pipeline-parallel refusals.
- The substrings `truncated` (HFQ container errors), `refusing to load Qwen2` (pinned in `hipfire-arch-llama`), `tokenizer metadata field missing or wrong type` (named in `hipfire-registry`), `topology.pp = N` and `HIPFIRE_PP_LAYERS` in the Qwen4 PP refusals.
- `carrier <name> has no VMM KV owner` (the automatic-VMM fallback reason; parsed in `kv_backend_reason` fields and `scripts/serve_harness.py`), and the daemon's explicit machine codes (`"unsupported"`, `loaded.kv_backend_reason`), which live outside these crates and were not touched.
- Error variants, enum names, return types and exit paths: only message text changed.
