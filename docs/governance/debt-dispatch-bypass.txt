# Debt table — arch crates that reach kernels without the dispatch registry.
#
# OBJECTIVE (holster): drive `bypass` to zero, or to a justified core, by
# migrating each arch crate onto `hipfire_dispatch::KernelRegistry`. Track the
# programme in its issue; this file is the ledger it draws down.
#
# This is a DEBT TABLE, not a purity check. Every row below is known, owned, and
# allowed to exist. What is not allowed is growth: `scripts/check-dispatch-bypass.py`
# fails when any crate's count rises above its recorded number, or when a crate
# appears that is not listed here at all. Paying debt down means editing this file
# to a smaller number, which is a one-line diff a reviewer can see.
#
# Why per-crate and not per-callsite. A table keyed on file:line churns on every
# unrelated edit and would be abandoned within a week. The crate is the stable
# identity and it is also the migration unit -- you convert a crate, not a line.
#
# Why a table rather than a single ceiling. `dispatch_registry_bypass <= 222`
# cannot see one crate improving while another regresses, and it cannot see a
# crate being added. Per-crate rows make both mechanical, and they make the
# migration order legible: `debt` crates convert cleanly, `partial` crates have
# to reconcile two routing systems and cost more.
#
# status
#   ok        no bypass calls; fully on the registry
#   debt      bypass only, zero registry use -- cheapest to convert, no dual system
#   partial   BOTH bypass and registry in the same crate. The worst state: a new
#             quant format must be wired into two routing systems that do not know
#             about each other. qwen35 at 118/189 is the expensive one and should
#             be migrated LAST, after the pattern is settled on the debt crates.
#
# Measured 2026-08-18 on arch/saddle. Baseline total: 222.
#
# Format:  <crate>  <status>  <bypass>  <registry>  [note]
